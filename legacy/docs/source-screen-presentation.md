# Shared source screen presentation

The full source census is 3,304 programs / 186,003 instructions. This family retains 104 complete original programs / 15,752 instructions and all references and unknown operations. Its 195 sites are ScreenEffect89, BackdropColor4, monochrome set26/remove34, and sepia sickness start14/stop22/“playing”6. The source operand envelopes are mechanism checks, not executions of those complete original programs or proof of campaign reachability.

## Native contract and evidence

The bounded evidence contains 21 complete methods and 11,808 original PE bytes, all aliases and C/binary/symbol/header digests. The 20 wrapper/owner methods account for9,744 bytes; preset cctor9f74c0 accounts for2,064. Ghidra truncated this cctor after a GC barrier. Its early-return decompilation is retained as a failed semantic reconstruction; the complete PE disassembly and RIP string/method/float metadata recover the four source presets. `check-screen-presentation-native.py` rechecks these static bindings. No original executable was run.

ScreenEffectCommon and all sepia wrappers return Main.Next and schedule numeric tasks. Preset1 interpolates sepia_ratio0→1 with EaseInQuad. Preset3 interpolates amplitude0→5 and blur_ratio0→1 with EaseInQuad and enables raster settings. Fade-out reverses each source range, rather than sampling a new start from current display. Repeated requests append. Native task execution samples Lerp after the easing function. A zero duration still creates work; it is not a skipped opcode. Source i2/i3 are retained even though these two presets ignore them. Preset2 needs the ScreenEffect_Normal_Wave texture and warp callbacks and remains a specific hard gate; unrecognized presets/operands remain hard.

Sepia start adds an immediate sepia task plus the two preset3 tasks of float32(.7)seconds. Stop adds two reverse preset3 tasks of .7seconds. The Japanese “playing” selector actually adds all three zero-duration tasks; it is not a Boolean query and writes no result register or story flag. Monochrome sets white with the native main filter white alpha40/255, and removes it with alpha0. Existing ColorFade uses another filter owner.

Backdrop uses IMapAccessor.GetBackdropColor→IBackdropColor.GetCurrentColor/ColorFade/IsCompleted. That controller changes camera background colors; it is independent of the FadeManager image overlay even though the wrapper reuses FaderCommon. Positive duration joins; negative duration starts asynchronously; zero completes immediately. No Backdrop state is added to FieldFadeState or its Battle reservation. The separate background numeric channel uses the existing proven color tween mechanism under the single ScreenPresentation owner.

## Explicit Web2D policy

`web-field-screen-presentation-2d-v1` requires current runtime and trusted content DevelopmentProfile.screenPresentation plus the existing storyRuntime declaration. A save, directory diagnostic or reached instruction grants none of these. Framework profile upgrade v9 has an exact new shape requiring all v8 markers and this marker; v1–v8 retain their previous shapes. Every fresh public/selected initialized producer, the actual app and detached replay ports carry the same declaration.

The owner is FieldGame, with its published Field10ms clock. All tasks sample in insertion order; later tasks on the same parameter win that tick, completed tasks retire after their last write, and tasks added later do not delete older work. Zero duration samples on the next nonzero real tick. The clock and displayed filters are Field-only and pause during Battle and loading. **Native global postprocess/task clock behavior across Battle was not recovered. This pause and Field-only display are explicit Web differences.** Existing Session passive BGM/SE/timer and global FadeManager clocks remain independently committed. This family claims no physical audio rollback or multi-clock atomicity.

The production Canvas renderer uses a declared standard sepia matrix, luminance with white tint for monochrome, a bounded horizontal 2D scanline wave and three-tap blur. It paints the separate backdrop behind map textures and actors, including the existing composition paths. Message/UI and FadeManager overlays retain their existing order. These approximations do not claim Unity shader, texture precision, raster units, 3D, HD2D or pixel equivalence. Rendering neither ticks the game nor edits the numeric state.

## Lifecycle, saves and acceptance

Commands prepare and validate detached state before one publication. Existing source VM instructions commit individually; a later unrelated stop does not roll back earlier committed instructions. A private map initializer owns its own detached state and owned-state preparation. Existing WorldSession publication fences include complete story state. Failed/cancelled media preparation discards that candidate; retries transfer the current snapshot; private candidates and retired Fields cannot tick the new owner. Actual Battle media failure, prepared entry, victory and return retain/pause/resume the same Field owner.

Story runtime v3 adds Screen state and optional existing shake state. Legacy v1/v2 keys are unchanged. Stable saves reject active tasks and backdrop tweens, retain exact stable numeric values/clock, and restore only against current runtime and trusted content source identity. Map transfer can carry unfinished numeric tasks but retires old camera shake under the existing declared rule. Forged callbacks, sources, policy, malformed scalars/tickets, stale transactions and missing owners remain errors.

Validation separates complete-source census/before-after decoder identity, 195 original-operand controlled Session envelopes, actual Session lifecycle/Storage, production renderer draw contracts and deterministic color pixels, exact v9 producer proofs, and static native bindings. None substitutes for the parent-owned full candidate or original-body campaign replay. No source IDs, map IDs or PCs select behavior.
