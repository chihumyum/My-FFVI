# 共用元素相性结算

2026-10-11，`narshe-playability-v8`。战斗开始携带显式攻击元素与目标抗性，普通物理、魔法和计算型恢复接入弱点、减半、无效和吸收。原有开场狼犬的火弱点由来源表进入实际战斗。没有增加区域、剧情解锁或 HD-2D 工作。

## 来源与运算位置

GameAssembly SHA-256：`1a7e12c90c6a734e17dda507dd6ab7555090dff6a1e96f3473a90c29916ca6dc`；metadata：`9b426d617a022020feee61cdfc19b16ce1a51c07542fe1dd59169e12f35a3e45`。

- `GetAbilityAttributeArray 0x3d5d60`：非零 attribute_group_id 优先，否则使用单个 attribute_id。无属性的 0 在 Web 编译为显式空列表。`SetupActiveAttributeList` 的回调 `0x4ef3a0` 仅加入 type 0/5 的成员，编译器保留来源输入的顺序与重复；上游原生字典的枚举顺序尚未闭合，因此多元素来源组仍有独立准入阻塞。
- `DamageAppliedResistanceAttribute 0xa93a40`：当前来源使用 1=弱点×2、2=减半截断、3=无效、4=吸收反转符号。其他系列值 401/402/403 未进入当前可执行契约。
- `MagicExecution 0xa94480`：相性位于防御/友方伤害之后，依照属性数组逐项处理，无效立即返回。先弱后半与先半后弱的逐步取整可能不同，重复吸收会再次反转符号。之后正伤害限 65535，再处理总目标数。吸收的负值在多目标时减半，最小恢复量为 1，即使 content flag 2 存在也如此。该入口最终只限制正伤害至 9999；资源应用另按 HP/MP 上限约束。
- `PhysicalExecution 0xa97b20`：相性位于暴击之后、attackPointCorrection 和总目标修正之前。多个匹配抗性按吸收 > 无效 > 减半 > 弱点选择一项，不逐属性连乘。吸收后的负值不做群体减半，最终限幅为 -9999 到 9999。玩家普通攻击使用选定手槽元素；非普通玩家物理不继承武器元素。敌人使用自身活动元素列表。
- 物理回调 `0xaa7d60` 匹配攻击元素与目标字典。另两个回调 `0xaa7dc0/0xaa7e30` 查询虚槽 35/36，metadata 标识为种族/有效种族，仍属于未放行的种族上下文。
- `PlayerCharacterParameter.GetArmConfirmedActiveAttributeList 0x534c70` 合并基础、选定武器与临时攻击元素；FF6 武器 provider `0x858e80` 使用当前手槽武器的 attribute_id。当前开场明确没有基础或临时授予，不把这一假设当作全角色默认值。
- `ConfirmedResistanceAttributeList 0x5340d0/0x4af6f0` 与 `MargedResistanceAttribute 0x4e7500` 合并来源抗性。优先数组由 `0x4e7750` 初始化，metadata 偏移 `0x4DED02` 的 28 字节为 `[4,3,402,403,2,401,1]`，字节 SHA-256 为 `ec16b1980ec69172d0dd3b5268ef871311eb5922060984cbd885693ff27467b4`。当前仅允许 1–4，因此合并顺序为 4 > 3 > 2 > 1；未知值不会用数值大小猜测。
- `GetResistance 0x4e73b0` / `GetResistanceAttribute 0x4e72c0` 仅从 armor 的 resistance_attribute 读取防御相性；武器攻击元素和防御抗性分开投影。没有据此放行装备资格、穿戴函数或附加技能。

本地 19 个带类型方法的原始字节/反编译摘要与优先数组已重新核对，`build/reports/element-native-check.json` SHA-256 为 `c665d61c26c18e0edcc1cc3cc6d0be1ccf0ee2e3f2ec9875a270d5bdc974e250`。静态恢复与实现检查不是原版运行一致性证书，原版对照仍后置。

属性组回调 `0x4ef5c0` 保留首次枚举的同元素条目；`SetupResistanceAttributeDic 0x4dc4c0` 使用上游字典。源组 81/125 同时列了吸收和弱点，尚未确认原生枚举顺序，编译器明确拒绝有冲突的重复元素，不能把 CSV 顺序或装备合并优先级套用到这里。相同值的重复行保留来源身份。

## 所有权与提交

`compiler/elements.ts` 保留属性、属性组、角色装备与敌人引用，`core/elements.ts` 负责类型校验、抗性合并及两条不同的运算规则。标量计算保留有符号结果；`core/ability.ts` 将其转换成正数量和资源变化方向，`BattleGame` 仍对全部目标统一扣费与提交。无效有独立结果标记和画面文字，不伪装成命中抽样失败。

v8 要求每个战斗角色提供 attackElements 和 elementResistances，魔法 plan 提供有序 elements。缺失数据不能隐式视为中性。任一目标具有未知抗性时，整次行动不提交 HP、MP、结果或日志，并回滚结算抽样。

当前装备模块只对明确给定的六槽与手槽做投影。动态换装重算、剧情授予、临时抗性改变、弱点变更能力、数值状态、反射、不死转换、完整命中类型与连续命中仍未完成。多元素来源动作仍可能因类型、范围或其他函数阻塞；标量规则恢复不解锁整条技能。

三条物理能力 743/754/757 携带 attribute 8，但其技能元素如何进入物理上下文尚未证实。旧开发规则将其置于中性限制下；v8 明确阻塞。1,530 条来源能力可解码，其中受限 plan 183 条、阻塞 1,347 条，不以 plan 数代表可玩覆盖。
