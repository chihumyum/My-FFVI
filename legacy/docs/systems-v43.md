# v43 共用对话、地图生命周期与行动状态

本批继续搭建游戏系统，内容仍用已有开场与受控样本验证。交付单位是可以接收不同来源参数的系统接口；不按地图名、消息 ID 或敌人 ID 增加剧情分支。HD-2D、着色器、字体和原生动画精度不在本批范围。

## 系统变化

普通同步对话使用同一个字段窗口和事件任务。窗口样式、位置、分页与下一条指令的保留规则来自编译内容；输入只推进当前任务的一页，窗口占用和实体更新集合一起准备与提交。商店、宝箱和自动字幕保留各自已经定义的生命周期，未支持的动态文字或自动推进仍报告依赖。

跨图继续使用同一批常驻演员。旧图的渲染目标引用先核对来源，再按目标图资源生命周期迁移；隐藏对象不因为新地图存在纹理就凭空执行一次 Attach。实际玩家按目的入口重新绑定。切图失败仍保留原地图、演员与角色状态，视觉能力缺口不转为剧情空操作。

战斗的换列指令走既有资格、目标、蓄力和效果事务。排队时不改变站位；效果提交后改变战斗副本，胜利与返场一起写回共享编队。战败重试恢复入场行位，准备返场失败不会提前发布行位或奖励。菜单、保存和下一场战斗读取同一份编队数据，没有新增持久行位副本。Web 仅用文字和简单站位偏移表现结果。

owned v9、field/world v9、session v4 与 `narshe-playability-v35` 保持不变。内容摘要仍随重新编译变化，旧内容绑定的存档不能冒充当前内容的进度。

## 连续验收入口

完成本地来源构建后执行：

```sh
npm run check
npm run framework:verify
```

`framework:verify` 用一次编译结果重新执行主循环、脚本运动与恢复、共享角色状态、普通对话与保存、剧情选择、战斗菜单和行动状态回写检查，另跑来源新游戏路线。每个子报告先清理再生成，汇总保存子报告摘要、案例数和运行代码摘要；运行期间代码变化会使汇总失败。结果写入 `build/reports/framework-systems-check.json`。

受控主循环通过与来源剧情仍未完成分别记录。来源路线在未知依赖处停止，不因子脚本正常退出就标为完整开场或批量填充就绪。浏览器实玩、原版一致性和整作迁移也分别验收。

## 后续系统顺序

先实现交通启用、停车数据、当前身份、演员骑乘和跨图恢复的共同事务，再扩展同步对话中的时间与动态文本提供器。已有数据驱动的战斗、事件、队伍和保存链路继续作为回归。系统契约通过后再接相应内容批次；原始使用频次用于评估复用范围，不能换算成可玩覆盖。具体边界见 [框架系统依赖](framework-system-dependencies.md)、[共用对话](field-manual-message.md) 和 [战斗换列](battle-row-change.md)。
