# 通用遭遇内容管线

战斗内容按来源编组身份选择、编译和装载。纳尔谢保留为回归入口，运行时不再要求所选编组集合必须恰好是开场四组。新编组使用相同的敌人参数、AI、能力、掉落和战斗会话，不复制场景逻辑。

## 生产与运行边界

导出器的重复参数 `--encounter-id` 扩充来源选择，保留开场回归所需依赖。它读取 `monster_party.csv` 的九个成员槽，导出对应怪物、背景、AI 和战斗脚本资源。选择资源不改变故事脚本，不授予角色或技能，也不把编组标为剧情可达。

来源编译器保留六个队形字段、成员的来源槽号、坐标、组别、脚本及相关旗标。脚本 ID 为零表示没有脚本，不查找不存在的第零行。来源编译不再因为多个阵型而丢弃整条描述。固定的来源 1/3 使用普通／opposed 开发投影；多候选必须显式提供 FrameworkBattleFormationPolicy，编译保留完整资格与作者权重，不预先抽选。会话用种子与遭遇序号生成一次入战结果，构造失败可重试、败北复用该结果。仅支持的来源 1/3 可带正开发权重，其余正权重明确拒绝；这不等于原版概率或先制机制已实现。无法编译的条目保留来源诊断，不让一条失败丢掉其余目录。

运行时编译器复用已有参数、AI、能力与掉落编译器，并按每个遭遇检查所需引用。公共目录身份损坏仍使整个构建失败；局部机制或资源缺口归属具体编组。战斗构造和后续动作继续执行既有检查，目录编译成功不绕过它们。

## 三类结果

| 结果 | 含义 | 后续处理 |
| --- | --- | --- |
| `blocked` | 缺少构造这条编组所需的定义、资源或机制 | 不发布该遭遇的运行定义，保留来源位置和原因 |
| `runtime-dependency` | AI 的某个条件分支仍引用未实现动作或指令 | 保留程序与 PC；运行到该依赖时明确停止，不宣称全分支可玩 |
| `development-omission` | 当前开发宿主明确保留的来源表现或生命周期偏差 | 单独报告，不能据此宣称原版一致性 |

原有狼犬高等级分支引用的未实现能力属于运行依赖。已有开场战斗脚本也不等于已被战斗宿主执行；保留它的来源身份和开发偏差。其他来源脚本不能因为外观类似而获得相同准入。

`BattleCatalog.encounters` 只保存已构造的定义，`encounterDiagnostics` 和 `encounterReport` 保存完整所选集合的结果。报告使用“已构造定义”，不使用“已迁移战斗”或“可玩地区”。后续区域批量接入应同时检查字段事件、遭遇依赖、角色状态和战斗返回，不能仅看目录计数。

## 复验入口

按 README 的战斗导出命令增加 `--encounter-id 3002 --encounter-id 3035`，再执行：

```sh
npm run battle-catalog:check
npm run framework:check
```

这两组来源使用既有媒体，拥有不同槽位或队形，用于检查编译器是否依赖开场编组身份。它们是系统留出样本，不扩展故事可达范围。`npm run battle:build` 生成来源包、运行目录和 `build/reports/battle-catalog.json`；原始资源与生成结果均留在本地忽略目录。

详细所有权、内容身份与各分支验收见 [v50 编组与入战框架](systems-v50.md)。
