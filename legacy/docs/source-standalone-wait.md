# 整族平台毫秒等待

本批涵盖全3,304份来源程序/186,003条指令中的全部51处 `PC版のみミリ秒指定で待機` 调用，完整32份程序/5,037条指令及地图、引用和其他未知需求共同保留。没有按场景改写等待时长或替换原始正文。键盘输入、BGM同步、字幕与异步地图等待是其他消费者，仍保留各自门槛。

固定Windows来源DLL的 `WaitMillisecondsInStandalone` 在首时钟读取 `DataStorage` category10 的 `MapLocalVariable[7]`，将毫秒除以1000写入同一Core的r0，并把本次时钟的entryTime写入r1。首时钟总是让出；后续时钟在 `entryTime-r1 < r0` 时继续等待，否则向下一条指令推进。负值与零也至少经过下一时钟。参数不是Format.r0，也不是调用时不断重读map-local。

Web使用既有FieldGame的10ms时钟、EventState和Task.generalRegisters，不添加计时状态所有者。保留秒数比较，不将它替换成整数毫秒倒计时；二进制浮点边界可能比整数向上取整再多一个时钟。等待期间捕获实际Web程序/PC、来源指令和寄存器身份，未知变量、来源变化或寄存器替换明确拒绝。活动等待阻止保存、切图或重置丢弃游标；完成后通过已有事件屏障保存同一Core寄存器，恢复不会重复等待前的发奖。

该调用属于已知Windows版本的主Core纯计时逻辑，直接类型化到共用VM；不新增内容或宿主权限来猜测外部完成事件。明确选择已有Web时钟不等于验证了原生动态调度。类型2、未知选择器和未准入保留操作数继续拒绝。
