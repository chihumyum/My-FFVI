# v55：动态战斗参与者与增援内容闭包

本批继续补游戏骨架的系统接口：敌人加入、替换和退休复用同一 `BattleGame`，根程序、AI、行动队列、奖励、重试及返场仍属于同一会话。没有针对某个敌队或地图增加运行时分支。

## 三种身份与生命周期

怪物主数据 ID 指向不可变模板；来源 uniqueId 指向原敌队的 1 基槽位和布局；实际单位 ID 指向一次进入战斗的实例。初始来源槽位保留原编号，不能用压紧后的数组下标推断。动态实例使用独立递增 ID，同一槽位或同一怪物再次进入也不会继承旧动作、AI 变量或计时器。

`BattleParticipantState` 只保存身份、退休标记、奖励元数据和生成序号。当前 HP/MP、条件、AI、队列与随机流继续由 `BattleGame` 持有。替换前准备完整新单位及其 AI，校验行位、条件、指令、掉落引用和当前 AI 行动能力；成功后原子发布。退休单位退出 live roster、普通/中断行动及 AI、Poison/Slow 计时器。正在表现且引用退休 actor/target 的动作取消；未开始的单体目标仍保留旧实例选择，执行时失效，不按槽位重新绑定。

单位历史不随退休丢弃。原版 `RemoveEnemyData` 会将旧单位放入 dust 集合，再从 live 集合移除；奖励是否读取这个集合尚未确认。Web 显式选择 `active-units` 或 `all-entered` 的 EXP/Gil 范围。已有死亡掉落登记保持顺序；新实例独立登记。同一怪物出现两次不合并为一个运行时单位。

帧事务保存原 combatants 数组、成员对象、完整参与者账、AI、队列、时钟、门控、随机流及掉落登记。任何后续失败恢复成员身份和顺序，不仅恢复数值。战败重试使用固定入战名单、模板、根程序和共享剧情银行，重新开始实例生成序号；后续修改目录或给旧静态战斗插入新 provider 都不能改变重试计划。稳定存档仍保存成功返场后的原持久 owner，进行中的战斗不新增第二份可持久状态。

## 事件接口

`BattleAddEnemy(i0,i1)` 编译成怪物 ID 与 uniqueId。首次调用请求宿主加入并保留原 no-act，停在同一 PC；同一时钟不重复加入，后续时钟确认加入完成再恢复先前门控。加入完成信号独立于行动表现/队列是否为空。新 AI 直接执行 Entry，不要求根脚本再启动所有 AI。

`BattleSleepEnemy` 设置敌方普通决策门控；没有将它解释为整场暂停或状态条件。Web 当前阻止新普通敌方行动选择，ATB、玩家行动、正在执行的动作和根时钟继续。完整反击、计时器与原版 no-act 的关系尚未验证。

Web 在进入战斗前装好依赖，替换与新单位发布在同一事务内；原版先移除旧单位，再异步装载新单位。正在执行动作退休、布局和这些时序仍是明确的 Web 策略，不能称为动态原版一致性。静态来源绑定见 [来源合同](battle-participants-source.md)。整队 Round2/3/4 与玩家加入保留为后续公共能力，不映射成一场新遭遇。

## 同一编译与准入管线

`compileEnemyBattleDefinition` 同时服务初始敌人和增援模板，复用属性、物理、AI、技能、条件、媒体和掉落检查。reserve 列表表示某个敌队需要的模板，不创建单位，也不增加初始 enemyCount。实际脚本决定加入时点和目标槽位。

普通静态敌队编译出原始初始绑定及 `active-units`；任何动态加入都要求明确的 development participants 策略，包括复用原有模板/槽位的替换。编译器逐原 PC 验证所有加入所需的 master 与布局，缺项阻塞；批次分析再检查包括未加入 reserve 在内的完整依赖。目录错误不能延迟成游戏中途的空白敌人。实际来源素材的增援导出接线和整段程序准入仍独立验收，不能用合成模板代替真实来源引用。

53 个完整来源战斗程序继续保留其他指令缺口；新增支持的 25 处加入、5 处 no-act 操作用原 PC、原操作数在明确标注的受控程序中执行，不等于整段程序或敌队已可玩。

## 验收

当前验证记录在 `build/reports/v55-validation-summary.json`。统一系统套件增加动态参与者 lane，代表性连续会话覆盖来源操作 → 新 AI/退休引用 → 战斗胜利 → 返场准备失败 → 一次提交 → 保存恢复 → 第二战战败/固定重试。还注入发布后的观察故障，确认原成员对象、时钟、随机流和生成序号恢复。

独立审查发现的 reserve 行位/指令校验延迟，以及编译根脚本未检查动态引用/策略的问题均已修复并补回归。静态重试也固定“未提供 participants”的入战基线，后续插入目录对象不会改变重试。掉落探针改为等待实际替换状态，避免把受控等待时长的单个浮点边界误当成退休完成。

更新战斗目录后，来源入口及 framework 派生入口按依赖重新生成。旧摘要被现有门禁正确拒绝，未放松来源/内容绑定。AI 受控宿主修改模板时同步维护初始槽位合同；用于探测分派的假 ID 各自独立，不能让不同模板共享同一怪物主数据 ID。来源开场继续在既有 Camera Move 提供器边界停下，仍未完成开场或成为可稳定保存的新游戏路线。

本批没有新增浏览器/UI 验收或原版动态对照。`readyForBatchPopulation` 与 `fullGameMigration` 仍为 false。下一项骨架能力是整队切换与玩家参与者的持有边界，随后按能力闭包批量接入内容；HD-2D 与精细演出继续后置。
