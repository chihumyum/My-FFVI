# v66 可信内容包入口

本批将启动、地图目录、战斗目录和恢复依赖从固定开场路径拆成共同引用合同。网页、批次规划和实际执行使用同一个 `GameContentRepository`；会话、地图、角色与存档继续由既有 owner 持有。内容引用只决定装载位置及版本，不创建初态或授予来源机制。

## 引用与状态边界

`GameContentRefs` 为宿主选定的完整配置：`kind`、`profile`、`world`、`source`、`development`。world 固定一个目录，两个入口各自包含 entry/battle 引用，允许显式 null，但至少提供一种入口。每个引用必须有同源根路径 JSON URL 与 64 字符的小写十六进制 SHA-256 摘要。解析立即复制数据，拒绝缺字段、额外字段、访问器、非普通对象、外部路径和无摘要引用。

仓库第三参数接收这份配置，其 profile 必须与宿主选择一致。自定义路径不回填默认值，缺入口直接拒绝。未传配置时使用原默认适配器；默认标题仍不预先读取任何游戏内容。

读取继续验证 payload、来源集合、kind、地图/区域、脚本及来源战斗资格。显式提供的地图目录也须匹配宿主固定摘要。恢复只按保存的 origin 选择宿主已提供的入口；保存摘要与宿主摘要必须同时成立，不能用保存摘要覆盖宿主配置。URL 和引用配置不进入检查点，保存格式保持不变。

批次清单新增可选 `contentRefs`，调用同一解析器并核对 profile、world 和所用 entry/battle 摘要。整份引用进入清单及依赖摘要；没有该字段的旧清单保持原摘要表达式。批次文件读取在配置模式使用准确 URL，不走兼容别名；地图也通过公共仓库取得。既有来源纯度、指令和能力诊断保留。

## 可运行接线

`npm run content-packages:build` 从已构建的真实本地包生成三个引用入口，输出在忽略的 `build/content-packages/`：

| 入口 | 用途 |
| --- | --- |
| `/game/?package=source` | 来源新游戏与既有开发片段，各用独立入口及战斗目录 |
| `/game/?package=framework` | 明确的框架开发派生与既有片段，保留各自资格 |
| `/game/?package=development` | 仅既有开发片段，不提供来源新游戏入口 |

builder 复制现有七个 payload、保留其摘要，先通过公共仓库验证内容绑定再原子发布目录。它不改原内容，不新增角色、地图或剧情状态。服务器提供相同路径；批次来源开场清单也已经使用这份引用。

网页只先读取所选引用文件，再按按钮装载必要角色。明确传入的 profile 与内容包声明冲突时拒绝。引用尚未就绪时不能开始或读档，缺失入口的按钮隐藏且操作拒绝。存档仍使用原 profile 槽，恢复严格核对内容身份，原进度不会因失败载入而被覆盖。
