## Evidence and staged ownership

The full registered wrapper PE and exact metadata identify12 ordinary forwarding wrappers plus separate Tina and Gau wrappers. `OpenChangeSingleName286950` creates an absent actual held character with the existing Unlock owner, disables only that new held owner, removes the counts of its nonempty equipped items, then opens the name client. Existing held state is not reset. The original loadout stays on that disabled owner. Equipment counts are changed in native order after initial grants; they are not algebraically netted, because capped inventory would differ.

The new owner is `GameState.fieldCharacterNaming`, also exposed by `prepareFieldState` on its existing map draft generation. No new roster, equipment, growth, job or persistent name owner is introduced. Static default text comes from the shared source MessageManager resolver and actual CharacterStatus rows. The FF6 provider's constructor identifies its readonly original-name character and `GetDefaultName74f310` selects its explicit `MSG_CHAR_NAME_01`; other rows use their exact `mes_id_name`. This default catalog is trusted content, never an input granted by a save.

The Web request binds the actual Field/Task/program/op/Core bank, EventState revision, content and owned identity. Opening commits before user input. An error in a later phase leaves this earlier committed acquisition intact. A map initializer uses the existing unpublished owned draft: failed or cancelled map media preparation discards that draft; successful publication promotes the same ports and leases. WorldSession retires naming requests with the actual old or discarded Field, so old source IDs cannot redirect a callback into a new map instance.

The input is exposed through GameSession, GameFlow and GameCommands to the actual App text form. The explicit `web-source-character-naming-input-v1` host policy provides a Web text window, preview and Yes/No confirmation. It does not certify the original popup animation, portrait, layout or system SE. The request remains pending without actual input. No default-name success acknowledgement, simulated cancel-success or blanket initial acquisition exists.

The source phases are:

1. Opening prepares and commits the actual new held owner if absent. The source Task remains on its original operation.
2. Nonempty user input advances the detached request to confirmation. No persistent name changes. No returns to input with the proposed text.
3. Yes prepares and commits the actual owned `Name` and the existing source name-tag binding. The UI closes, but the source Task has not advanced yet.
4. The next positive Field logic clock performs the wrapper completion and advances the original Task. Gau's first clock captured the actual absence result in its real Core `i0`; only that result authorizes the existing `CorrectLevel(firstJoin=true)` owner after the name client closes.

Native `SubstringInByte b167b0` iterates UTF16 code units. A unit has width1 for `<0x81`, `f8f0`, `ff61..ff9f`, or `f8f1..f8f3`, otherwise width2. Confirmation truncates at width12; an exact default-name match bypasses truncation. This is not UTF8 encoding, Unicode grapheme counting or a replacement string guess. Empty input stays an error. The original Back route goes to a separate end-game popup phase; it is not offered as a source continuation. General Web pause/title controls still use their existing owner and revoke old command admission.
