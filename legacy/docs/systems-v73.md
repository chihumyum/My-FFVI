# v73 初始化后的完整系统演示

本批已接入独立的 `systems-initialized` 内容包，把商店、魔石、学习、成长和存取组合成网页可操作流程。旧 `systems-playground` 的开发检查点没有原生持有域，不能通过补写快照来开放魔石；它的内容和存档槽继续保留。

## 初始化与作者入口

`framework-new-game-content-v1` 单独绑定原始新游戏初始化定义的摘要、战斗目录、世界、初始地图、PointIn 和原生演员提供器。公共 `GameSession.prepareFrameworkNewGame` 先捕获完整参数并验证内容，私下调用 `GameState.createNewGame` 创建持有状态，再通过同一演员工厂、MapSetup 和 PointIn 准备字段。作者地图有单独的入口身份；原始 `NewGamePlan.entry` 和 `SourceNativeState.entrySeed` 不改成作者地图。

严格来源新游戏仍执行原路由和标题交接守卫。新框架入口有明确的 framework profile，不运行原开场镜头，也不把作者演示标成来源剧情。它不读取旧检查点的剧情种子或魔导状态；后续作者事件只使用真实库存接口及明确的地图局部状态。

## 同一入口与存取管线

内容引用新增 v2 的 `initialized` 入口，v1 的 source/development 合同不变。仓库、网页与批次从相同可信引用读取新包，使用既有 `GameEntryLoader` 发布会话，媒体失败和迟到完成继续使用原票据取消边界。页面依据仓库能力决定入口，不能根据包名授予游戏权限。

新检查点使用 v6 和独立的 `framework-new-game` origin；owned v14 表示实际来源初始化及随后演化的状态。恢复必须取得可信初始入口、世界、战斗及实际目的地图，验证同一摘要和 profile，在私有候选内恢复演员与 owned 数据；不执行作者初始化、重定位或发奖。旧 v4/v5 不能通过改写 origin 获得这个能力，旧开发存档仍无原生持有域。

新批次入口和执行回执同样有独立的 framework initialized lane。依赖规划、玩家命令、媒体准备、战斗归还、保存恢复和恢复后输入都复用实际公共接口；作者路线通过不能关闭来源主线或全游戏验收。

## 实施与验收状态

本批按三条模块线并行实施：来源内容与可信仓库、原生初始化与字段演员、网页入口与受控交互；集成线独占会话、世界恢复、批次合同和发布。当前代码检查通过 2,919/2,919，Python 工具 43/43、原生绑定 16/16。

实际来源初始化的连续检查通过 9 项：领取并装备魔石、局部状态防止重复领取、实际商店买药和离店、选择返回、普通 517 战斗、一次奖励与成长、v6 保存恢复和恢复后的下一次输入。战斗使用原普通攻击、HP、AI 和随机流；96 经验和 96 Gil 写回一次，两位初始士兵从 1 级升至 2 级。3398 学习战保留来源难度，入口提示先升级与回复，不修改数值或保证直接学满。

实际 app 和菜单的受控界面检查通过 8 项，验证商店、魔石装备、部分学习到学会、保存恢复、下载及媒体失败重试、取消晚到与旧回调拒绝。该检查使用明确的合成内容及受控 DOM、媒体和绘图；它提供系统接线证据，不替代来源剧情、实际浏览器或原版验收。来源入口、世界、地图和持有目录的摘要已复核，新包没有修改原初始化定义。

统一框架通过 50 组受控系统合同，另独立记录 1 组未完成的来源路线；总计 51 组检查。新 initialized 批次入口还通过公共 runner 的菜单、两次保存恢复及恢复后输入，回执保持独立 lane。来源开场仍停在 `sc_e_0001_3` PC154 的镜头 Move 提供器；本批不沿该单场景继续解码，也不把系统入口计作来源剧情通过。

最终回执为忽略目录中的 `build/reports/v73-validation-summary.json`。本批先修正了仍断言旧入口链接与旧拒绝文本的检查，再完成统一回归；未放宽状态、摘要或来源准入。后续按 [系统推进计划](systems-roadmap.md) 交付成组内容包和其需要的世界旅行模块。

入口为 `http://127.0.0.1:4173/game/?package=systems-initialized`，也可从默认游戏页的系统演示链接进入。上方选择训练、右侧进入商店、下方领取魔石；方向键面向设施，再按 Enter / 空格交互。Esc 打开菜单和保存。命令为 `npm run initialized-systems:build`、`npm run initialized-systems:check`；共同框架的统一检查仍使用 `npm run framework:verify`。

HD-2D 继续后置，全游戏迁移目标保持 active。
