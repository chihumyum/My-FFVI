# 二维到 HD-2D 重制工作流

状态：**后续设计，未启动调查或制作。** 必须先通过实施计划中的全游戏 Web 迁移放行。当前配方及资源约束代码只保留数据边界，不表示已有风格规范、重制资产或可运行重制场景。

## 输入和阶段

固定源内容指纹、世界状态上下文、风格规范和目标配方版本。输出包括生成场景、资产锁定清单、语义与装配检查、视觉对照以及未定项。

1. 读取区域知识。明确地点身份、剧情条件、物理对象身份及当前未知项。
2. 解析二维地图、碰撞、实体、入口与事件；保留源坐标，不在美术转换中改变逻辑空间。
3. 标注墙体、屋顶、地形高差、门窗、前后景与可探索边界。推断高度先保留 proposed，审核后才成为 approved。
4. 产生语义资产需求，查询登记库。顺序为直接复用、受控参数变体、派生、新建；每次选择保存原因和版本。
5. 按确定性装配规则生成场景。随机装饰使用固定种子，但种子本身不保证生成式模型可重复；生成资产按内容哈希冻结。
6. 应用环境风格、灯光、镜头和演出轨道。歌剧的表现规范作为参考来源，不自动视为全地图通用标准。
7. 运行装配和游戏空间检查、固定视角/时间点视觉检查、目标状态与浏览器性能检查。
8. 审核后发布本地版本化场景包。记录依赖和回滚版本。

## 资产登记和风格

每项资产记录 ID、版本、母资产、来源、地区/用途/状态条件、尺寸/原点/方向/连接点、材质类别、规范版本和验收证据。参数变体必须列出可变化字段及范围，结构改变产生派生资产。新资产先登记与验收，再被配方引用。

风格规范包含人物比例、texel/pixel density、采样、调色板、材质、照明、后处理、相机和遮挡约束。首版未从原版测得的数值保持待定，不以任意默认值伪装为既有标准。场景配方固定规范版本；升级产生影响报告。

## 配方与修正

配方引用逻辑地图、状态上下文、标注、规则版本、资产精确版本、镜头和局部覆盖。人工修正进入配方或标注；生成产物始终可删除并重建。特例有清晰目标和理由，不能散落为内核中的地图编号判断。

逻辑入口与可见门的对齐、可通行路线、屋顶遮挡、角色可见性由空间检查器验证。固定镜头的布景还需声明允许观察范围；用于自由探索前重新验证。

## Drift 检查

| 变化 | 检查 |
| --- | --- |
| 语义偏离 | 地点/对象身份、区域/剧情条件与来源一致 |
| 重复资产 | 登记前候选检索、来源及派生链；相似度仅辅助 |
| 装配偏离 | 尺寸、连接点、原点和人物比例 |
| 风格偏离 | 规范参数与固定视角人工复审 |
| 游戏空间偏离 | 碰撞、入口、触发器和可见性 |
| 版本偏离 | 精确版本锁定、反向依赖和升级对照 |

共享资产更新先计算受影响配方，不自动升级。逻辑、视觉与性能分别验收。美术生成可以批处理，但未审查内容不能因批次平均通过而放行。

## 工作流验收

连续处理三张同类地图，其中一张为未参与规则设计的留出地图；复用资产及装配规则，必要新语义显式阻塞。重建摘要一致；共享资产变化能列出全部直接/间接受影响场景；变体不会跨剧情状态错误套用。
