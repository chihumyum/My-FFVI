# 框架系统依赖与实施顺序

当前排序以 [游戏系统推进计划](systems-roadmap.md) 为准。下方调用频次帮助归并公共能力，不能把每个特殊消费者都变为骨架放行前置。

当前公共骨架与批次接入见 [v78](systems-v78.md)：精简系统门禁作为日常批次的公共合同证据，完整 suite 为显式回归。批次工作单重新读取内容，保留完整诊断并按公共系统归并；不得凭频次或数据解码数宣称可玩覆盖。

以下 v69–v71 为对应阶段的交付记录，不是当前任务队列。

[v71 字段魔法系统](systems-v71.md)：独立菜单能力编译、实际持有资格、目标与 MP、候选随机流、外观共同提交及 owned v13 存取。魔石及成长闭环现已接入，来源剧情与全游戏迁移仍独立验收。

[v70 持有名册与三组编队](systems-v70.md)：在可操作骨架上支持成员换入换出、保存组选择、字段与下一战的共同依赖和存取；仍按系统和内容资格分别验收，精细演出与 HD-2D 后置。

[v69 可操作的系统骨架](systems-v69.md)：通过共同入口验证连续游玩及取消、存取边界；以下来源缺口按共同能力安排后续批次。

v59 [公共能力需求](systems-v59.md) 将 typed 指令所需 owner、演员、声音与完成信号同时呈现给计划和实际执行。未知 actor/root/刷新条件保留 conditional，潜在分支不被用作构造器全量禁用。批次引用、实际路线、稳定保存与全游戏验收继续独立。

新增公共 [字段恢复合同](systems-v58.md)：事件到 shared owner、地图草稿和演员发布使用同一事务，保存与下一战保持资源一致。后续继续优先公共状态与内容能力合同；不把下一条开场镜头或任意地图细节当作框架任务。

本表服务于共用系统与批量接入，不按地图逐个写规则。精细粒子、着色器和 HD-2D 继续后置。当前实际运行与后续静态依赖分开记录。

当前主线先补公共运行接口：切图失败/取消/重试与存档提交已收进共享流程；v46 已解除入口依赖，v47 已提供 Web 主任务保存/续行，v48 已建立清单、依赖和连续轨迹绑定的批次检查。v49 已接普通探索遇敌与原地返场，v50 已拆开敌队资格、显式选择与一次入战计划，容纳通用成员布局。v51 已补显式普通撤退、返场失败重试和区分胜利/撤退的保存记录。v52 已贯通来源魔法学习点、持有值、重试和保存。v53 已统一战斗 root、AI、行动等待与终局；v54 已接共享剧情草稿，v55 已接单个敌人生命周期及增援闭包，v56 已接完整敌队换轮和最终一次结算；v57 已接已有角色借用、换组、重入及每owner一次回写。后续按公共系统合同和统一内容闭包安排批次。来源开场清单仍未准入，下表不能把下一条演出变为框架优先级。见 [v56 多阶段战斗](systems-v56.md)、[v48 内容接入](systems-v48.md)。

## 已运行边界

`build/reports/framework-source-route-check.json` 从来源新游戏入口执行 **609 → 3 → 178 → 609**，在 80,550ms 停于 `Map_40037/sc_e_0001_3:154` 的摄像机 Move 提供器；`completeOpening=false`、`checkpointReady=false`。passed 表示预期边界成立，不是开场完成，也不自动将摄像机细节列为下一框架任务。

三次实际切图分别来自 `sc_e_0001:19`、`sc_e_0001_1:10`、`sc_e_0001_2:10`。这是显式 `framework-development-v1`，使用受控标题／音频宿主、10ms 更新、自动确认，以及逐条留证的匿名环境粒子省略和显式交通开发能力。实际已执行停车、玩家上乘、三个剧情演员上乘及骑乘定位；原生交通副作用和动画仍单列差异。严格来源包独立保留。

后续 **609 → 572 → 3** 仅是静态链：`sc_e_0001_3:45`、`sc_e_0001_4:17` 的非广告分支。`sc_e_0001_5` 后续包含脚本调用、地图标题、自动保存与帮助／退出，真实新游戏尚未执行至此。守卫战 `sc_e_0002:5` 及返场 `sc_e_0002_1` 已有开发样本回归，不等于新游戏已到达。

## 交通的所有权合同

已有来源链区分 `SetVehicle 0x2cb2b0 → TransportationEnabled 0x2f1fe0` 的启用／停放、`GetOnMagitekArmor 0x27a190` 的 `ChangeTransportation(6,true,false,0)`，以及只修改角色骑乘结构的 `RideVehicleNPC`。详见 [交通模块](transportation.md)。

| 现有所有者 | 当前缺口与应有职责 |
| --- | --- |
| `GameState.sourceNativeState` | v2 的 `ownedTransportations` 唯一保存交通记录，停车 map/position/direction/timestamp 经 owned 草稿提交；不再复制 parked map 字典。自动行驶位置回写待接。 |
| `EventState` | release flag 是 enable 的所有者；与停车记录同事务发布。未知保持未知，不复制布尔状态。 |
| `FieldGame` 与原生 `actors` | 当前交通可在显式开发能力中切换，与原演员内外层资产、外观记账、镜头及碰撞开关一起发布；速度、完整碰撞几何、操控与 GPS 仍是差异。 |
| `WorldSession`／保存／返场 | 跨图保留当前步行/魔导身份，保存恢复交叉校验来源目录、owned 记录、release flag 与队伍交通记账。其他交通切换继续阻塞，旧候选不能绕过。 |

实现返回可验证的一次性候选，复用 `prepareFieldState` 和验证后 `commitWith` 的总事务模式。媒体或后续准备失败时不修改 enabled flag、停车记录或演员；不新增持续 actor 副本。字段毒、菜单、入战和跨图都读取同一实际交通身份。

交通 6 的 release flag 是 `TreasureFlag4[137]`，不是 `sc_e_0001_5` 的 `ScenarioFlag4[132]`；负 actor selector 也不是 Web 实际玩家 id，必须通过既有来源绑定。初始化种子的 `parkedTransportationMapIds=-1` 转成完整 owned 记录，不能当作任意停车位置证据。
