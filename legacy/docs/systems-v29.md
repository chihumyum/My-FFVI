# 系统集成 v29

本批将共用事件调度和渐变接入 Web，继续遵循系统先行。完整新游戏、原生演员/相机宿主和全游戏迁移仍未完成；没有开展 HD-2D 或区域填充。

## 运行系统

`FieldGame` 统一管理主任务及全局 32 个 puppet 槽。每次逻辑 clock 先排主任务，再按槽顺序执行；同一任务连续执行 Next 指令，到等待或结束才让出。`Call` 跳过目标标签，`Return` 使用来源栈；puppet 从指定入口执行并限制在第一个 Exit 范围内。同步 Exec 至少等待一次，异步 Exec 继续主任务，Finish 观察所有 Ready 槽。主任务结束后先完成本帧槽调度，再清理，不能把旧的父子任务列表当作原生槽语义。见 [任务控制](field-task-control.md)。

宝箱与普通消息共用窗口归属。在提交奖励前检查所选消息分支，冲突不会覆盖已等待的对白；主任务结束时，如果宝箱还有消息或领奖标记待完成，则明确阻塞并禁止保存或重启。移动只暂停拥有该移动指令的任务，不会顺带暂停主任务的对白/旗标；尚未恢复的多个任务竞争同一角色移动控制器保持阻塞。

渐变使用唯一 `FieldFadeState`。负时长异步推进，非负时长首次等待；其他任务替换渐变后，旧等待者观察当前全局颜色。Image 与 CanvasRenderer 颜色分开，保留来源 float32 和颜色量化，不用固定黑幕倒计时或容差替代。切图复制活动状态到候选，失败/过期候选不会改当前画面；稳定存档保存颜色和 raycast，活动 tween 不能存。见 [字段渐变](field-fade.md)。

玩家显隐能力由准确 DLL 和玩家 prefab 工厂链绑定。字段导出 `field-0.1.1` 现在包含 prefab 文件摘要，世界编译使用已锁定语料的同一依赖；不能仅因 Web 没有子节点就宣称原生 child 不存在。见 [玩家显隐](player-visibility.md)。

## 已实现的受控宿主与未接入部分

`FieldPuppetActorsPort` 读取明确的脚本 flags、角色/编队/居民上下文，批量准备 start、Entry、Ready 和 finish 的位置、层、朝向、动画与显隐效果。Exec/Finish 读取可信的世界地图脚本身份及 callback 状态，并准备地图碰撞、实体碰撞、交互观察三项开关；异步脚本结束不会自行恢复碰撞。坏依赖和失败准备不发布部分 Ready/Show。见 [演员宿主](field-puppet-actors.md)。

这些端口已进入受控 `FieldGame` 测试，但正式 `GameSession` 尚未提供完整原生隐藏演员与相机所有者。现有开发检查点保留其既有演员引导，不冒充来源初始化。声明 `scriptPuppetContexts` 的内容缺少宿主会停止；接入原生端口的实例当前禁止稳定保存/恢复及战斗返回，直到对应状态编解码和候选 owned-state 绑定完成。

摄像机 actor 0 有独立纯状态投影、目标选择、来源地图范围、SetPos 与 Lerp。它不是普通碰撞实体，尚未接入正式 `FieldGame` 和 renderer。真实视觉 offset、既有 SetPos 回调与 viewport/效果处理仍是下一步依赖。见 [摄像机](field-camera.md)。

渐变的开发透明初态也不是原生新游戏初态证明。标题到字段的实际交接、完整叙述/镜头和原生演员初始化仍须接通，不能把来源调用数量换算为可玩剧情。
