# 系统集成 v22

本批将剧情持有状态、稳定保存、入战资格和魔导装甲表现接到同一个角色所有者。正式开发目录改用 `source/current` 动态资格；仍从来源绑定的纳尔谢开发检查点启动，未完整执行片头，也不代表完整战斗或全游戏迁移完成。系统优先，区域内容与 HD-2D 不扩展。

## 持有状态与事务

来源 `AddCondition/RemoveCondition` 的参数是 condition type，持久状态保存 row ID。当前准入 type607 → row53。target0 选择当前编队，-1 选择 enabled 名册，正数查来源角色 ID；不会创建未知角色，也不把交通身份当状态。每个来源目标仍触发演员刷新，包括重复添加或清除不存在状态。

外观与所有中间刷新先在候选中准备，再提交持有状态和演员；缺媒体、未知 `KeepBadStatusVisual` 或过期草稿均不部分发布。状态与编队、库存、切图共享草稿版本。存档继续使用 owned v6、field/world v4；恢复覆盖开发检查点种子，不重放已经清除的607。210个来源调用点中8个607调用准入，其余202个保持阻塞；这不是完整脚本或剧情覆盖。见 [剧情持有状态](owned-conditions.md)。

## 入战与菜单

18份普通模板保留来源初始化、当前持有能力和独立执行计划。只有具备对应外观提供器才解除607外观门禁。当前地图和交通决定禁用内容；步行存档点或兽原上下文在实际需要且未知时阻塞，不自动填 false。

物品菜单按每名角色、完整 enabled 装备占用与战斗内即时库存计算；最后一份消耗和已有预订分别处理。命令使用原始禁用列表，单项能力与物品使用来源过滤后的列表，不能共用一个布尔开关。能力的首函数身份与函数类别分开，已学能力也不等于效果已迁移。见 [入战提供器](battle-entry.md)。

## 魔导装甲表现

状态初始化保存原角色尺寸类别，607选择来源魔导姿态；死亡及战斗结束按来源条件规则保留，明确移除时恢复原类别。尺寸类别不是图片高度。默认、死亡、濒死及当前二维动作宿主所需的右向姿态使用来源别名；身体与装甲分别选择媒体和帧。

精灵导出保留 PPU、pivot、Clamp 和 point filter，画面使用来源 UV 与像素位置，不再固定裁去8像素或固定抬高22像素。右向姿态使用实际 R 媒体。完整原生动画调度、动作时长、音效、特效和动态画面对照尚未完成。见 [战斗状态外观](battle-appearance.md)。
