# v49：探索遇敌与战斗返回

当前优先级仍是游戏系统骨架。新增一条不依赖剧情脚本的闭环：普通行走、遇敌、战斗、一次结算、原地继续探索、菜单及存读档。共用系统接受地图配置，运行时没有纳尔谢或敌队编号分支。HD-2D 和原版动态对照继续后置。

## 状态与交接

- `GameSession` 持有唯一 `WalkEncounterState`。字段只准备和提交一步；RNG、计数及每地图倒计数随会话保存，离开地图再返回不重置。配置身份变化拒绝沿用旧进度。
- 起步时，在碰撞、门与交互准入通过后准备候选；步末一起提交已有地图状态效果、坐标和遇敌计数。撞墙、失败移动、脚本移动、暂停与宿主未就绪不消费普通行走计数。
- 目的地事件优先。即使事件同步结束，本步也不追加随机战斗；已抽中的本次结果被消费。该选择属于明确的 Web 开发协议，尚未声明为原版概率与取消规则。
- 普通战斗请求使用 `returnTo: {kind: "field-idle"}`。胜利返回保留同一字段、演员、位置、变量与生命周期，不创建空白后继脚本。原有剧情战斗继续使用来源 continuation。
- 返场外观与奖励先共同准备、校验，再一次发布。媒体或宿主不完整时保留未领取奖励。战斗准备失败保留原位置和选定敌队，页面可重试，不重新掷骰；败北重试继续复用原战斗租约与初始种子。
- 未发布、被取消及已退役的地图候选没有消耗遇敌状态的权限；候选被外部步进改变后不能提交。

外层检查点升为 v5，包含遇敌状态。v4 仅在受信任内容没有步行遇敌配置时可读，并在下一次保存时升级；不能用缺少计数的旧存档重置已开启的遇敌系统。移动中、待入战与战斗中仍不允许稳定保存。

## 内容配置与批量入口

`FrameworkWalkEncounterPolicy` 明确标注开发协议：调用方提供最小/最大步数、允许交通身份及完整权重敌队池。当前使用确定性 uint32 LCG 与拒绝采样；这不是原版随机数迁移。没有显式配置的来源地图不自动启用这套规则。

`compileWalkEncounters` 读取 `map.csv` 与 `monster_set.csv`，保留原始 16 槽、来源行、权重与原生步数参数。原生参数不解释为格数。只有显式提供开发配置且所有正权重敌队依赖都就绪，才生成策略；未支持和条件化敌队整组阻塞，不过滤敌人后重新归一化。重复敌队仅合并权重，原槽证据保留。

批次依赖图纳入所有候选敌队。来源批次拒绝开发遇敌策略，初始字段与地图包的策略必须相同，避免入口偷偷启用未分析的战斗。

本地来源盘点：205 张地图有默认敌组，共 96 组、259 个正权重敌队，与当前六个已发布剧情敌队没有交集。当前盘点不产生可准入的来源遇敌策略。地图 3/18 的来源 set129 引用 276/274/275/129，权重 80/80/80/16；不能套用开场剧情编组。普通编组的多阵型、条件选择及其能力依赖是后续共用系统工作，不逐图补丁。

## 验证口径

`npm run walk-encounters:check` 使用本地实际开场地图、队伍与战斗内容，加上明确的“两步选择 party3”控制策略，验证保存倒计数、行走入战、96 Gil 奖励与成长、同一字段原地返回、菜单保存恢复与下一步。只写入忽略的控制样本，不改正式来源包。该检查已经接入 `framework:verify`。

专用测试覆盖确定性重放、权重边界、陈旧/重复/失败提交、墙体和脚本移动、触发器抢占、入战失败重试、自然败北重试、跨图候选取消、内容绑定与旧存档升级。原生来源静态证据只确认起步准备/步末事件优先，以及遇敌计数独立保存；未新增原生导出，也未关闭原版阈值、特殊旗标、交通切表、战后重排或全剧情验收。
