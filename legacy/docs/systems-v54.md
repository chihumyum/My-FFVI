# v54：战斗与字段共享剧情状态

这一批补齐游戏系统之间的状态接口。战斗根脚本可读取、分支和修改共用剧情状态；胜利或普通撤退时，将变化与角色、库存和奖励一起提交，再恢复字段脚本。没有新增具体地图或敌队的运行时分支。HD-2D 和精细表现继续后置。

## 所有权与提交

`EventState` 是剧情旗标、宝箱旗标和全局整数的唯一持久所有者。`BattleEventSharedState` 借入三组银行的独立快照，只保存固定入战基线及本场候选。未知单元保持未知，读取时仍拒绝；显式赋值可写入此前未知的单元，不能默认填零。字段与战斗的脚本局部帧不互相借用，选择寄存器和地图临时值也不进入这条接口。

`BattleGame` 在同一帧事务内处理共享读写、根程序、AI、动作、随机流与逻辑时间。任何后续动作或 AI 错误都恢复本帧候选。战败重试重新使用固定的入战银行和程序，不带入上一战的共享变化，也不采用后来被修改的目录对象。

`GameSession` 将战斗候选传入既有 `FieldGame.prepareEncounterReturn`。返回准备先验证所有借入单元，包括只读取而没有改写的单元；任何过期基线、缺失续行或演员准备失败均发生在奖励发布之前。成功时一次发布角色、库存、奖励及全局变化，再恢复事件；普通探索撤退复用同一事务，但不发胜利奖励。字段仍持有原 `EventState` 对象和暂停的局部帧句柄。

稳定保存继续使用现有检查点合同；存档无需新增第二份战斗剧情状态。保存后的字段会话保留已提交的旗标与整数，恢复后下一战借入这些实际持有值。进行中的战斗仍不开放任意保存。

## 编译器与公共查询

共同支持 `ScenarioFlag1..4`、`TreasureFlag1..4` 和 `ScenarioVariable` 的计算、分支及 Set/Reset/Flip。带符号旗标地址复用既有 `EventState` 规则，先转换至同一银行位置；ScriptLocal 继续由战斗 VM 独立持有。未知类别、未声明局部槽、稀疏银行、非法整数、额外结构字段及不匹配的来源操作数仍拒绝。

精确 SysCall `プレイヤーの状況で戦闘終了` 映射为 `players-ended`。查询读取当前 `BattleGame.players`，逐单位使用既有条件结束规则；结果为 true 时将脚本局部槽 0 写成 -1，为 false 时保留原值。它不直接改写 HP、队伍或奖励，也不代替终局所有者。

来源绑定见 [来源记录](battle-event-state-source.md)：12 份已有 C 回执、38 个原始函数区间、7 组绑定检查及 15 个精确 selector 注册。6 处共享变量操作和 10 处玩家结束查询用原 PC、原操作数单独验证。53 个完整战斗程序仍有 52 个保留其他缺口；支持这 16 个调用点不能放行完整程序或敌队。

## 来源与 Web 策略的区别

原生 `DataStorage` 单例立即写入全局银行。Web 当前将战斗变化暂存，直到成功返场才与其他状态一起提交。这是为失败回滚和重试建立的明确 Web 事务策略，尚未证明与原版的全部可观察时点一致。

原生序列化排除脚本局部银行，但尚未证明完整的字段 → 战斗 → 字段局部银行备份规则。Web 显式隔离两套局部帧，保护暂停的字段任务。原版没有运行，本轮全部静态回执继续标记 `semanticsVerified: false`。
