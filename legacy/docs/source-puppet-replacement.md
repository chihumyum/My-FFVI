# Source temporary Puppet replacement

This family is a persistent callback list of source entity selectors. It is not a party organizer, actor factory, resident alias rewrite or another roster owner. `GameState` exposes the existing three Corps slots and full owned identities through one detached read. `FieldGame` owns only the bounded callback value and its Puppet tasks; actors, camera, materials, collision and permanent party remain with their existing owners.

The complete physical inventory retains 3304 programs / 186003 operations. All matching replacement and RTS selectors are retained as 53 complete programs / 4526 operations, 179 sites and 10 dependent map closures / 265 assets. Nine generic replacement selectors account for 109 sites, including 60 reset sites. Three NPC dictionary/placement forms account for 12 sites and remain explicit gates. All 58 RTS sites retain their separate permanent-party and motion protocol gates. These static counts are not original story execution or playable coverage.

## Native contract

The native evidence checker binds 20 unique wrapper/owner methods (11664 PE bytes), a previously exported complete CopyEntityLayer body and a shared predicate's actual 48 PE bytes to the supplied DLL and IL2CPP symbols. The failed first export has no complete receipt and is not accepted. Callback wrapper 277220 tail-jumps to Integrator.ReplacePuppetEntity at 5f4ab0; its inline Ghidra output is not misreported as extra wrapper bytes. Method metadata identifies the callback and the owned-ID predicate without assigning semantics to an arbitrary shared managed alias.

Slot forms enumerate all four raw stored cells. A zero owned identity stays zero; a nonzero identity resolves through the complete owned list, including disabled owners, to the negative CharacterStatus ID. Leader is the first nonzero raw cell. Except-leader keeps that cell as a zero hole. Two-leader form keeps both list positions. Battle-party reads ScenarioVariable[4] and the actual selected Corps slot: equality leaves the existing callback/list intact, otherwise it publishes `-1030-selectedSlot`. Reset clears the callback/list and is repeatable.

On first Exec, callback list index i addresses actual track i, before Ready. Sleeping tracks do not compact the mapping. Only Awake tracks are rebound. Zero sleeps that task and still copies player Z/layer to the actual sprite-less camera dummy, preserving dummy XY. Nonzero destinations retain actual actor/inner entity identities and XY, receive player Z/layer, and refresh existing view/transparent bindings. Ready then shows the rebound actual actor through the existing host. The callback remains installed for later Exec calls.

The Web implementation prepares callback effects, Ready, zero task sleep, collision, assignment reset and camera changes before publishing any of that batch. Init and SetPuppet instructions committed earlier in the program are separate operations. Unknown/absent destinations, unbound resources, unknown children and foreign callbacks remain gates. Empty Exec's warning continuation remains a gate rather than silently succeeding after all listed tracks sleep. The known sprite-less camera does not invent a material or actor entry.

## Persistence and boundaries

The callback list persists across script initialization/finish and prepared battle failure, cancellation and return. Maps transfer a detached integer value to a private destination before its initializer. Failed/cancelled/stale preparation preserves the old value; successful publication retires the old execution owner. The retired Field no longer advances and cannot start a replacement callback; no integer selector is retargeted into an old map's actor instance.

Stable saves include an optional native callback value bound to source set, parent source set and Misc catalog. Restoration requires current trusted native actors, full Corps reader, camera and known absent foreign callback, and checks resident selector provenance. Actor/provider/catalog authority cannot be supplied by a save. Active events retain the existing save refusal. Storage quota failure retains the live value and permits retry through the same public owner.

The NPC forms require the actual Current static dictionaries at +0x140/+0x148 and complete placements; role-ID/scene-specific branches do not replace those data. RTS operations also switch permanent selected Corps, saved per-party playable leaders and field/camera transforms, including a 1.4-second shared-register motion sequence. Their reset-looking names do not authorize a no-op or reuse of this temporary callback transaction.
