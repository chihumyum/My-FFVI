## 来源与导出

仅适用于 DLL SHA256 `1a7e12c90c6a734e17dda507dd6ab7555090dff6a1e96f3473a90c29916ca6dc`、metadata SHA256 `9b426d617a022020feee61cdfc19b16ce1a51c07542fe1dd59169e12f35a3e45`。导出器同时检查主表包和 BGM 包，保留父来源 `6638e4e4f46835754f17c376a253da6de7a1996cab5e9fda71ff09cddace8965`。

`bgm_asset.csv` 的 105 行与既有导入逐行核对。曲库包中的音频是 MAB TextAsset，并非 Unity AudioClip；按精确容器路径和表中 `asset_name` 连接，保留语言后缀。原生 `BgmAsset.PlatformAssetName`（`0x142CDB0`）将当前两段名称转为 `stem.win.mab`，资产路径另带 `.bytes`。不采用文件名相似匹配。每条记录含表行、包摘要、序列化文件、十进制字符串 path ID、原始 MAB 摘要和 PCM 摘要。

导出器 `tools/source_adapter/export_bgm.py` 使用 vgmstream-cli r2117 将来源音频解码一次，再用 FFmpeg 编码为 FLAC。解码时不把循环展开进文件；原采样率、帧数和循环起止样本单独保存。每条 FLAC 再解码回 PCM，必须与第一次解码的 PCM 摘要相同；多音流、非法循环和不支持的声道数明确拒绝。源文件在操作前后校验，临时文件只写入 `build/`，输出完成后原子替换。

解码器对 MAB 的支持依据为 [vgmstream 官方格式列表](https://github.com/vgmstream/vgmstream/blob/master/doc/FORMATS.md) 和 [SQEX SEAD 解析器](https://github.com/vgmstream/vgmstream/blob/master/src/meta/sqex_sead.c)；当前工具版本 r2117，对应 [源码修订](https://github.com/vgmstream/vgmstream/tree/71e2361042531fe767fb98300cf8c1ee95e539a0)。本机从 Homebrew 安装 vgmstream r2117_1 时，Homebrew 同时更新了 FFmpeg 至 9.0.2、OpenSSL 至 4 及相关依赖，完整安装日志在 `build/vgmstream-install.log`。其他解码器版本需重新审核；FFmpeg 版本进入媒体元数据，不能把不同编码版本的输出当作同一产物。

导出结果为 105 条、共约 253.28 分钟，其中 62 条含循环区间；FLAC 合计约 1.4 GiB。全部 105 条通过 PCM 往返；首批另对一条曲目独立重复解码与编码。2026-10-11 抽取共用解码模块之后完整重复导出 105 条，快照摘要相同，收据见 [环境音批次](environment-audio.md)。

## 指令与状态

| 静态证据 | 当前采用的语义 |
| --- | --- |
| `0x8176E0`、`0x818CF0`、`0x819C10`、`0x838960` | PlayBGM 的 i0 为主表 ID、i1 为异步方式、i2 为静态通道，r0 / r1 为淡入秒数 / seek 秒数；当前仅支持显式异步 i1=1、通道 0/1、非负淡入和 seek、零 pan |
| `0x81ACB0` | BGM 静态通道为两个独立槽位 |
| `0x493740`、`0x4A3A20` | 同通道同曲目且 seek=0 时保留播放位置；替换曲目时旧实例按 0.5 秒停止，新实例使用请求的淡入 |
| `0x81A140`、`0x4953E0`、`0x495500` | StopBGM 读取通道和淡出秒数；通道立即分离，旧实例继续淡出直至结束 |
| `0x491970`、`0x142CDB0` | BGM 主表身份与平台资源名连接 |

15 个方法的完整导出及原生指纹收据位于 `build/native/audio-bgm*/complete.json`，摘要核对记录于来源完整性收据。静态反编译是实现依据，未替代原版运行对照。

`StaticAudioState`（环境音批次从 BgmState 统一命名）在内核保存逻辑时钟、两条通道、播放实例、seek 和淡出状态。曲目先播放引子，到来源循环终点后回到来源循环起点；无循环曲目按来源帧长结束。缺失曲目或非法请求在更改原通道之前失败。状态副本不共享可变对象。

`WorldSession.prepare` 将音乐状态复制给候选地图。新图初始化失败、请求被放弃或过期，都不能改变原图音乐；提交还检查原音乐状态未被修改。浏览器解码结果只按资产摘要缓存，不调用游戏 VM，不回写剧情状态。切图资源准备完成后才提交。

## 浏览器表现与明确适配

Web Audio 在开始按钮的用户操作后启用。文件摘要、解码声道和时长通过检查后才播放，循环点使用来源采样率换算。缓存保留活动曲目及两条非活动曲目，避免全部 PCM 常驻。静音只影响输出增益；暂停、地图总览、页面隐藏及明确停止状态暂停音频时钟。长渲染帧导致逻辑/音频位置偏离超过 125 ms 时按逻辑位置重建播放实例。

音频等待期间冻结模拟、全局增益 0.45、线性淡化、长帧纠偏和暂停策略均为当前 Web 开发适配，尚无原版混音或时序对照。页面“音乐播放中”来自主音量之后的非零 Web Audio 分析器信号，不能解释为已人工听音确认或与原版输出一致。
