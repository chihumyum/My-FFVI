# Animated map entities on the Web

The batch unit is every physical `object_type=10` map object, all installed map and Resident programs, and the remaining non-cardinal direction cases. Raw nomination precedes typed decoding: a failed object remains in the denominator. The original source set has 153 affected maps, including 152 maps with kind 10 and one additional map with two kind 6 direction-7 objects. This is a content-family inventory, not a claim that those maps or their stories are playable.

`web-field-animated-map-entities-v1` is an explicit framework policy. Strict source maps retain the animated-map presentation/lifecycle blocker. The policy does not apply to the two NPC direction-7 cases and does not infer a cardinal facing from kind 10's opaque direction 15.

The source factory constructs `FieldMapObjectAnimDefault`, a `FieldSpriteEntity` and `IInteractive`. Its Init selects `Default` through the shared authored playback-mode path when `play_on_awake` is true; the reviewed body does not consume the property's Direction field. The Web implementation places the object in `FieldGame.actors` with scope `map-animated`, `character=false`, and `direction=null`. It uses the existing `ActorAnimation`, native actor projection, field clock, group activation transaction, source script VM, collision/interaction flow and checkpoint codec. It creates no NPC movement controller, additional VM or animation owner.

The Web policy draws the source sprite and frame through the existing flat compositor. Native split/building/stencil and native depth appearance remain unverified. Building and front metadata remain source-bound; unsupported auxiliary hosts remain blocked. A non-playing initial object uses the first Default frame as a declared Web presentation choice. This does not establish the native stopped object's initial sprite. Opacity is an explicit Web compositor policy, not proof of the kind-10 native material pipeline.

The native JSON import protocol is separate from this display policy. The fixed original `MapManager.GetSpriteAnimStructure` loader calls `JsonUtility.FromJson<AnimAssetDatas>`. Unity's [2019.4 API contract](https://docs.unity3d.com/2019.4/Documentation/ScriptReference/JsonUtility.FromJson.html) assigns default(T) to missing fields without running the constructor or field initializers. A missing string is null. The retained `SetupAnimCommon` and `SwitchNext` consumers use `String.IsNullOrEmpty(next_anim_name)`, so null has the same no-successor branch as an empty string. Only a physically bound original anim_info object, its complete raw hash, bundle identity and matching DLL may use that normalization. Explicit malformed fields, aliases, foreign objects and unbound authored inputs remain rejected. Raw JSON and its original source hash remain unchanged; `WorldCatalog.characterImports` records each import observation. This rule supplies no default world state or plot flags.

The saved actor payload remains the existing native actor codec. Trusted map definitions and the profile reconstruct actor metadata at restore. A save cannot grant the policy or native shader bindings. Failed/cancelled map/media preparation preserves the old actor and playback; successful map preparation installs one map-local successor. Battle suspends the same actor and returns to it through the existing session handoff. Stable restore does not replay Default selection or source initialization.

New framework derivatives explicitly declare the policy. Pinned recipes require the exact additive `compiled-framework-profile-upgrade-v4` declaration, which verifies its compiled provider and audits previous/candidate identities. Versions 1–3 do not implicitly gain this permission. The marker declaration cannot normalize geometry, source, script, animation-media or other gameplay changes. A separate `compiled-source-map-animation-import-addition-v1` audit reconstructs both generations from the same raw corpus and media snapshot. It verifies exact legacy/current Character definitions, import observations, source kind-10 rows, character asset membership and all pose diagnostics before constructing a detached comparison projection. Unrelated entity, geometry, script and diagnostic changes remain visible to the ordinary gates. Both original identities and raw-source hashes are retained in the audit; actual candidates and tracked recipe pins are never rewritten.

The batch tools are private pure consumers until the publication owner runs the normal content package pipeline:

```
node scripts/compile-source-map-animation-candidates.mjs --compiled-dir dist --output build/source-map-animation-candidate
node --max-old-space-size=8192 scripts/check-source-map-animation-programs.mjs --compiled-dir dist --candidate-dir build/source-map-animation-candidate --output build/reports/source-map-animation
python tools/native/check_source_map_animation.py --input build/native/source-map-animation-inputs
```

The native input directory contains an ignored `manifest.json`, original complete export receipts and the thirteen reviewed C bodies. The checker verifies all copied bytes against the original DLL, symbols, header and metadata; it needs neither Ghidra nor an old WIP readiness report. No original assets or decompiled game bodies belong in Git.

The source checker rebuilds the raw family from the complete bound corpus, uses one same-runtime source candidate, preserves all map/Resident namespaces and dependencies, and attempts each original initializer before its related full source bodies. It records initialization prerequisites, actual completion, clock observations and stable save/restore independently. It never injects plot flags, roster members, extra money or alternate scripts. A directly invoked root after initialization is a controlled mechanism probe, not proof of story reachability. All remaining geometry, material, opcode, party and initialization failures stay in the report.
