# 来源剧情战斗入口

这一批处理全部来源 `Encount` 的统一入口、候选目录和返场生命周期。它不按地图或敌队 ID 分支，不改原剧情正文、PC、旗标、HP 或名册。当前来源保留185个使用点、162份物理程序、284个非空候选槽及89个敌队依赖；未知战斗行为、地图初始化和其他来源指令仍阻塞。

## 来源合同与明确的 Web 政策

来源指令要求完整8槽操作数，前四个整数是原始概率槽，重复敌队保留其权重；第五个整数是 effectId，首个字符串是返场脚本。空洞槽、全零分发、负数及未证明的保留参数不转成默认值。编译器只生成数据并发现所有候选依赖，不选择战斗、不读活状态。

`web-source-encounter-uniform-slots-v1` 由实际 app 和批次执行器明确选择。它复用 GameSession 已保存的 seed 与 encounterSerial，采用独立域的确定性均匀映射，不新建随机状态 owner，也不声称复刻 Unity 随机流。单槽指令同样需要这个政策；旧 authored encounter 的合同单独保留。

当前指令只消费 FootInfo 的背景投影。进入时先从可信地图定义和**尚未同步的实际玩家**捕获该投影，再将相机 dummy 的 localPosition 和直接 GameObject.layer 写入实际玩家的私有草稿。默认遇敌表与排除路径均可证明 BG0 时，记录为 `default-or-excluded-unprojected`，不伪装成完整 FootInfo 或 null；无 attribute 且无默认表才是已知 null。terrain、overwrite 以及其他未证明的背景选择仍拒绝。

## 单一会话与事务

FieldGame 在来源指令处准备一次槽位选择，固定敌队、effectId、返场、FootInfo 投影、任务和演员身份。GameSession 校验全部可能候选的依赖，复用现有战斗入口、媒体准备、owned lease、结算与返场。候选成功发布时才同步玩家并提交 encounterSerial；旧 Init/Finish、相机重新初始化或第二套战斗状态都不是替代操作。

媒体失败、取消、晚到结果和过期演员/相机候选不能提前修改 live 状态或重抽选择。实际 app 的 GameFlow 准备门禁暂停字段时钟；跨多个真实 RAF 的延迟媒体仍须保持原 request、owned state 和演员状态，重试后一次发布。败北重试保留同一入场与 lease；胜利结算和返场只提交一次。

稳定存读复用已有 codec、Repository 和事件 continuation；保存不会授予政策或重新执行初始化。未发布的准备事务不转成稳定保存。恢复后的下一次来源指令继续使用同一会话随机序号，过去的奖励与演员同步不重放。

## 验证范围

全量目录从当前编译器和来源表重新生成，不复制公共旧 common 能力。静态 ready/conditional/blocked 是完整战斗依赖评估，不能解释为剧情可达或原地图可玩。一次旧公共能力表曾错误地把两个已支持的技能标成未知；原失败及新鲜重编回执分别保留。

整组执行先按完整原正文、每个地图的真实 alias/Resident 命名空间、所有后继与全部候选依赖选根，保留其余程序的排除原因。原地图初始化路径与独立受控地图路径分开：前者执行原初始化器，后者明确使用既有受控地图而安装完整原程序，两者都走实际 Session、Flow、Handoff、命令及保存 API。不跳未知指令，也不把源指令正常结束或受控放置当作主线进度。

原生审计只验证固定 PE、完整方法字节、元数据和结构绑定；未运行原可执行文件。实际 DOM/Canvas、受控图像/音频确认及 RAF 检查也不等于真实浏览器像素、声音、原版动态一致性或新游戏到结局验收。
