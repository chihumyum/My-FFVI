# v57：角色参与战斗的公共骨架

角色借用、加入、换组、重入及结果回写已经接入同一个 `GameSession` 和战斗 lease。内容声明依赖，持久角色 owner 提供固定资源投影，战斗只管理当前实例与临时资源，返场时整体提交。它不为某场战斗增加运行时特判。

## 统一身份和资源边界

- `BattlePlayerPlan` 属于 encounter。借用池包含入场角色、明确声明的来源角色及三组已存编队中的指定组；必须存在唯一已有 owned 记录及战斗定义，包含尚未启用的已有角色，但不会创建、启用或永久入队。
- 四个 Corps 格保留空位及行位。加入使用第一个空位，换组保留指定组的格位。当前实例有独立身份 `player:dynamic:N`，退休身份不再接收行动；同一角色重入时取回已有临时资源，不复制另一个 HP/MP owner。
- 所有候选身份、状态、装备、能力上下文及显示资源在准入时检查。整组准备成功才发布；帧内失败恢复单位对象、身份历史、计时、装备资格、行动队列、剧情草稿及随机流。失败帧用零新增时间重试。
- 观察学习在行动开始读取完整当前玩家列表。只给当时在场的角色记录日志；结果阶段分别检查资格。未在场角色不会回溯获得旧观察。成长投影保持纯函数，首次参与顺序决定学习回执序号，可以超过四个当前格位。
- 结果按首次参与的 owned 顺序，每个角色一次。战斗结束清理临时状态；资源、成长、道具、钱、剧情与地图返回共同准备及提交。保存的是提交后的角色 owner，实例历史不进入持久存档；败北重试重新借用同一固定入场池。

## 明确的开发策略与来源准入

`web-owned-borrow-v1` 明确采用 `all-entered` 角色受益者及 `preserve-entry` 保存编队策略。源编译器不会默认给原版遇敌套用它；没有来源角色资源闭包和回写策略的事件继续阻塞。

原始 `BattleAddFellow` 两处操作保持精确参数：`sc_b_0017:20 → source33`、`sc_b_0460_2:43 → source1`。玩家完成端口与敌方加载、行动演出端口分开。Web 预加载后同步准入，不声称已重现原版异步帧序。

原版 `LB:プレイヤーパーティ変更` 没有组参数，消费预置 owned 等待名单并局部替换符合状态的角色，不是 Web 的指定 saved group 整组替换。普通结果按当前单位回写；最后战斗 flag3 会绕开该普通路径。真实等待名单、特殊结果及完整故事合同继续单独阻塞，见 [来源边界](battle-player-transition-source.md)。
