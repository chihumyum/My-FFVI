# v41：共用事件移动与连续系统验收

本批继续优先搭建可运行的游戏骨架。角色与镜头的脚本移动通过同一指令契约接入事件任务；没有新增地图名、脚本名或坐标专用运行规则。框架验收关注状态所有权、统一时钟、等待与交接、连续游玩和失败回滚，完整机制覆盖与全游戏迁移仍单独追踪。

## 系统变化

`Move` / `Lerp` 由共用编译器保留坐标、速度、动画、层和来源位置，运行时根据当前任务的真实绑定选择演员或镜头宿主。每条移动路径归既有演员所有；插值寄存器归发起它的任务所有。暂停、后台、媒体未就绪和宿主操作继续通过 `GameFlow` 冻结同一个时钟，渲染器不另算游戏进度。

普通原生演员能够逐格移动、插值到指定位置并等待结束，随后继续对白、事件或地图交接。多个镜头槽保留原来的来源执行顺序；普通演员的未恢复并发写入明确拒绝。活动插值不能被换脚本、切图、入战或主任务结束悄悄丢弃，避免临时位置进入稳定存档。移动完成时先提交持有状态，再发布坐标和动画；失败不会留下半次移动或重复到达事件。

旧开发入口仅在自身明确的非原生宿主中保留已有空动画 Move 子集，继续使用原来的逐格任务。缺少原生依赖的来源会话不能借此回退。演员插值的实体动画调用与旧 Puppet 动画调用分开，避免 `next` 动画链被额外选择一次。详细参数、来源依据与宿主限制见 [共用剧情移动](field-script-motion.md)。

## 内容身份与接续

内容包重新绑定各自摘要，旧内容的存档不会被静默套用。公开战斗 profile 仍为 `narshe-playability-v35`，owned v8、field/world v9、session v4 不变；开发配置与严格来源内容及保存槽继续分开。

下一系统工作根据实际依赖补齐共用地图实体工厂和交接，再推进角色学习与通用战斗事件。代表性系统组合通过后才按能力闭包批量接内容；不要求先把每项特殊技能和表现细节做完，也不能用空操作跳过当前批次真正依赖的能力。相机 Move、骑乘、循环路径、实际玩家动态移动倍率、Sprite 弧线等仍待各自宿主实现。原版一致性对照、精细表现和 HD-2D 保持后置；完整 Web 迁移尚未完成。
