# 子敌队的来源准入与实际工厂

完整来源范围仍为3304程序／186003操作、Battle53／2312和原490请求（483描述＋7来源诊断）。共同工厂有33站点、7完整正文、718操作：25条单怪增援、3条LB换轮、5条Gau换队；5个Gau站点依赖405原请求。这些是来源覆盖，不能记为通关或可玩队伍。完整旧Gau94／41／6858关联范围另保留。

本族只增加独立目录v9的`childPartyAdmission: web-source-child-party-entry-v1`与实际Session同名运行授权。原默认v7文件、独立v8文件和v1–v8精确形状保持不变。没有来源政策或实际运行授权时，不能使用新子队合同；存档不能提供这两项权限。

编译器先独立核对完整MonsterParty原行、九槽、Monster与asset行、原物理AI、源参数结构、正生命值／等级、非负奖励、完整元素组和媒体尺寸及完整旗标行。身份错位、缺引用、改slot或AI物理绑定仍是目录hard。标准来源编译失败也保持hard：原子队514的attribute_group125／element5冲突保留原诊断和完整raw，不产生ready子队，不以排列或后写覆盖。

完整已知entry-only旗标集合为14／19，涵盖空组、19-only、14-only与混合组。14仍需普通story上下文；19仍需已有显式Web手动控制器。子队构造不重新执行入战初始化：保留同一root的场景、编队选择、控制、逃跑和结果owner。原child旗标与not_escape原值保留在严格内容事实与来源proof中。原生SetMonstarParty直接体只替换InstantiateManager敌人数据；BattlePlugManager.Start另捕获entry旗标和escapeType。此静态证据不等于整个原生间接调用或Unity更新顺序已等价。Web保留父上下文是显式政策，原root escape3的既有门槛没有被放开。

包含3／9或其它未闭成员的完整旗标组、未实现child escape模式、条件、名字或能力等行为依赖，保留为严格deferred entry与全部原诊断。它不是空ready子队。独立初始化消费者重新绑定完整来源行、槽位、成员、旗标、原escape与每项执行gate；篡改或丢失gate拒绝。只有到达实际共同prepare时才要求这些语义闭合。

同一BattleGame的Gau媒体任务与LB换轮使用共同纯准备检查。先检查完整child entry／gates及实际ready内容一致性，再发媒体请求、创建新实例或退休旧单位；实际到达未知项则在原PC明确停止。准备失败的帧沿已有Battle事件事务回退，已经成功的前帧、动作费用、效果和manager时间不声称回滚。旧实例、AI、ATB、状态、队列、奖励ledger、同一GameState lease和prepared return继续由既有owner管理。

当前实现保留既有Web资源预加载与原子换队规则，没有实现原生先隐藏／销毁再异步构造的顺序。未知资源不补ack。源名称函数保持原identity与typed方法，真实live-name owner由独立名称族接入；本族不填默认名字、补held成员或改变名册。持有加入的首次装备、Quick退出、save/victory/escape合并顺序仍保留旧具体门槛。

验收分为来源proof与旧目录守恒、受控原参数／机制、真实Session和Storage、实际App与BattleView、原始正文与原始队伍执行。前几项不能替代最后一项。独立检查器为`scripts/inspect-source-child-admission.mjs`及`scripts/check-child-admission-view.mjs`，所有报告落在其calling worktree的物理build/reports中。本族不运行649生产或发布。

## 后续默认升级的有界接线清单

当前交付仍为明确opt-in；默认升级由下一联合候选单独决定，并使用同一份新策略字节／摘要，不修改旧v7审计输入。

- 纯完整目录：`scripts/source-battle-directory.mjs`选择新v9文件，向compileBattleEncounterRuntime传`framework.childPartyAdmission`；同一框架保留Gau factory、sourceParticipants、spawnConditionPolicy、forcedSavePolicy、sourceFormatImport完整闭包。
- Framework真实新游戏与恢复：public内容管线／source-candidate／initialized producer选择同一新v9策略；`validateInitializedBattleSharedCapabilities`和source participant proof重建完整绑定。framework source battle引用完整目录，初始owned、source initializer、route/factory不换成示例；保存只能重绑可信目录。
- 实际App：`battleChildPartyAdmission: WEB_BATTLE_CHILD_ADMISSION`透传GameSession，再由同一BattleGame读取；Gau媒体仍由实际image repository提供真实decode与尺寸状态。不得用typed元数据或默认true替代实际媒体。
- Common Session replay：现有通用observer仍固定读默认v7，尚不选择本独立v9文件。升级时须增加明确同policy输入，给loader和participant closure传Gau授权，给runtime compiler传完整Gau factory＋childPartyAdmission，给实际Session传child运行权限和真实媒体提供器。若观察器使用受控媒体ACK，报告必须明确controlled host／源资源身份与未验证浏览器像素，不能称为source/native媒体实玩。
