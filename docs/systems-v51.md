# v51：战斗结束与持久化

这轮补公共战斗退出合同。普通探索遭遇可通过显式开发策略撤退；战斗、持有状态、返场和存档仍由既有所有者管理，不按地图或敌队编号另写规则。来源逃跑时机与成功概率未恢复，HD-2D 和精细演出继续后置。

## 从退出请求到再次探索

1. `BattleEncounter.escapePolicy` 是逐敌队的显式能力声明。运行时解析并复制 `framework-battle-escape-v1`，拒绝未知字段及放在公共目录层的策略。默认来源目录不自动开启它。
2. `GameSession` 只为普通 `field-idle` 遭遇暴露撤退。现有剧情遭遇只有胜利后继，因此在构造战斗前移除该能力；既不会跳过剧情战斗，也不会擅自执行胜利脚本。
3. `BattleGame` 接受请求后停止新指令与敌人决策，等待已经开始的动作执行完。未开始的普通、反击和连续动作队列取消，未执行物品的预留释放。正在执行的动作仍可消耗物品、造成伤害；若已导致全灭或胜利，其结果优先。
4. WAIT 菜单不能卡住已接受的撤退；暂停、帮助暂停、宿主进度和强制等待仍生效。结果保留 HP/MP、持续状态、前后排和实际物品消耗，清理战斗临时状态；不授予经验、Gil、掉落或学习。
5. `GameState.prepareEscape` 与胜利共用一次性持有状态事务。`GameSession.continueEscape` 先准备原字段演员及返场，再通过 `commitWith` 一次提交。任一预检失败保留战斗副本、租约、地图和库存，可修复后重试；同一结果不能重复结算。
6. 页面通过 `GameFlow` 门控请求与返场。结果页显示“已撤离战斗”；返场发布前失败显示“重试返回”。若结算已发布，仅后续界面同步失败，则仍显式停止，不进入第二次结算。

## 一份结果记录

`owned-game-state` 升为 v11，既有 `completedBattles` 每条增加 `outcome: "victory" | "escaped"`。遭遇序号校验全部已结算记录；`completedEncounters` 只投影胜利，观察学习记录也只能绑定胜利。这样撤退不会被批次验收当成击败敌队，不需要第二份计数或胜利账本。

旧 owned v10 只能记录胜利，读取时先严格验证其原形状，再赋予这一已知结果并执行完整当前校验；不修改调用者对象或浏览器原存档字节。其他不支持版本仍拒绝。外层 game v5、字段/世界 v10 保持不变；活动战斗和待返场结果仍不能保存。

## 来源准入与未完成范围

编译器仅在显式 opt-in 且来源 `not_escape=0`、`get_value=0`、`get_ap=0` 时发出该开发策略；除已知的 NoARBattle 14 外，其他战斗旗标不能通过开发省略名单绕过。来源值 2 继续没有撤退能力。该保守范围不是完整来源逃跑许可实现；原生成功率、计时、重绘、剧情分支与其他旗标仍待恢复。

严格来源新游戏和来源内容批次拒绝开发撤退策略，即使调用方重算摘要也不能混入。开发批次保留明确的能力说明。本轮真实目录与新游戏包重新编译，已发布敌队仍为六个；没有把系统能力增加写成新内容覆盖。
