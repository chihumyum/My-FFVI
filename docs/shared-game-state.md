# 共享角色、库存与奖励状态

2026-10-13，[v54](systems-v54.md) 将共享剧情旗标和全局整数纳入战斗返场事务。`EventState` 仍为唯一持久剧情所有者，`BattleGame` 只借入可回滚的全局银行草稿；返场不替换字段所有者或脚本局部帧。角色和库存的 owned v12 格式及既有检查点合同继续复用。

2026-10-12，当前 [v52](systems-v52.md)。共享快照为 owned v12，包含逐角色魔法学习值与胜利/撤退记录；旧 v10/v11 仅按明确规则升级，仍须匹配内容身份。`GameState.createNewGame` 校验同源初始化定义、角色、装备、数量和上限，创建未叠加开发检查点状态的 owner；它本身不发布字段会话。稳定恢复保留数量、不重新执行初始化。默认槽与角色首次创建/已有角色重新加入的区别见 [空装备](empty-equipment.md)。下方旧版本说明和计数保留各自历史范围。

2026-10-11。`GameState` 统一拥有角色名册、三组编队、普通/重要物品、装备总持有数和六槽占用、Gil 与领奖记录。v17 将角色生命周期端口并入同一事务，快照升级为 `owned-game-state` 版本 4：保存原生持有 ID、当前职业、追加等级、持有职业历史、魔石身份和全局已释放职业。内容 profile 仍为 `game-state-development-v1`，受限于当前开发初始化。当前批次见 [系统批次 v17](systems-v17.md)，生命周期规则见 [角色加入与离队](roster-lifecycle.md)。本文保留的早期数据均为历史范围，不代表全游戏系统已完成。

## 所有权与交接

| 模块                         | 拥有的数据与职责                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| 内容编译                     | 角色定义、物品身份与分类、独立菜单/战斗函数与准入、上限、显式开场初始值；保留来源表行           |
| `GameState`                  | 会话中的名册、三组编队与当前选择、进度与库存；返回副本，校验变更后整体发布                      |
| `BattleGame`                 | 从当前队伍借入独立副本，拥有本场行动条、队列、敌人 AI、随机流与暂存结果                         |
| `GameSession`                | 协调战斗借用、失败重试、领奖和字段事件返回，不另存一份角色或 Gil                                |
| `WorldSession` / `FieldGame` | 地图及事件状态；库存、编队和名册端口共用 `prepareFieldState` 私有草稿，成功发布后同时重绑当前所有者   |
| 暂停菜单                     | 投影角色与库存；战斗中显示本场 HP/MP 和库存，地图中显示已提交值；道具确认交由会话和状态模块校验 |

进入战斗时建立带实例身份的借用记录并冻结入场队伍、库存与逐敌队奖励规则。战败重试从该记录读取奖励规则，角色魔法学习值不由菜单或共享目录常量维护。战斗期间禁止外部修改共享库存或恢复快照；v14 在本场副本中预订和消费道具，胜利时校验消耗清单并与角色、Gil、领奖记录一起提交。失败重试使用相同入场状态和种子，恢复战前角色和库存。战斗构造失败会释放借用。稳定地图中的菜单道具也经同一 `GameState` 投影资源和数量后整体提交。

胜利结算有两道边界。首先，战斗内部在临时副本上为所有角色计算经验、成长和战斗结束状态，全部成功才公布胜利；修复了后续角色缺少成长记录时，前面角色已经升级、奖励却无法领取的问题。然后，`GameSession` 预检地图后继脚本与局部变量，再预检所有角色、Gil 和领奖记录，连续提交后才消费奖励。地图后继脚本排入下一正常模拟步，不在奖励提交中执行。缺失后继、非法局部变量或非法角色结果均不会先消费奖励。

领取记录按战斗发生次序编号，不用 encounter ID 去重，因此同一种编组再次出现仍可正常领奖。旧借用、重复提交、替换后的事务均被拒绝。命令与能力仍取编译定义；属性由显式基础/成长上下文和当前装备重算。等级成长从来源初始等级逐级累加原始增量，不能从已封顶的 maxHP 反推；战斗升级、菜单换装和读档校验共用该投影。完整成长输入、被动能力与学习仍待做。

`prepareFieldState()` 为候选地图提供 `ports.inventory`、`ports.party`、`ports.roster` 和只读移动限制。三个写端口共用一个完整状态草稿和 `generation`；任一端口提交后，其他端口先前准备的事务也失效。候选发布还检查当前所有者的 revision 与战斗占用，不能覆盖期间发生的道具使用、换装或编队变更。成功发布只发生一次，随后端口调用都转向当前共享状态。准备失败、旧候选和被丢弃的地图不发放物品，也不更改当前名册或编队。

## 名册与编队

名册保存已持有角色及 `enabled`，编队保存 `selectedSlot` 和三组四格 `{ id, row }`。空位保留，不能把有空洞的编队压缩后再写回存档。角色可以出现在不同保存编队中，但同一编队重复角色仍在当前运行模型外。`activePartyMembers` 从当前选中编队投影成员、原位置和前后排；菜单目标、战斗借用及胜利归还使用这一投影，非活动名册成员继续持有装备和角色进度。

来源编排不会自动创建、启用或招募角色。v17 区分已持有、enabled 和活动成员：只有 enabled 名册预留装备副本，停用成员保留的六槽仍逐项校验，但不重复占用库存。离队的两种装备分支、职业释放和重加入均经生命周期事务；新持有角色的完整初始化、原生成长/学习与恢复提供器仍缺失，不能据此扩张名册。要求外观刷新的来源调用在真实字段中仍阻塞。

实际 `FieldGame` 只执行 `refreshActors=false` 的受支持切换，保存、恢复和后续战斗共享该选择。`refreshActors=true` 仍在提交前明确阻塞：leader、角色媒体、坐骑、状态和 companion 生命周期尚未完整恢复，不能用修改第一张贴图代替。纯编队与受控端口测试不意味着这条字段演出路径已开放。空当前队及包含后排的战斗也明确阻塞，不自动补人或忽略排位。

## 来源与受限规则

静态研究读取同一版本的 `GameAssembly.dll`、元数据、符号和结构头，不执行原始 DLL。首次 v13 研究核验了 15 个导出方法的完整回执、原文件区间和反编译文本摘要；后续扩展另有独立回执，原生语义验证字段仍为 `false`。主要定位：

- `NewGameWindowController.InitializeUserData 0x655220`、`UserDataManager.Initialize 0x8722b0`：原版分开初始化角色、物品、重要物品、仓库、魔石等所有权容器。Web 尚未恢复整个新游戏流程。
- `DataInitializeManager.CreateItems 0xaac310`、`OwnedItemClient.Initialize 0x7fa730`：先清空物品容器，再读取初始物品和 Gil；后续还有装备占位记录等分支。初始化选择器、角色创建与装备计数链尚未完整跟踪，不能把当前编译入口称作完整原版初始化。
- `CreateOwnedItem 0x7f8050`、`AddOwnedItem 0x7f7900/0x7f79a0`：内容类型有不同分支。首次只接入 `content.type_id=1` 的物品数量；v16 将类型 2/3 接入装备总所有权，保持占用语义，魔法与类型 9 的独立魔石所有权仍阻塞。
- `OwnedItemData.IsImportant 0x8df610`：物品行的 `type_id=2` 表示重要物品。内容 ID 与物品行 ID 分别保留，不因名称相似合并。
- `GetItemMaxCount 0x862bf0`、`GetGilMaxCount 0x862a70`：读取来源上限。`AddGil 0x7f7740` 的原始机器码确认持有 Gil 封顶，非负收入完整累加到 totalGil。

`initialize_data.csv` 的当前开场输入为角色 1/31/32、3000 Gil，以及 `INIT_ITEM_1` 的内容 58 × 1（对应 `item.csv:57`、重要物品）。六个装备槽来自各角色 `character_status.csv.content_id1…6`。这些输入用于已有开场检查点，不替代地图、剧情标记或能力解锁初始化。

来源上限为：单种物品 99、Gil 9,999,999、HP 9,999、MP 999、等级 99、经验 15,000,000。当前 totalGil 限于非负有符号 32 位整数，溢出明确拒绝；没有宣称模拟原版整数溢出。等级曲线和奖励资格仍沿用有标注的开发规则。

物品编译纳入 50 个内容身份，其中 13 个为重要物品。`changeItems` 提供整批授予/消费：授予封顶，消费先检查足量，任一条无效则整批不改。字段移除另走来源语义，允许耗尽已有数量；收入与收费也经同一事务所有者。v15 在固定 HP/MP 恢复之外接入复活与解除已支持状态；引用已解码不等于活动状态已支持。数量为零的记录保留；按内容 ID 排序只是当前确定性存储选择，不是原版排序结论。

装备总持有数包含已穿戴副本；空闲数量从全部 enabled 名册六槽占用导出。普通换装检查职业、槽位、角色限制、库存和效果依赖，在同一事务中处理另一手冲突并重算数值、元素和实际持武器手的物理参数。当前初始总量由来源 CreateItems 授予和 AddFromMaster 六槽追加组成，包含五种空件；不授予来源以外的备用物品。特殊装备效果和能力提供器仍显式阻塞。

字段装备取得只增加总所有权，未恢复穿戴效果的身份仍可保存，但不能进入换装选项。来源移除直接减总数，不会自动卸装；当前若请求会令总数低于全部 enabled 名册占用数，则整个事务明确阻塞，不把请求缩小为空闲数。真实来源库存检查目前准入 134/173 处指令，覆盖 462 组受控输入；新增 17 条装备取得/保存/战斗投影链中，6 条完成当前队伍可执行的实际换装。这些是隔离系统检查，不代表剧情可达性，详见 [剧情库存](inventory-events.md)。

## 快照边界

`owned-game-state` 版本 4 的快照包括内容目录摘要、名册及原生生命周期元数据、已释放职业、三组编队与 `selectedSlot`、物品、装备总量、Gil 和领奖记录。恢复先复制并验证全部数据，再替换当前值：错误版本/来源、未知成员、非法格数/选择/排位、同组重复成员、非法 enabled/职业/持有身份、非法数量、HP/死亡不一致、重复身份、缺少角色、额外字段、装备超额占用或资源上限与装备/成长不符均拒绝。不能通过快照注入攻击力或战斗执行器字段。v15 使用版本 2、v16 使用版本 3；旧版本不静默迁移，浏览器保留原保存数据。

这只是共享状态片段。它不含当前地图、剧情变量、事件任务、地图请求、会话种子或本场战斗，因此不能单独作为游戏存档。后续 `game-checkpoint-v1` 已在会话层组合稳定地图快照并接入浏览器保存/恢复，见 [检查点存档](checkpoint-saves.md)；本文下面保留共享状态首次交付的验证记录。
