# 共享角色、库存与奖励状态

2026-10-11。`GameState` 统一拥有角色、普通/重要物品、装备总持有数和六槽占用、Gil 与领奖记录。v15 在原有固定恢复道具上接入玩家复活、解除已支持状态、普通换装/动态属性与字段库存事务；见 [状态道具](item-status.md)、[装备](equipment.md)、[剧情库存](inventory-events.md)。快照升级为 `owned-game-state` 版本 2；内容 profile 仍为 `game-state-development-v1`，受限于当前开发初始化。下面保留首次 v13 来源研究和独立验证记录，不代表全游戏系统已完成。

## 所有权与交接

| 模块 | 拥有的数据与职责 |
| --- | --- |
| 内容编译 | 角色定义、物品身份与分类、独立菜单/战斗函数与准入、上限、显式开场初始值；保留来源表行 |
| `GameState` | 会话中的名册、当前队伍、进度与库存；返回副本，校验变更后整体发布 |
| `BattleGame` | 从当前队伍借入独立副本，拥有本场行动条、队列、敌人 AI、随机流与暂存结果 |
| `GameSession` | 协调战斗借用、失败重试、领奖和字段事件返回，不另存一份角色或 Gil |
| `WorldSession` / `FieldGame` | 地图及事件状态；通过库存事务端口写共享状态。候选地图初始化使用私有库存草稿，成功发布后重绑当前所有者 |
| 暂停菜单 | 投影角色与库存；战斗中显示本场 HP/MP 和库存，地图中显示已提交值；道具确认交由会话和状态模块校验 |

进入战斗时建立带实例身份的借用记录并冻结入场队伍和库存副本。战斗期间禁止外部修改共享库存或恢复快照；v14 在本场副本中预订和消费道具，胜利时校验消耗清单并与角色、Gil、领奖记录一起提交。失败重试使用相同入场状态和种子，恢复战前角色和库存。战斗构造失败会释放借用。稳定地图中的菜单道具也经同一 `GameState` 投影资源和数量后整体提交。

胜利结算有两道边界。首先，战斗内部在临时副本上为所有角色计算经验、成长和战斗结束状态，全部成功才公布胜利；修复了后续角色缺少成长记录时，前面角色已经升级、奖励却无法领取的问题。然后，`GameSession` 预检地图后继脚本与局部变量，再预检所有角色、Gil 和领奖记录，连续提交后才消费奖励。地图后继脚本排入下一正常模拟步，不在奖励提交中执行。缺失后继、非法局部变量或非法角色结果均不会先消费奖励。

领取记录按战斗发生次序编号，不用 encounter ID 去重，因此同一种编组再次出现仍可正常领奖。旧借用、重复提交、替换后的事务均被拒绝。命令与能力仍取编译定义；属性由显式基础/成长上下文和当前装备重算。等级成长从来源初始等级逐级累加原始增量，不能从已封顶的 maxHP 反推；战斗升级、菜单换装和读档校验共用该投影。完整成长输入、被动能力与学习仍待做。

## 来源与受限规则

静态研究读取同一版本的 `GameAssembly.dll`、元数据、符号和结构头，不执行原始 DLL。15 个导出方法的完整回执、原文件区间和反编译文本摘要已重新核验；原生语义验证字段仍为 `false`。主要定位：

- `NewGameWindowController.InitializeUserData 0x655220`、`UserDataManager.Initialize 0x8722b0`：原版分开初始化角色、物品、重要物品、仓库、魔石等所有权容器。Web 尚未恢复整个新游戏流程。
- `DataInitializeManager.CreateItems 0xaac310`、`OwnedItemClient.Initialize 0x7fa730`：先清空物品容器，再读取初始物品和 Gil；后续还有装备占位记录等分支。初始化选择器、角色创建与装备计数链尚未完整跟踪，不能把当前编译入口称作完整原版初始化。
- `CreateOwnedItem 0x7f8050`、`AddOwnedItem 0x7f7900/0x7f79a0`：内容类型有不同分支。本批只接入 `content.type_id=1` 的物品数量，不把武器、防具、魔法或魔石混作同类堆栈。
- `OwnedItemData.IsImportant 0x8df610`：物品行的 `type_id=2` 表示重要物品。内容 ID 与物品行 ID 分别保留，不因名称相似合并。
- `GetItemMaxCount 0x862bf0`、`GetGilMaxCount 0x862a70`：读取来源上限。`AddGil 0x7f7740` 的原始机器码确认持有 Gil 封顶，非负收入完整累加到 totalGil。

`initialize_data.csv` 的当前开场输入为角色 1/31/32、3000 Gil，以及 `INIT_ITEM_1` 的内容 58 × 1（对应 `item.csv:57`、重要物品）。六个装备槽来自各角色 `character_status.csv.content_id1…6`。这些输入用于已有开场检查点，不替代地图、剧情标记或能力解锁初始化。

来源上限为：单种物品 99、Gil 9,999,999、HP 9,999、MP 999、等级 99、经验 15,000,000。当前 totalGil 限于非负有符号 32 位整数，溢出明确拒绝；没有宣称模拟原版整数溢出。等级曲线和奖励资格仍沿用有标注的开发规则。

物品编译纳入 50 个内容身份，其中 13 个为重要物品。`changeItems` 提供整批授予/消费：授予封顶，消费先检查足量，任一条无效则整批不改。字段移除另走来源语义，允许耗尽已有数量；收入与收费也经同一事务所有者。v15 在固定 HP/MP 恢复之外接入复活与解除已支持状态；引用已解码不等于活动状态已支持。数量为零的记录保留；按内容 ID 排序只是当前确定性存储选择，不是原版排序结论。

装备总持有数包含已穿戴副本；空闲数量从全名册六槽占用导出。普通换装检查职业、槽位、角色限制、库存和效果依赖，在同一事务中处理另一手冲突并重算数值、元素和实际持武器手的物理参数。初始总量只汇总真实开场装备，不增加备用物品。特殊装备效果和能力提供器仍显式阻塞。

## 快照边界

`owned-game-state` 版本 2 的快照包括内容目录摘要、名册、队伍、物品、装备总量、Gil 和领奖记录。恢复先复制并验证全部数据，再替换当前值：错误版本/来源、未知成员、非法数量、HP/死亡不一致、重复身份、缺少角色、额外字段、装备超额占用或资源上限与装备/成长不符均拒绝。不能通过快照注入攻击力或战斗执行器字段。旧版本不静默迁移，浏览器保留原保存数据。

这只是共享状态片段。它不含当前地图、剧情变量、事件任务、地图请求、会话种子或本场战斗，因此不能单独作为游戏存档。后续 `game-checkpoint-v1` 已在会话层组合稳定地图快照并接入浏览器保存/恢复，见 [检查点存档](checkpoint-saves.md)；本文下面保留共享状态首次交付的验证记录。
