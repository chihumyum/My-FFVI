# 系统集成 v36

本批把来源粒子拆成可组合的启动与调度、出生、运动、几何与 RT 提供器，并按明确文件所有权并行开发。模块使用相同的 UnityPlayer、资源来源身份和随机状态契约，没有加入地图名或具体效果名的运行时分支。Web 迁移保持优先，HD-2D 仍未开始。

公开可玩内容 profile 保持 `narshe-playability-v35`。这些新提供器尚未接成完整的共享粒子宿主，不能用版本递增或独立模块测试把五个来源发射器标为可执行。检查点版本仍为 owned v8、field/world v9、session v4。

## 模块与所有权

| 提供器 | 本批实现 | 显式输入与后续边界 |
| --- | --- | --- |
| 生命周期 | 停止态启动的三次种子重置、预热起点、固定/普通步长、追赶、容量对齐、逐粒子出生时间 | 同一个 manager 随机流；来源帧时间取得和完整粒子数组提交仍由宿主负责 |
| 出生 | Initial、Cone、起始速度，SIMD 填充 lane 的随机消耗与 Color32 | 已接受数量、出生时间、单位 simulation scale；只返回局部坐标 |
| 运动 | 来源 Noise、慢曲线速度、重力、角速度、年龄/位置/旋转积分 | Physics3D 重力、逆发射器变换、系统 seed/Noise scroll；死亡与数组排列由拥有者处理 |
| 几何与 RT | 原生 billboard 顶点、尺寸钳位、UV/Color32 顺序、Gamma RGBA8 无深度 RT | 最终颜色/大小、实际父变换、显式 GPU view-projection；完整来源投影宿主仍有门禁 |

生命周期先生成有序切片；每片先更新已有粒子，再接受新生。出生内核消费 Initial/Shape 独立随机流，motion 不把世界变换重复用于局部位置。Noise scroll 由系统拥有者每次更新一次，只在相应更新阶段存在粒子时推进，不能在每个粒子的计算里再次推进。

预热的 `Play(true)` 会经过 `Simulate(restart)` 和嵌套 `Play(false)`，因此自动种子模式消费三次 manager 抽样。出生 timing 的 SIMD 下限为 float32 `1e-6`；burst 在 mask 为零后也保留这个下限。通过隔离执行发现的这些规则已进入共用实现，不能用一次 seed reset 或固定 `dt/2` 替代。

粒子实体的 prefab 根为单位变换，实例分配后按共享 player 的位置放入 effectRoot，不能使用显示板的地图坐标代替。实际 effectRoot 世界变换和 GPU 投影必须由宿主提供。来源 Gamma 配置把请求的 sRGB RT 选择为 `GraphicsFormat 8` 的 UNorm；不能仅凭请求标志再做一次线性/sRGB 转换，也不能给零 depthBits 的粒子 RT 虚构深度附件。

具体接口、来源位置和独立验证分别见 [生命周期](field-particle-lifecycle.md)、[出生](field-particle-birth.md)、[运动](field-particle-motion.md) 和 [渲染](field-particle-rendering.md)。原生字节、PDB、反编译、指令探针和真实资源导出继续保存在本地忽略目录。

## 接续与验收

下一步由单一宿主拥有完整粒子数组、manager 随机流和每个效果的模拟状态，将已有粒子的更新、来源死亡/压缩顺序、出生、最终颜色/大小及渲染接入 v35 的共享效果候选事务。失败和过期候选不能发布半步粒子、半份随机流或部分切图结果。运动发射器补偿、未恢复的投影输入、缓存/重启与稳定保存各自保留门禁。

这批未改变公开可玩内容，没有重写用户浏览器存档。来源新游戏的 609→3 仍等待完整效果提供器；既有开发片段与完整序章、全游戏迁移分别计验收。所有原 DLL 隔离结果都与 Windows 游戏进程、实际 GPU/浏览器帧及全流程对照分开报告。
