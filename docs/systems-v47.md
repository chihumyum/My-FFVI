# v47 事件保存与续行

本批继续搭建游戏骨架：显式 Web 事件可以请求保存，刷新后从保存指令之后继续，再进入既有战斗、领奖、切图和菜单流程。保存仍由同一个 GameSession 拥有；页面没有第二份剧情状态，也不自行序列化任务。

## 共用协议

`event-save` 是明确编写的 Web 内容指令，当前编译器不会把原版 `AutoSave` 翻译成它。到达该指令时，FieldGame 消费当前指令、验证主任务及所依赖的状态均可编码，再发布稳定的请求身份。等待、编码失败或取消期间，字段与会话都丢弃经过的时间，后续指令不执行。

`GameSession.prepareEventSave` 返回私有候选：检查点表示保存已经确认、下一逻辑帧尚未执行的状态。`GameEventSaveCoordinator` 取得 Flow 保存票据，异步编码后再次验证同一会话、字段、请求及完整状态；随后同步执行一次存储提交和 ACK。ACK 不运行 VM、不发放奖励、不调用事件结束处理。下一次正常 10 ms 时钟才继续。

编码、配额或槽内容冲突失败都保留同一个请求，显式重试重新准备。返回标题、换会话或取消使晚到结果失去写入权限。写盘成功后发生的 ACK/界面错误属于致命错误，不能再旋转存档槽或重试已写入的请求。页面自动处理请求，失败显示重试和返回标题；取消没有跳过保存指令的含义。

## 持久化与恢复

| 范围 | 格式与恢复方式 |
| --- | --- |
| 外层与共享状态 | 继续使用 game v4、owned v10、web-game-save v1；来源 origin、内容摘要、奖励/库存仍属于原所有者 |
| 旧空闲存档 | `idle-world-v10` / `idle-field-v10` 继续可读，手动保存仍使用原格式 |
| 事件存档 | `event-world-v1` / `event-field-v1`，另带 `field-event-continuation-v1` |
| 主任务 | 保存 PC、Call 栈、范围、演员别名、root；地址逐个绑定可信程序，而非保存可执行指令 |
| ChangeScript | 保存单层返回位置与局部变量帧；区分与当前银行共享引用、独立银行，恢复后继续保持别名关系 |
| 地图与演员 | 保存入口是否已开始/同步完成、活动生命周期和相机事件状态；演员从既有 codec 恢复，脚本上下文来自可信包 |

恢复不执行保存指令、开始脚本、工厂/NPC 初始化或先前奖励。`lastClock` 重建为保存时间，保证正常下一帧续行。来源 origin 的事件存档同样不需要旧纳尔谢开发包。浏览器准备依赖和媒体后发布候选，先显示暂停菜单，玩家继续后才推进。

该协议只接受可编码的单个主任务停点。未完成并行 puppet/宝箱任务、运动/插值、消息/选项/商店窗口、活动渐变、粒子/RNG 历史、待处理切图和战斗仍明确拒绝。已结束的子任务可丢弃；它们产生的演员/游戏状态由各自 codec 保存。不能把这一能力描述为任意时刻存档。

事件保存与手动保存共用 current/previous 槽，仍按 source/framework profile 隔离。一次 `setItem` 更新两份记录；写入前比较槽原始字节。这不是跨标签页原子锁，也没有模拟浏览器进程崩溃后的磁盘持久性。

## 来源边界与下一步

来源全库 3304 脚本中有 95 处 AutoSave；字段范围为 94 处、94 脚本、58 地图。原 DLL 的现有证据显示它不等待保存成功 ACK，原版读回入口尚未证明。因此 Web 保存协议不能作为 strict AutoSave 的来源准入依据，详见 [来源说明](event-save-source.md)。这轮没有继续扩展原生反汇编，也没有生产 HD-2D 内容。

下一步给具体内容批次建立依赖闭合与准入：明确所需事件、地图、战斗、角色状态及媒体能力，先验证完整连续路径，再批量导入依赖已满足的内容。未满足能力作为系统任务集中补齐，不能靠逐地图改坐标、跳过指令或伪造状态增加“可玩数量”。系统回归通过不代表完整 FFVI 主线已迁移；来源开场的现有演出边界保持单独记录。
