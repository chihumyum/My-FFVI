# 世界知识与语义资源

## 知识是工程输入

Agent 需要理解一个对象属于什么地方、在哪个剧情条件下存在、是否是另一个对象的后续状态。知识库的首要用途是约束资源选择与研究，防止外观相似导致错误复用。它不依靠聊天上下文积累隐含设定。

## 模型

- 地点身份：区域、地点、内部空间与世界地图位置；显示名和翻译是别名。
- 表示关系：地点关联具体源地图、场景、资源包；多个表示不自动合并。
- 状态维度：世界阶段、全局剧情标记、地点局部状态、任务和角色状态。不要用单个线性章节数字覆盖所有维度。
- 事实：subject/predicate/value、适用条件、证据 ID、状态、修订。状态为 observed、verified、hypothesis、contradicted。静态 observed 只支持对应的静态事实。
- 资源：物理身份、用途、地区/文化/环境适用范围、世界与剧情条件、派生链、尺寸和装配接口、版本、风格规范版本。
- 变更：事件对世界状态的影响、旧新表示关系。迁移解释与用户创作的修改采用不同 profile。

条件采用明确的 all-of 等值约束作为首版子集。遗漏状态值返回 unknown；只有显式相等或不等才能得到 true/false。后续添加比较、集合和逻辑组合时扩展版本并新增语义测试，不把自由文本当代码。

## 事实和来源

本地导入已支持 `map.csv.area_id → area.csv.area_name → system_en/system_zhc` 的关联。它可以证明一组地图属于源数据标注的纳尔谢或歌剧院，不能证明 Map_20010 在哪个世界阶段启用。后者需要事件选择逻辑和原版观测。

开场纳尔谢、之后重访、世界变化后的状态应共享地点身份，同时具有各自的 SceneVariant 与条件。具体标记及范围保持待证。歌剧舞台、后台与观众区也不能仅按纹理相似合并。

研究事实至少包含来源指纹与定位；原版运行事实还需存档/输入/环境和检查点。不同源版本的证据不能隐式拼接。相互矛盾的有效事实返回冲突而非按更新时间覆盖。撤销或取代关系要显式记录。

## Agent 上下文包

`npm run knowledge -- narshe` 生成稳定排序的上下文，包括地区及地图绑定、已知事实、未知状态、当前未完成的研究任务。可通过 `--state '<JSON 上下文>'` 提供已知条件；无状态查询保留适用性未知的条件化事实，不能挑选一个默认变体。

当前可执行子集包含区域、单值事实、等值条件与资源匹配。地点包含、相邻、历史转变等多值关系仍需独立关系 schema 和查询扩展；不要把多值关系硬塞入当前单值事实冲突检查器。

工作流为：读取 dossier → 查询上下文 → 提出有证据的局部问题 → 研究/观察 → 登记事实或未知项 → 验证冲突与依赖 → 更新生成摘要。每次结束记录已完成证据和下一问题，避免 Agent 重复猜测同一事实。

## 资产解析

匹配先限定语义身份/用途、区域与世界状态、规范版本与装配接口，再考虑复用策略。候选状态为 eligible、ineligible、unknown；多个 eligible 必须报告 ambiguous，不能选择第一条。未知候选可能改变结果时同样阻塞。无适用资产才提出变体、派生或新建任务，不能自动生成后直接发布。

生成图像、相似度与命名检索只能提出候选。相同纹理可以被多个地点共享，地点唯一建筑也可以使用相同材质。物理文件去重与世界语义身份保持不同层级。

## 当前知识缺口

- 开场、重访与后续世界状态对应的实际源 flags 和地图选择规则。
- 纳尔谢 20 个主城地图记录之间的内外空间和剧情适用关系。
- 歌剧 15 个地图记录与三个演出包的事件触发、时间线选择关系。
- `Wait`、`SysCall`、角色控制任务的真实语义。
- 原版捕获环境和独立对照样例。

这些缺口直接进入目标验收报告；地图标签已识别不关闭这些问题。
