# v84 共用敌队目录与遇敌接入合同

本轮继续以六组游戏骨架为边界，不恢复单个 NPC、镜头或粒子。现有探索、战斗、返场、持有菜单和保存 owner 保持原样；新增工作在整批内容生产、完整敌队依赖与跨系统事务接线。

## 一个敌队生产器

[source-battle-directory.mjs](../scripts/source-battle-directory.mjs) 从同一候选的全部来源地图、保留的 map/monster_set 原行和原始 Encount 收集请求，再复用现有来源描述、AI、技能、状态、参与者、掉落和战斗编译器。重复引用保留各自来源位置；额外参数、动态或无地图绑定的指令保留原参数与未知项。typed party 与原始 primary 不一致时保留原始候选，不授予错误 typed ID。

目录固定进入公共内容管线，与其它包一次发布。strict 与 framework 是两个独立正文；没有从原版目录偷取临时规则。完整请求、每队诊断和编译失败记录一并保留，不因某队失败放弃其它目录记录，也不把条件性定义称为可执行。

本次来源发现333个敌队，保留历史目录的另外两个请求后合计335。显式 Web 版产出143个定义，其中22个依赖就绪、121个条件性，另192个阻塞；严格来源版仍全部阻塞。描述阶段的六个失败是现有编译器逐队遇到的首个失败，其余依赖未被穷尽，不将该目录当作完整原生机制缺口清单。

[共享开发声明](../content-batches/source-battle-directory.policy.json) 明确使用普通阵型、保留字段音频、暂缓 battle intro，以及绑定完整来源摘要的共用8010脚本与11旗标组执行省略。AI、能力、条件、奖励和角色提供器没有因此获得新权限。完整来源脚本、旗标行及严格诊断仍在目录报告；此声明服务于 Web 系统变体，不证明原版战斗行为。

源初始化、库存、名册、装备、魔石及其它持有目录保持 canonical 相等，共用战斗规则保持原样；敌队与掉落内容按原编译器扩充。新生产器不新增 GameState、位置 owner、时钟或随机流。

## 遇敌与地图合同

[source-walk-policy.ts](../src/compiler/source-walk-policy.ts) 将完整来源 set 绑定到显式 Web 步数、交通身份与率值权重声明。原 required_steps/subtract_steps 不转换或猜单位；零率正 ID 仍须闭合依赖，重复率值只在该 Web 权重声明内合并。未知 area-grid、额外槽位、坏值或任一敌队缺失/条件性均不能取得运行策略。

`initialized-source-map-recipe-v2` 可声明这些设置，消费本次候选的共同敌队目录。绑定包含来源元数据、战斗目录和派生策略摘要；批次规划及已发布内容检查重新推导。原 map/set、事件、实体、碰撞与出口不改，原版调度未实现诊断继续保留。v1 配方和默认训练场没有自动开启遇敌或更换初始队伍。

来源321的完整382/383/384池通过敌队依赖检查，但原地图进入仍受 minimap/particle 提供器阻塞。实际私有候选通过数据编译后在 Field 准备处拒绝。没有删除实体、过滤敌队或为这个地点扩大视觉研究；静态目录、骨架连续流程和原地图可玩性分别记录。

地图候选准备前、提交前和恢复时都通过已有 WalkEncounterState 的只读 query 核验策略。已访问地图变更或删除策略不得先发表；未访问地图的核验不安装计数器、不抽随机数。原单流、逐图倒计时、入战票据、一次奖励及同字段返场继续复用，存档格式不变。

## 构建与验收

共同发布前的输入锁增加实际 battle 编译消费的 import 快照及两份已有魔石编译证据，核字节与实际路径。候选完成后的改动或相同字节换 symlink 均拒绝发布；没有新增原生研究，也不把快照锁解释为所有原 Unity 文件已现场复核。

`npm run check` 本轮3265项及 registry 检查通过，Python43+16项通过。实际候选一次发布九个入口包及共同敌队目录，3899个目录地图引用、完整 JSON/媒体归档和发布前输入复核通过。七个骨架检查器的112个连续用例、两批来源声明路线的五项检查、内容版本会话的14项回归全部通过；两批完整计划仍保留13/19条诊断，没有取得全批准入。
