# 全量剧情批量迁移

2026-10-14：用户要求一次处理全部原始剧情，先验证批量方法，再以独立 goal 完成全部剧情和 Web 游戏迁移。完整 Web 迁移仍未完成；HD-2D 后置。系统骨架里程碑不重新打开。

本次把处理对象固定为整个来源语料和全部来源地图，不按开场的下一条未知指令推进。来源脚本直接转换并由共用运行时执行；原始正文、分支、地址、Segments、局部变量和来源身份保留。新工具没有另一套事件 VM 或游戏状态所有者。

## 一次全量转换

`npm run story:build` 用现有 `loadCorpus` 的完整快照和同源 `system_zhc`，调用纯 `compileStoryCorpus`，一次生产 `build/story-corpus/corpus.json`。序列化后重新验摘要、完整源输入、系统文案和运行时，最后原子替换这个私有产物。原始游戏文本和转换结果留在 ignored `build/`。

每份脚本包括全部原始字段和每条指令的原始地址/操作数。字段程序复用 `decodeFieldOp` 逐条转换；中间的未知指令保留为同址显式停止，后续地址不移动。战斗/AI及未绑定程序保留原文，不套用字段语义。现有引用分析的全部 resolved/unresolved 边保留；能力缺口按确切指令家族（包括 SysCall 选择器）、诊断代码和原因归并，同时保留每个原使用点。

这是无损检查和转换产物。`operandDecoded` 只证明操作数被接受；运行时宿主、剧情可达性和完整迁移仍分别未评估。不能把全部指令已入库解释为全部剧情可玩。

## 直接消费统一产物

`npm run story:execute` 对全量源程序与统一产物逐份核对原文、来源、指令地址和摘要。实验选择一整类能在独立宿主执行的完整字段程序：普通对白、选择、控制流、等待、变量和旗标。选择在执行前完成；所有未入选程序和完整排除原因保留，不按失败结果过滤清单。

执行直接使用产物中的 typed instructions 和局部银行，不重新转换脚本。执行器是原有 `FieldGame` / `EventState`；工具仅提供输入并记录分离的观测。受控零初值、单变量条件边界及有界选择前沿用于验证机制与重放，不冒认为真实剧情存档。每个用例重复执行并比较对白、选择、状态变化和终态；停止、未知和预算不足均单独记录。

## 全世界共用缺口工作单

`npm run story:plan` 读取现有可信来源包，逐图校验全部649个来源地图及其引用，以全部 map-local 脚本和 PointIn 为根，计算完整依赖。几何失败、演员、战斗、提供器和脚本未知都保留。工作单按确切 capability 或诊断代码/原因归并，保留所有原始定位；动态依赖及故事时期不猜测。

下一轮实现单位由这个全量工作单选取：一类共用语义或宿主完成后重编整批依赖程序，整体回放。静态使用点数量帮助观察影响，不替代完整生命周期执行或主线可达性。解析未归类项不单独变成逐场景任务。

## 剧情区段的连续验证

`story-route-contract-v1` 是对既有检查点的只读断言，固定来源、可信内容引用、运行时及包摘要，核对入口/出口地图、精确剧情或宝箱银行引用、名册、编队、Gil、物品及装备库存。变化合同核对经济增量和新增结算记录，旧结算必须保持原前缀且序号唯一。缺失状态保持 unknown。

`runContentBatchRoute` 的显式 continuation 读取前段真实产生的检查点，经既有 `GameContentRepository.restoreSessionContent`、`GameEntryLoader`、`GameSession.restore` 继续。它不执行初始化或修改状态，核对当前地图、初始包、世界与战斗正文的可信绑定。恢复的路线有独立 `story-checkpoint-continuation` 证据 lane，不能混入普通新游戏路线准入。输入前首个稳定检查点用于核对完整入口状态。

`npm run story:continuity` 在完整南费加罗八图/十二宝箱原内容路线验证该方法：第一段预先按来源奖励定义声明出口；第二段从第一段实际写出的检查点文件恢复，重跑整段并要求所有奖励增量为零。另核对错误旗标、断链和改写的检查点被拒绝。第一段仍是明确的 Web 开发放置，方法验证不会授予原主线已到达该地。

## v94 实际方法实验

全量转换保留3,304份原始程序及186,003条指令。2,804份字段程序中166,442条指令操作数被接受、6,584条明确阻塞；另500份非字段程序的12,977条指令保持原文未评估。433个精确操作数/局部变量缺口组、33,939条已解析引用及17条未解析引用全部留证。带源输入和序列化复核的一次构建约27秒，统一产物摘要在重复构建中相同。

直接消费统一产物的成组实验选择265份完整字段程序，507个有界用例中504个结束、3个选择前沿用于扩展后继输入；没有执行停止、异常或预算耗尽。29份程序出现状态变化、3份实际回答选择。其余3,039份程序及其排除原因仍在报告内；这不是265份主线剧情区段的可达性验收。

完整来源世界的静态扫描覆盖649图、8,733个地图内脚本键和1,535个PointIn，形成10,268个根。约37秒保留105,934条边、23,665条诊断、41,449条宿主需求和35,153份评估，并精确归并为648个诊断组及26个需求组。地图内脚本键和指令包含公共程序的多地图使用点，不能与3,304份唯一程序数量相加。没有提供真实宿主观察的评估均为conditional；它们不是35,153项已证实缺失功能。

真实两段续行使用原八图路线、12个普通宝箱、累计1,246条玩家输入和30次存读档。入口/出口合同核对原始旗标、名册和队伍，以及按来源奖励预先计算的Gil/物品/装备增量；完整库存集合另独立比较，防止新增未声明ID。前段实际检查点经文件原字节交给后段，后段重跑整段不再次发奖。错误出口、改写检查点、断链和额外库存均拒绝。

完整内核3,531项测试与六组骨架的七个检查器/112个连续用例通过。以上均为方法及现有声明范围的执行证据；公共游戏包未在本实验中重新发布，完整原剧情、浏览器实玩及原版一致性仍未放行。最终摘要留在 `build/reports/v94-validation-summary.json`。
