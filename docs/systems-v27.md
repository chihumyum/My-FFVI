# 系统集成 v27

本批继续补齐共用状态和新游戏入口依赖。空装备所有权、新游戏共享状态与来源标题上下文并行推进，再统一接入字段、跨图和存档。纳尔谢用于系统回归；完整新游戏尚未发布，HD-2D 仍后置。

## 已接入的系统

- **空装备所有权。** 空手、空盾、空防具和空饰品的真实 Count 统一进入 `equipmentStock`。来源先各发五件，初始三人的六槽追加使空饰品成为十一件。默认空位查询当前持有数量和槽资格，换装只改登记、不消耗 Count；新 owner 包含全部六槽，已有角色重新加入与离队只增减非空件。修正真实盾牌与另一手空盾的冲突规则。见 [空装备](empty-equipment.md)。
- **新游戏共享状态。** `GameState.createNewGame` 校验同源模板、参数、装备、库存、队伍和上限，生成没有开发检查点魔导状态的 owner。开发入口和恢复保留各自语义；读取零数量存档不会重新发放初始种子。新游戏仓库、交通与计数器等尚未由会话承载的状态仍保存在候选中，不能据此发布完整游戏。见 [新游戏](new-game.md)。
- **标题待机演示上下文。** 两种来源 SysCall 接入共用字段 VM。探测到开场演示 fader 才写局部变量 7 为 1；不存在时保留原值，未知时阻塞。返回标题保留淡出、状态切换、停止输入的顺序和 End，需要真实副作用宿主。跨图候选只能读取上下文，发布前禁止产生标题副作用；过期上下文拒绝提交。稳定保存拒绝活跃演示，恢复与可信宿主比较且不重放命令。见 [来源表现](source-presentation.md)。

装备菜单、商店和战斗物品资格过滤空件；宝箱容量查询仍读取真实普通持有列表。原始获取次序缺失造成的默认空件并列、null 装备槽、双持与任意字段空件发放仍明确受限。
