# v60：共享游戏目录与入口分离

本批落实“先系统骨架、后批量内容”：角色、能力、装备、成长、库存和战斗依赖由公共编译器提供，真正新游戏和纳尔谢开发检查点分别组装入口。公共构建不再要求后来剧情的魔导检查点成功，也不从检查点反推新游戏状态。精细表现和 HD-2D 继续后置。

## 系统边界

`compileSharedBattleSource → compileGameCatalogModules → assembleGameCatalog` 建立共用来源与能力目录。初始持有人由 `createNewGame(sourceNewGame)` 推导；所有角色模板仍表示潜在能力，不自动授予队员、物品或技能。`compileOpeningBattle / compileOpeningPlayable` 保留独立开发入口，显式注入其检查点与省略策略。

`npm run catalog:build` 先发布独立来源数据，再发布严格来源目录；`npm run new-game:build` 依赖它和世界编译，随后绑定来源入口。真正新游戏与来源存档读取 `/game/source-catalog.json`；开发入口仍读取 `/game/battle.json`。内容仓库和直接 `GameSession` 调用执行同一准入，不能绕过仓库将开发种子传给新游戏。

来源目录禁止 `initialOwnedConditions`，即使它为空；初始成员身份、等级、经验、当前 HP/MP 和条件必须与初始化计划一致。正式初始 owner 仍是 source 1/31/32，条件为空；后续来源事件合法取得的条件可保存和恢复。不会在读档时重新初始化或清除实际持有状态。

来源入口、世界目录、初始地图与读档目的地图必须采用一致 profile。直接 API 与仓库保持同一边界：严格来源不能夹带开发地图或步行遇敌策略；framework 必须在各层明确声明相同规则，各文件仍拥有独立来源摘要。不能通过正确重算内容摘要绕过规则归属。

来源会话构造时捕获世界目录摘要和 profile，首次切图就检查该绑定，不等到第一次地图提交后才固定目录。候选准备与读档重建之前检查实际地图规则；初始位置尚未切图的恢复也保留目录绑定。旧独立开发入口继续按其原合同选择第一个世界目录。

## 准入与兼容范围

严格来源目录拒绝开发编队、逃跑规则、生命周期省略和省略诊断。请求、依赖和来源定位完整保留，未准入的遭遇定义不发布。当前六个战斗请求全部明确阻塞，严格目录可执行遭遇数为零；这是已有依赖缺口的明确报告，不是六场战斗已迁移。

显式 framework profile 可使用声明的开发规则，仍必须拥有真正来源初态。旧纳尔谢开发产物的完整内容和摘要保持不变，旧开发存档的身份绑定保持有效。以前以检查点目录绑定的 source-origin 存档不符合新来源目录，明确拒绝；本批没有跨内容摘要迁移或自动重标身份。

`BattleCatalog` 的既有格式名和 profile 字面量保留，避免无关格式改动；它们不代表公共编译仍依赖纳尔谢。状态继续由原 `GameState / WorldSession / BattleGame` 持有，由 `GameSession` 协调，没有第二套游戏状态或新增场景分支。

## 验证边界

新增机制检查直接调用公共生产编译链。在临时导出快照中移除或改变后续检查点证明，共享目录仍可构建，旧检查点入口正确拒绝；原始来源包未修改。旧开发目录以完整 canonical 内容和文件摘要回归。

真实新游戏初始化与同一会话的持有事务验证初态、准备、提交及重复提交拒绝。另一个缺少原生上下文的合成字段脚本正确拒绝，状态不发表；提供器存在不等于指令依赖完整。这两条证据分别记录，不冒充来源剧情执行。

验证入口为 `npm run check`、Python 适配器测试、`npm run catalog:check`、`npm run source-new-game:check` 和 `npm run framework:verify`。本批验收结果与产物摘要保存在 ignored `build/reports/v60-validation-summary.json`。受控系统和 DOM 检查不授予浏览器实玩、原版动态一致性或完整游戏验收；批量内容放行仍须单独检查。

最终回归为 2,516 项 TypeScript 测试、39+16 项 Python 测试和 34 组系统集成检查通过；共享目录机制检查通过 9 阶段，来源新游戏及两条真实来源演员事务检查通过。旧开发入口两份文件的内容摘要和完整字节摘要与拆分前相同。来源路线仍未完成，批量内容未获放行，严格来源的六个战斗请求继续阻塞。

接下来实现入战准备、战斗发布和返场的公共阶段合同，复用会话、battle lease、Flow 票据与音频所有者。失败、取消、过期和重试必须保留请求及一次结算边界。不得因来源路线的下一个镜头或粒子边界重新展开细节研究。
