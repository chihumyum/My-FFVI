# v81 系统骨架与批量内容依赖

本轮继续以同一游戏会话、状态 owner 和连续系统流程为主干。三个并行模块分别负责来源候选编译、当前内容版本上下文、共享队伍查询；集成线负责统一管线及跨模块验收。没有开启 HD-2D 或新的镜头、NPC 原生控制器调查。

## 公共系统改动

`skeleton:build` 现在从已提取的完整来源快照编译来源世界和新游戏入口，再派生 framework 与声明的内容包。来源与 framework 的全部 indexed maps 都位于同一公共候选集合。已验证战斗目录明确复用，原始 Unity 提取和全部战斗目录重建仍是独立步骤。

配方原文件不变；编译先核对原绑定，再将本次合法候选绑定写入审计报告。来源、媒体、地图物理身份、入口初始化和声明的开发策略不能因此改变。省略记录只有已验证的原地图依赖摘要可以随新编译更新，其对象、规则、数量和顺序保持相同。各生产器读取本次私有候选，不回退旧磁盘缓存。全体闭包、媒体、输入锁和 CAS 检查完成后一次发布。公开来源地点包也走这条主管线。

新游戏、来源标题启动和当前读档先选择可信内容版本，再私有准备原有 GameSession。后续切图、图像和音频继续读取该版本的不可变对象。当前包更新不会给运行中的游戏切换资源；版本或对象缺失明确失败。legacy 无包入口保持原合同。

成员数量查询使用现有 VM 和持有队伍状态，不增加缓存名册或存档字段。原来源的当前四位置计数与启用名册计数分别实现，保留 label 后一条指令的跳转语义。统一编译器与依赖分析使用相同指令；未知队长和自主 NPC 生命周期仍保持独立能力缺口。

## 验收范围

新鲜结果保存在 ignored `build/reports/v81-validation-summary.json`。日常骨架门禁仍是六组、七个代表性完整流程；没有为每条来源指令扩大前置清单。第一轮实际候选在派生依赖检查处失败，原 44 个公共文件保持原字节；该失败和随后的修复收据均保留。

最终源码检查 3208/3208、Python 43/43 与原生绑定测试 16/16 通过。六组骨架的 112 个受控案例、来源往返 8 个、版本续行 14 个、音频版本 6 个及 HTTP 5 项检查通过。公共管线完成 8 个包的一次发布：完整两类 649 地图进入同一候选集合，111 个来源地图的编译正文更新，来源目录的原导出与旧 world 别名保持原字节。24 个来源队伍查询全部进入共用解码器；这些数字是编译及合同证据。

声明的来源路线完成；全来源批次仍保留 13 条依赖诊断，完整准入按预期阻塞。旧存档缺少世界身份而同时匹配多个版本时，既有歧义拒绝规则保持；没有隐式选择最新版。

完整来源剧情、浏览器实玩、原版运行和全游戏迁移分别验收。地图编译及归档数量不等于可玩剧情覆盖。完整 Web 迁移 goal 继续 active；下一工作单位仍是共享系统合同及声明内容批次。
