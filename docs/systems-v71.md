# v71 字段魔法系统

本批继续系统优先，补齐地图暂停菜单中的持有能力、目标选择、费用、恢复结果、角色外观与保存合同。字段施法和战斗执行分别编译；能在战斗中执行不自动意味着能在地图使用。

## 数据与所有权

`FieldAbilityCatalog` 读取完整来源 master，保留菜单函数组、实际消费者使用的 `RengeId`、三槽函数、过程参数、禁用状态和内容旗标。缺失或歧义的内容身份保留 `null`，未知完整行为保留阻塞。来源模板不授予能力；资格只查询当前活动队伍中实际持有的角色、已学能力和指令。

`GameState` 仍持有角色资源、能力熟练度、装备和成长。新字段能力模块只投影资格、目标和全部效果；`GameSession` 负责地图上下文、必要的角色外观准备与共同提交。`GameCommands` 将界面和内容批次的 `use-ability` 输入交给原会话，不重新选择状态所有者。

菜单施法使用当前字段排除提供器，与原版的 `CurrentlyInvalidContentIds` 域相同；未知值不默认为空。单体与全队选择按字段范围建立，不借用战斗中的敌方、反射或阵型目标。

## 施法与事务

持有能力的源菜单函数独立执行。普通恢复按菜单调用链恢复的算术和群体规则计算；解除状态和复活按函数顺序处理。Cure 的 Unique23 槽保留为已证明的 `None` 结果，其他 Unique 过程不按此放行。

所有目标以施法前的参数投影，效果完成后对实际施法者扣一次 MP。装备的减半或固定一 MP 费用复用已有提供器。无效目标、费用不足、无效果、失效会话和未完成内容都不能通过菜单取得技能或消耗资源。

字段恢复具有随机浮动。Web 使用明确的 `web-field-random-v1` 流；来源算术与 Unity 随机数逐位一致性分别记录。随机流由同一个 `GameState` 持有，读取菜单不抽样；施法准备只推进私人候选。角色、费用、条件及随机状态在全部验证后一次发布，失败或取消不推进原流。

条件改变时复用现有字段角色外观准备，确认原字段、持久版本、实际排除上下文与 Flow 资格仍有效后提交；旧按钮不重定向到读档后或替换后的会话。

共同发布原先在 owned 写入后再次校验演员，存在后一次外观拒绝而资源已提交的缺陷。本批将编队和施法接到同一同步提交边界：锁定持久写入，演员完成最后一次可失败读取，重新确认会话和宿主，随后发布已准备的演员与 owned 数据。真实外观提供器失败、晚到的标题/读档切换、媒体就绪撤销和重入都保留旧资源及随机状态。

## 保存与内容发布

带字段能力合同的内容使用 owned v13，并明确保存字段随机状态；缺失随机状态的存档不从入口种子补齐。没有该合同的旧内容继续使用 owned v12，不能凭新运行时获得施法。历史内容与新内容按自己的目录摘要和状态版本验证。外层 game-checkpoint v5 继续承载已版本化的 owned 状态。

原始文件、地图几何和作者路线不需要因施法接口改变。字段能力进入共同目录后，相关 battle/catalog 与入口引用必须重新构建、计算摘要并发布；旧摘要不自动替换。

## 验证与后续

系统演示使用真实持有的蒂娜 Cure，通过实际敌人造成的伤势施放，再保存、恢复和重新绑定命令。合成测试独立覆盖准备后的失效、重复提交、无效输入、菜单只读、费用与随机序列的恢复。受控 DOM、来源数据执行、浏览器实玩和原版对照分别留证。

最终 `npm run check` 通过 2,836/2,836，Python 工具 43/43、原生绑定 16/16；统一框架通过 46 组受控合同，另记录一组未完成的来源路线。真实来源持有状态与作者演示包的连续流程通过 14 项，字段施法 UI 10 项、编队 UI 16 项、真实演员共同发布回归 6 项均通过。运行时摘要为 `af2ae731e16c8a72b06d1fcdfae01fc5102ce2fc234a8febc07035ed7ee62537`，回执在忽略的 `build/reports/v71-validation-summary.json`。没有新增浏览器实玩、原版动态对照或来源剧情放行。

完整来源 1,530 条能力中 35 条声明非零菜单函数组，16 条生成本范围计划，19 条菜单行为保持阻塞；这些数字不是可玩技能或剧情取得覆盖。目录及入口重新构建，三个作者清单按实际生产摘要更新固定引用。22 个已发布 JSON 中 18 个摘要变化，原来源/框架/Figaro world 与旧开发字段入口四个文件字节不变；作者地图因配方中的 battle 引用变化重新封装，几何和路线规则未修改。

魔石本批已进一步恢复召唤映射、成长奖励字典、学习累计和底层装备消费者。它的取得、唯一装备、能力资格、胜利学习、成长与保存必须作为下一套完整系统接入；召唤特殊效果和 disabled 角色的原生转移范围仍保留缺口。现有商店还需接通批次声明交易与连续经济流程，执行次序见 [系统推进计划](systems-roadmap.md)。全游戏迁移未完成，HD-2D 继续后置。
