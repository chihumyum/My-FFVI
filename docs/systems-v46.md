# v46 独立游戏入口与恢复依赖

本批继续交付共用游戏骨架。标题、新游戏、开发片段和存档恢复各自取得所需内容，准备成功后发布一个会话；不以继续追赶开场演出指令作为本批目标。

## 入口与所有权

`GameFlow` 可以从无会话的标题开始。标题只拥有输入与载入状态，不下载游戏包，也不创建旧纳尔谢状态充当占位。`currentSession` 可为空；需要已开始游戏的代码继续使用明确的 `session` 所有者。无会话时保存和切图请求被拒绝，新游戏与读档可以准备第一位所有者。

所有入口遵循同一流程：取得匹配的内容闭包 → 构造私有候选 → 准备图片与音频 → 验证操作票据 → 发布 → 绑定界面。异步准备期间旧会话冻结；取消或准备失败保留原会话与存档。迟到结果不能替换会话、关闭较新的载入提示或解锁其按钮。发布后界面绑定错误属于致命错误，不重试已提交的入口。

来源新游戏仍经过实际标题渐变和 `NewGameFieldEntry` 的启动协议，不绕过来源初始化。渐变及启动准备中的错误回到可重试入口。三个 Renderer 在发布前准备，战斗和库存界面在发布后绑定该会话的战斗/道具目录，不再沿用页面最初下载的全局目录。页面提供明确的取消载入操作。

## 内容与媒体

| 入口 | 可信依赖 |
| --- | --- |
| 标题 | 页面和运行模块；零游戏内容或媒体读取 |
| 来源新游戏 | 来源入口包、匹配的世界目录、初始地图、匹配的战斗目录 |
| 来源新游戏存档 | 存档绑定的上述入口闭包，以及当前地图包；不读取旧纳尔谢开发包 |
| 纳尔谢开发片段及其存档 | 旧开发字段包、匹配的战斗目录；跨图存档另需当前目录及地图 |

`GameContentRepository.sourceNewGame` 返回已验证的 battle；`restoreSessionContent` 按存档 `origin` 返回实际初始内容、战斗目录和恢复依赖。`GameSession.restore` 在来源分支使用可信 source bundle/initialMap，不再要求额外的 legacy field。开发分支仍必须提供原始字段包。旧 `restoreWorld` 和已有恢复调用保持兼容。

`sessionMediaUrls` 与 `sourceEntryMediaUrls` 统一收集当前入口的地图、角色、小地图和战斗图片，按 URL 去重。它们保留当前目录所列的角色和战斗媒体；尚未做按剧情裁剪或后台流式加载。音频按当前声部和待处理音轨准备。内容摘要、来源、版本及地图身份的检查保持原约束，没有引入存档格式升级或静默迁移。

## 验证与后续

新增 `npm run framework-entry:check` 执行整份实际 `app.js`，绑定真实内核、内容仓库与存档模块，并控制网络、图片解码、DOM 和音频宿主。它验证标题不下载包、旧入口不可用时仍能启动来源新游戏、入口/读档失败重试、取消后的迟到结果，以及战斗和库存界面绑定到新会话。它单独列为 `framework:verify` 的入口检查通道，不能代替真实浏览器或完整主线验收。
