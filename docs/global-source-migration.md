# 全源共用能力调度与完整剧情批次验收

这份策略落实2026-10-16的执行纠正：先成组补齐全游戏共用能力，再以完整剧情批次的实际贯通确认收益。真实新游戏保留为主线回归，不再从它的下一个报错派发主任务。整体系统骨架沿用既有实现，HD-2D与正式原版对照继续后置。

## 一份全源工作集

`scripts/plan-source-migration.mjs`消费一个已冻结的完整来源、同代649图候选和完整来源战斗审计，按各自编译器评估Field、Battle和AI。其余程序域原样保留为明确的unassessed任务，不能套Field解码器后计作支持。

原程序保留物理来源、完整正文摘要、原指令数、地图绑定和程序依赖。工作集还保留地图几何、资源、来源战斗请求与技能目录的独立诊断。没有程序定位的记录保持dependency site，不捏造某个脚本或第一条PC。条件性宿主需求单列为observations，未测量不等于未实现，也不等于已就绪。

`content-batches/source-common-capabilities.json`为确切selector分配共用工作流。它源于全源提名，只有调度含义；旧提名不授予新语义。当前编译器重新检查实际使用点，已支持的点自然退出缺口，未登记的selector进入unclassified。每条原诊断、操作数与来源位置仍可追溯。

纯`compileSourceMigrationWorkSet`构造程序及gap依赖图，以完整地图和声明批次同时所需的缺口集合选择并行波次。同批的互补缺口共同评分，每个owner占一条并行工作流并最多提名三个缺口；公平轮转避免战斗或地图系统长期挤占其他系统。独立程序与全局目录分开标注，不能把几百份独立AI程序当成几百段剧情收益。单纯高频、靠近开场或最先报错没有额外权重。

循环、未分类及其下游明确保留。含未知的地图仍可提名已知共用工作，但`plannedPreparationWave`只描述已知部分的潜在准备度，`plannedClosureWave`仍要求所有原缺口闭合。后续波次只是假设前波实施成功后的计划，不能当作实际完成。

## 内容和规划器的身份

执行源编译器、原数据、候选内容及其完整输入锁属于同一个冻结游戏运行时。规划工具单独记录代码与运行时摘要，可以检查该代内容，但不能因此让旧候选通过另一游戏运行时的加载守卫。规划不启动另一套游戏VM、不修改旗标、名册、HP或初始队伍。

全源计划默认只写ignored `build/reports/`，不发布内容。字段、战斗、名册、交通、媒体和保存的共用改动汇合后，统一检查并冻结；每波只生产一次完整候选。发布继续使用原有公共集合管线，不能让并行任务分别覆盖公共目录。

## 共用宿主接口

`field-runtime-ports`集中定义会话、初始入口和跨图的显式转发分类。宿主对象保持实际身份；缺失仍缺失，没有默认Ready或权限升级。`GameSession`和`WorldSession`继续持有原有事务，动态puppet路线、地图FX租约、draft、时钟与来源上下文仍由实际owner准备，不能用通用spread替代这些阶段。

这项调整减少新增共用能力在newgame、prepare、restore某个路径漏传的风险，不重写Field或新增游戏状态所有者。

## 什么才算完整剧情批次贯通

自动得到的地图或程序依赖闭包是structural cohort，不是已理解的剧情章节。缺少明确故事合同的批次保持`missing-contract`，即使所有静态缺口关闭也不计完成。

完整剧情合同绑定原程序及正常Main入口、所需分支、入口/出口状态、战斗、真实检查点续行与存读档。执行仍经过`GameEntryLoader → GameSession/GameFlow → Field/World/Battle → Storage`。只读执行证据来自实际任务入口、分支、自然结束与交接；候选准备、失败尝试和实际发布分别记录。以实际当前Field为准，宿主不得自报完成或指定中间PC来绕过正文。

合成合同只证明验收机制，独立受控正文结束只证明对应执行。只有完整来源合同的全部要求在同一代通过，才可记为完整声明批次贯通。主线连续新游戏、浏览器实玩、支线/世界阶段和最终全游戏放行仍分别留证；不以静态无缺口、测试数量或转换数量替代。

## 工作循环

1. 从完整源工作集选择可共同闭合一批内容的共用缺口，按现有owner并行开发。
2. 每项交付完整使用点、来源合同、未解决依赖及代表性的实际生命周期，保留失败与未知。
3. 汇合到同一个运行时；成组执行原始正文和已声明完整剧情合同，记录贯通、阻塞、失败及未评估。
4. 用批次结果刷新全源缺口与后续波次，另跑真实新游戏检查连续性；首个开场报错不能替换全源队列。
5. 持续至真实新游戏到结局及原目标所有相关内容、保存和浏览器验收完成，才关闭goal。
