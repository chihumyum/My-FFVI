# 稳定检查点与浏览器存读档

2026-10-11。`game-checkpoint-v1` 为已实现的共享系统提供会话级保存恢复。地图空闲时可在暂停菜单保存，刷新后从标题页继续；另保留上一份进度。它包含角色、物品、剧情与地图状态，已经超出单独 `GameState` 片段，但只接受稳定地图检查点。战斗、事件、移动、开门等待、淡入淡出和待处理切图期间不能保存。它是明确的 Web 开发存档规则，尚未恢复原版保存许可和原版存档格式。

v15 的共享片段已升级为 `owned-game-state` 版本 2，新增装备总持有数；当前六槽、等级与原始成长上下文共同决定可验证的资源上限和属性。复活/解除状态、换装和字段库存事务均经同一检查点保存。恢复世界地图时重新绑定库存端口，不重放已经完成的物品授予或收费；旧目录/快照版本继续拒绝并保留旧数据。以下首次交付的计数和浏览器结果作为历史记录保留，最新系统检查见 [装备](equipment.md)、[状态道具](item-status.md)、[字段库存](inventory-events.md)。

v15 最终目录与重新编译的现有世界包再次通过五次遭遇中的 40 次保存/恢复，最终状态与连续运行一致；既有 131 个空闲入口保持通过。受控浏览器完成换装/成长和复活/解除状态后的内存存取；本批没有覆盖用户原有浏览器存档。新回执 `build/reports/save-check.json` 内容摘要为 `1e988d247dbfd1be659577468dee0fb674d57ce70b9f3fd64975216d08abf957`，不把入口数算作完整可玩地图。

## 状态所有权

| 层 | 保存内容与恢复职责 |
| --- | --- |
| `GameSession` | 来源父集、战斗目录摘要、种子、遭遇序号、固定步长余量；校验序号与已领取战斗次数一致 |
| `GameState` | 开场名册与队伍、成长/HP/MP/状态、六槽装备身份与总持有数、物品数量、Gil/totalGil、领奖记录 |
| `WorldSession` | 初始包摘要；当前世界目录、地图、入口及入场角色外观；从可信包重建字段内容 |
| `FieldGame` | 逻辑时钟、步长余量、下个任务 ID、变量银行、已激活实体组、隐藏实体、角色位置/朝向/步数、门、动画及音频状态 |
| 浏览器宿主 | 校验文件摘要，获取同版本依赖，准备媒体，在全部成功后替换会话；菜单只投影状态 |

未知剧情变量仍为 `null`，不在读档时补零。只保存动态状态，不让存档携带脚本、能力执行器、地图定义、图块帧或角色属性公式。角色/图块动画的浮点状态与 BGM/环境音的通道、声部、时间和淡出尾声分别恢复。

读取在新建的候选会话中执行。世界加载与读档共用包身份、入口、角色媒体等依赖检查，但读档**不执行地图初始化脚本**，也不重新触发入口/已领取奖励。恢复实体组只重建来源绑定，再覆盖动态状态。用户点击继续后才推进模拟时钟与音频播放。

完成的事件任务历史、切图诊断历史和已记录的表现遗漏不属于未来执行所需状态，本版不保存它们；来源检查回执另存。活动任务、待处理战斗和切图本来就不能保存，不能把丢弃这些执行器状态解释为支持任意时刻恢复。下一场战斗仍从保存的种子和遭遇次序导出随机流。

## 文件与持久化边界

`web-game-save` 版本 1 包含保存时间、完整检查点和规范 JSON 的 SHA-256。`decodeSavedGame` 检查版本、长度和摘要；`GameSession.restore` 继续检查来源/目录、全部状态字段及来源对象身份。摘要用于检测损坏，不是签名或来源授权。不同内容目录、未知版本、额外字段、无效数量、失配的角色/门/动画/音频引用明确拒绝，当前会话不被部分覆盖。

`CheckpointStorage` 通过可注入的浏览器存储接口写入单个槽，键为 `ffvi-reweb.checkpoint.v1`，同时包含 `current` 与 `previous`。一次 `setItem` 发布两者；配额失败保留原槽。编码结束后会重新检查读取时的槽内容，检测异步等待期间发生的修改；这不构成跨标签页的原子比较交换。无法解析的旧槽在用户再次保存时仍作为原始字节备份保留，不能承诺该备份可读取。没有删除入口、静默格式迁移或自动覆盖存档。

浏览器加载期间冻结当前模拟。存档和依赖验证、图片/音频资源准备完成后发布候选会话，随后显示暂停菜单供用户继续。实测发现过暂停读档中 `resume` 与逐帧 `suspend` 互相等待，已将音频上下文初始化/解码与播放恢复分开；播放只在继续操作后恢复。音频资源准备不决定内核进度。
