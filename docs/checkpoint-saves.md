# 稳定检查点与浏览器存读档

2026-10-12，当前 v34。外层 `game-checkpoint` 的 `formatVersion=4` 为已实现的共享系统提供会话级保存恢复。地图空闲时可在暂停菜单保存，刷新后从标题页继续；另保留上一份进度。它包含角色、物品、剧情、地图状态和战斗模式/速度设置，但只接受稳定地图检查点。战斗、事件、移动、开门等待、淡入淡出和待处理切图期间不能保存。它是明确的 Web 开发存档规则，尚未恢复原版保存许可和原版存档格式。

当前格式分别为：

| 层           | v34 格式                              | 当前约束                                                                 |
| ------------ | ------------------------------------- | ------------------------------------------------------------------------ |
| 会话         | `game-checkpoint`，`formatVersion=4`  | 保存可信来源入口身份及 `battlePreferences`；来源新游戏恢复须另供可信 bundle 和地图 |
| 共享角色状态 | `owned-game-state`，`formatVersion=8` | 保存持有能力、全局能力历史、姓名标签、追加经验与成长及初始化来源身份 |
| 世界         | `idle-world-v9`                       | 保存当前位置及独立 `traveler.transportationId`，禁止伪造未支持的交通切换 |
| 字段         | `idle-field-v9`                       | 保存唯一原生演员集合、碰撞、更新 mask、相机偏移及已完成脚本上下文 |

共享状态继续保存三组四格编队、所选组、空位/前后排、完整已准入名册、六槽装备与总数、原生持有身份、职业历史、追加等级、enabled 装备登记和已释放职业。字段库存、编队、生命周期及步行状态通过同一份 `prepareFieldState` 候选草稿发布。旧版本严格拒绝，不静默补值或覆盖保存字节。接口见 [共享状态](shared-game-state.md)、[编队](party.md)。

v34 新增原生演员稳定 codec，并贯通 FieldGame → WorldSession → GameSession → 浏览器加载。来源与媒体定义来自可信内容，存档只携带运行值；恢复不执行工厂、NPC Init/Look/Cue、入口或剧情。原生演员不能重复写入旧演员/隐藏集合。活动 puppet 生命周期、骑乘、FX 和未绑定的跨图保留材质仍阻塞。真实开场停在活动切图，不能据此保存或宣称完整新游戏可玩，见 [原生稳定保存](field-native-checkpoint.md)。

以下 v30 及以前段落是逐批历史边界，当前原生保存能力以上述 v34 说明为准。

v30 字段新增来源绑定的 camera v2 状态：目标、dummy 位置/层/方向、独立视觉偏移及显隐状态。任务内 Lerp 不能稳定保存，玩家位置不会复制进相机；恢复拒绝重复的 hiddenEntities 表示、未绑定的宿主及旧 field/world v7。标题交接协议和完整原生演员仍不能借此保存。

v29 字段保存全局渐变的 Image/CanvasRenderer 颜色及 raycast 状态；活动 tween 不可保存，稳定黑幕可以保存。切图候选继承并隔离当前渐变，恢复必须匹配可信入口是否具备该宿主。原生 puppet 端口还拥有未持久化的演员/相机/碰撞状态，接入该端口的受控实例当前明确禁止保存和恢复；不能以空闲任务代替完整宿主状态。旧 field/world v6 拒绝，见 [渐变](field-fade.md) 与 [任务控制](field-task-control.md)。

v27 的共享库存包含真实空装备 Count；读档保留零数量，不重新发放五件初始种子。字段检查点新增 `sourcePresentation`，必须与可信宿主上下文一致，活跃标题演示不允许稳定保存；恢复不重放探测、标题副作用或地图初始化。旧 owned v6、field/world v5 明确拒绝，见 [空装备](empty-equipment.md) 和 [标题演示上下文](source-presentation.md)。

v23 新增 `entrySynchronized`，来源地图入口必须完成初始化才准稳定保存；固定开发检查点保持未知。恢复按可信内容分别要求 true/null，拒绝 pending、伪造证明和旧 v4，不重跑初始化，见 [字段入战上下文](field-entry-context.md)。

以下保留 v19 历史记录。v19 新增动态 owner 的追加经验/成长保存，恢复重算等级、能力与上限；字段另存同图原生演员状态，拒绝伪造骑乘内外层、隐藏身份和不可更改的提供器。旧持有 v5、字段/世界 v2 不兼容；完整依据见 [v19](systems-v19.md)。正式带演员宿主的跨图仍阻塞，131个既有入口只属于独立几何机制恢复检查。

## 状态所有权

| 层             | 保存内容与恢复职责                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `GameSession`  | 来源父集、战斗目录摘要、种子、遭遇序号、固定步长余量和 `battlePreferences`；校验序号与已领取战斗次数一致                              |
| `GameState`    | 已准入名册与队伍、成长/HP/MP/状态、六槽装备身份与总持有数、物品数量、Gil/totalGil、领奖记录、初始能力状态、全局能力历史和姓名标签映射 |
| `WorldSession` | 初始包摘要；当前世界目录、地图、入口、入场角色外观及实际交通身份；从可信包重建字段内容                                                |
| `FieldGame`    | 逻辑时钟、步长余量、下个任务 ID、变量银行、实体组与隐藏实体、角色位置/朝向/步数、交通身份、原生演员上下文、门、动画及音频状态       |
| 浏览器宿主     | 校验文件摘要，获取同版本依赖，准备媒体，在全部成功后替换会话；菜单只投影状态                                                          |

未知剧情变量仍为 `null`，不在读档时补零。只保存动态状态，不让存档携带脚本、能力执行器、地图定义、图块帧或角色属性公式。角色/图块动画的浮点状态与 BGM/环境音的通道、声部、时间和淡出尾声分别恢复。

读取在新建的候选会话中执行。世界加载与读档共用包身份、入口、角色媒体等依赖检查，但读档**不执行地图初始化脚本**，也不重新触发入口/已领取奖励。恢复实体组只重建来源绑定，再覆盖动态状态。用户点击继续后才推进模拟时钟与音频播放。

完成的事件任务历史、切图诊断历史和已记录的表现遗漏不属于未来执行所需状态，本版不保存它们；来源检查回执另存。活动任务、待处理战斗和切图本来就不能保存，不能把丢弃这些执行器状态解释为支持任意时刻恢复。下一场战斗仍从保存的种子和遭遇次序导出随机流。

## v18 历史新增的持久边界

`battlePreferences` 由 `GameSession` 持有，包含玩家选择的 active/wait 模式，随稳定检查点写入存档。模式改变影响当前和后续战斗，不改来源目录、不重置毒周期或蓄力。WAIT 在技能、道具及目标菜单等待时停止相应进度；主命令页不因此等待，普通暂停停止完整模拟。存档不保存正在打开的战斗菜单或活动战斗执行器。当前 `atbSpeed=1` 仍由开发配置固定，不提供尚未恢复来源映射的速度档位，也不能通过存档额外字段注入速度。具体门控见 [战斗时间模型](battle-timing.md)。

`owned-game-state` v5 的每个已绑定来源角色保存 `abilities`：初始命令列表、持有能力的 ability/content 身份与 SkillLevel、命令可见投影、取得/排序顺序、槽位及明确的提供器状态。`learnedAbilityIds` 是来源全局历史，其初始化包含全部持有能力，不能把列表成员资格等同于 SkillLevel 达到 100 或已经能够施放。当前恢复将角色能力及全局历史绑定到初始来源模板；尚未实现的学习变化明确拒绝。此能力状态进入存档不代表所有原生命令已进入战斗执行器，也不开放未知角色的剧情加入。

`characterNames` 的 key 来自模板 `nameTag`，即 `character_default_name.csv.tag_name`；本地化用的 `nameKey` 不作为标签。没有该表匹配行的角色不创建姓名标签。恢复必须使映射与已保存角色名及模板标签一致，不能另存一份可漂移的别名。

普通毒身份跨战斗和检查点保留；战斗周期时钟只属于本场战斗，进入下一场重新初始化。v18 已将已知实际交通状态下的字段步伤接入共享 HP：起步准备、成功完成时扣血一次，目的地事件和战斗读取扣血后的值。稳定存档没有额外的字段毒时钟，恢复也不重放上一步。已知交通类型 1 每步结算普通毒，其他已知类型按来源跳过相应监视器，详见 [地图步行状态](field-conditions.md)。

实际交通身份与骑乘资源分开。当前尚不准入通用交通切换，世界恢复要求保存的交通身份等于初始内容的已知身份或 `null`，字段恢复再次检查内容匹配；即使把存档两处同时改成另一合法身份，也不能绕过验证。正式开场的交通身份仍未知，魔导装甲外观不能用来补值，因此该流程带毒时移动保持 blocker，稳定菜单可解毒后继续。

## 文件与持久化边界

`web-game-save` 版本 1 包含保存时间、完整检查点和规范 JSON 的 SHA-256。`decodeSavedGame` 检查版本、长度和摘要；`GameSession.restore` 继续检查来源/目录、全部状态字段及来源对象身份。摘要用于检测损坏，不是签名或来源授权。不同内容目录、未知版本、额外字段、无效数量、失配的角色/门/动画/音频引用明确拒绝，当前会话不被部分覆盖。

`CheckpointStorage` 通过可注入的浏览器存储接口写入单个槽，键为 `ffvi-reweb.checkpoint.v1`，同时包含 `current` 与 `previous`。一次 `setItem` 发布两者；配额失败保留原槽。编码结束后会重新检查读取时的槽内容，检测异步等待期间发生的修改；这不构成跨标签页的原子比较交换。无法解析的旧槽在用户再次保存时仍作为原始字节备份保留，不能承诺该备份可读取。没有删除入口、静默格式迁移或自动覆盖存档。

浏览器加载期间冻结当前模拟。存档和依赖验证、图片/音频资源准备完成后发布候选会话，随后显示暂停菜单供用户继续。实测发现过暂停读档中 `resume` 与逐帧 `suspend` 互相等待，已将音频上下文初始化/解码与播放恢复分开；播放只在继续操作后恢复。音频资源准备不决定内核进度。

## 当前验证入口

来源检查依赖已生成的开场/战斗包、世界目录和 `world:check` 回执；全新工作区先按 README 构建这些产物。

```sh
npm run check
npm run world:check
npm run save:check
npm run playable:check
.venv/bin/python -m unittest discover -s tools/tests
```

当前针对性回归覆盖 active/wait 设置往返及下一场战斗、无效偏好拒绝、交通身份不可伪造、字段毒伤完成后保存恢复、初始化移动跨候选发布、重复/过期事务拒绝，以及成长、能力、全局历史、姓名映射或原生演员状态损坏时保留原状态。测试、来源探针、受控 DOM 与实际浏览器分别记录；下面的历史浏览器记录不替代 v19 最终验收，也不声称已经迁移用户原有存档。
