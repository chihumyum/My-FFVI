# Source producer policy bindings

The public collection builder and initialized source consumers must use the same explicit Web policies as the app. Policy declarations do not certify a source route, remove unknown instructions, or replace the strict baseline with a cached framework catalog.

The battle directory producer already emits `source-battle-directory-policy-v4`: its manual controls and condition policy retain the v3 meaning, and its branch execution policy must equal `web-source-battle-branch-execution-v1`. `validateInitializedBattleSharedCapabilities` accepts that exact combination through both initialized selection consumers. Missing or unknown branch policies, branch declarations on an older version, unknown policy/framework fields and unknown versions reject even after a caller recomputes document hashes. Existing v1/v2/v3 valid shapes and independently validated source/drop/initializer/diagnostic bindings remain intact. A strict optional catalog still has no Web policy.

`compileSharedContentPackages` forwards its explicit `worldAutoTasks` option, defaulting to the shared Web input declaration, into `compileSourcePrerequisites`. The prerequisite result supplies the same policy to the complete framework derivation and to each initialized source batch builder. `initializedContentBatchProfile` constructs each derived entry/world/map profile from that explicit option. Standalone calls that omit the option retain their earlier content shapes; runtime policy alone cannot authorize a content task.

Pinned recipe comparison uses an exact `compiled-framework-profile-upgrade-v5` declaration when adding `worldAutoTasks`. Its marker value must equal `web-flat-world-auto-tasks-v1`; it binds the current compiled `field-world-auto-tasks` module, the exported policy constant and the real `worldAutoBinding` provider with the module digest. V1 through v4 declarations retain their previous marker shapes. V5 adds no media, geometry, actors, source instructions, owned state or runtime default. It may normalize only explicitly declared additions during identity comparison; it cannot remove/change existing markers, excuse a wrong source pin or perform a save migration. The earlier v4 declaration remains in use when no world-auto policy was supplied.

Core source catalog comparison already includes the marker; world-to-field conversion copies the complete trusted destination profile, and development entry conversion already preserves it. These paths need no fallback or relaxed source admission. The task owner requires both current content declaration and runtime policy, plus the current map/camera binding.

Tests exercise the real initialized selection and selected-source validation consumers under v4, including rehashed malformed declarations. Recipe tests verify the complete entry/world/map pin chain, unavailable compiled providers, old declarations, unknown fields and foreign map changes. The public builder is called with an invalid explicit policy in an empty controlled root and must reject before source compilation or publication; actual initialized profile construction and GameSession execution test both single-authorization failures and a successful double-authorization queue. This test lane does not run the public 649-map producer. The parent integration owns one subsequent production run and the complete source observer checks after its final runtime freezes.


BirdView actor producer followup uses a separate exact `compiled-framework-profile-upgrade-v6`. Its required marker set retains the v5 hosts, including `worldAutoTasks`, and adds `birdViewActors: web-flat-bird-view-actors-v1`. The compiled `field-bird-view-actors` module must export both the matching `WEB_FLAT_BIRD_VIEW_ACTORS` constant and `fieldBirdViewActorBinding` function; the current compiler digest binds that physical module. Older declarations keep their original shapes and cannot add this marker. V6 cannot grant a future world-auto-move marker. Full source instructions, geometry, presentation, map and dependency identities still compare unchanged, apart from the declared additive profile values.

The public collection producer forwards the explicit actor policy through source prerequisites, complete framework derivation, recipe comparison and each selected initialized batch. The initialized profile constructor derives entry, world and every map profile from that same option. Replay runtime ports also supply the explicit actor policy. The runtime binding provider requires both current content and runtime declarations, the framework map/camera identity and the current content hash. It grants no actual actor; the existing FieldGame owner separately validates the live native actor before creating or restoring an elevation component. Stable saves contain only validated numeric poses and cannot grant either declaration.

The integrated compiler removes the previous scalar-family early stop for `MoveBirdView`, which otherwise masked the later separate BirdView decoder after a clean textual three-way merge. The separate `AddAirShipMoveTask` gate remains in place. Tests exercise actual production profile constructors, single-authorization failures, successful double authorization, unavailable providers, old/future declaration rejection, complete pinned identities, actor lifecycle and storage. These bounded checks do not produce all source maps or certify an original route as executable.
