# v52：奖励与角色进度

本轮把敌队奖励、战斗副本、角色持有状态、返场和存档连接为一条共用合同。没有增加地图或剧情专用分支。来源 `monster_party.get_value` 是战斗魔法学习点，先前将非零值一律视为“特殊奖励”并阻塞；现在明确编译其规则，并保留真正未实现的奖励和学习提供器门禁。

## 状态和事务

- `BattleEncounter.rewardPolicy` 保存严格解析的 `{ kind: "battle-reward-policy-v1", ap: 0, magicPoints }`。来源角色目录必须逐敌队提供它，不能放在公共目录层或缺省成零。编译器拒绝非零 AP，以及会改变结果保存、经验或 Gil 的旗标 3/9/10/11/12/13；即使开发省略列表精确匹配，也不能绕过这条检查。
- `GameState.openBattle` 复制并固定奖励规则，和本场队伍、库存一起保留。`BattleGame` 另持只读规则副本，结果包含 `magicPoints`；战败重试从原租约读取规则，不重新读取可变内容参数或新开奖。
- `OwnedCharacter.magicLearningValue` 是每名角色的持有值，初次建立和首次 Join 为零，重加入保留。每名符合当前普通结算资格的存活成员取得完整点数，独立封顶 128，不按经验人数分摊；经验分配为零也可增长。死亡成员不增加此值，原先已支持的观察学习仍独立处理。
- 进度回调在临时角色上计算，所有成员成功才公布胜利。持有状态在 `prepareVictory` 独立复算并核对结果，随后与字段返场一起提交。错误结果、后来成员失败、返场缺失、过期事务或重复确认都不会部分写入。撤退保留入场学习值，无奖励；战败重试恢复原副本。
- 战斗资格查询读取当前角色的值，避免借用同一个公共上下文值。结果页只显示非零“魔法学习点”，菜单只显示已知角色的持有值；界面不做累积计算。该值与可施法的 MP 资源、技能熟练度是不同状态。

`owned-game-state` 升至 v12；外层 game v5 和字段/世界 v10 保持不变。旧 v10/v11 先校验完整历史形状，再补入零值，因为之前的编译器拒绝非零 `get_value`；v10 同时补入已知的胜利结果。读取不修改调用者或存储字节，也不重写内容摘要；不是任意旧目录跨版本兼容。当前值只校验范围和运行事务，不把存档当作历史奖励证明，也不新增一份可漂移的累计账本。

## 来源与边界

静态来源绑定见 `scripts/check-battle-result-native.mjs` 和本地 `build/reports/battle-result-native-check.json`：

- `StartWinResult`（0x463f00）从敌队分别取得 AP、MagicPoint；`BattleSkillUpInformation` 的两项字段不同。
- `BattleResultProvider.Genelate`（0x3d51a0）为 `IsGetExp` 成员增加完整 MagicPoint，再执行成长；非资格成员仅走观察学习。
- 构造函数 0x3d58b0 将上限字段写成 0x80，即 128；保存数据的 `MagicLearningValue` 是独立字段。

检查覆盖固定 DLL 指纹、4 个方法收据、10 段原始字节和 8 个语义锚点。这是静态来源核对，不是原版动态运行对照。当前死亡以外的完整经验资格、非零 AP、魔石、装备学习、战斗背景学习、特殊结果旗标及完整变身效果仍未迁移。现有门禁不因本次正奖励而放开。

真实正奖励候选仍保留独立依赖：敌队 4 缺少已导出的怪物媒体；敌队 274 需要未实现的状态抗性。集成探针因此采用明确的组合：把敌队 4 的真实 +1 奖励规则应用到私有的敌队 3002 副本，保留后者的角色、敌人、AI、能力、装备、普通掉落与经验/Gil。仅加入开发行走遇敌和撤退策略，不发放额外库存。既有 sc_b_0239 和旗标 14 省略仍被标明，不能据此宣称敌队 4 或 274 已可玩。
