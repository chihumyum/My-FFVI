2026-10-11，开发包 `narshe-playability-v7`。单体、一方全体和敌我全体现在共享目标选择、排队复验、逐目标命中/效果和整次提交。来源范围的编译与运行时单位选择分离，不添加场景、角色或遭遇 ID 分支。开场仍只开放既有魔导菜单；本批没有扩展地图或剧情解锁。

## 接口与事务

`compiler/battle-targets.ts` 将源枚举编译为 `TargetRule`。`core/battle-targets.ts` 消费关系、可选模式和阵型前置条件，输出 `TargetChoice`；内核不判断原版能力 ID。

`BattleGame.targetChoices()` 返回明确的 single/side/all 请求及对应单位 ID。旧 `targets()` 只列出单体候选。`command()` 接受单位 ID 或显式选择；固定全体动作不能用单体请求绕过。排队保留选择含义，出手前重验集合；单体重选不会从敌方跳到友方。`BattleAction.results` 按目标保存效果，UI 为每个目标独立绘制数字和效果。

整次行动先计算所有目标的数值、状态和日志，再提交一次 MP 费用及全部结果。自我 MP 恢复使用扣费后的起点。后一个目标出现不支持输入时，前面的 HP/MP、状态、结果和随机流都不改变；这是一项 Web 提交契约，不声称原版内部也是事务实现。战斗时钟、队列和演出仍沿用开发调度；尚未形成任意时刻存档或全局事务。
