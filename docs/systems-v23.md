# 系统集成 v23

本批将完整来源技能定义、普通魔法、防御和字段入战上下文接入已有共享系统。技能由数据批量编译，实际菜单仍由角色持有、学习进度、当前状态及效果依赖共同决定。纳尔谢只作回归样本，未扩大区域内容，未启动 HD-2D。

## 技能定义与实际持有

来源包保存全部 1530 条能力定义及其函数依赖，不再把开场遭遇选用的 12 条能力当作全局执行目录。261 条具备当前算术计划，其中 260 条满足有界宿主的依赖；其余 1270 条保留具体阻塞。缺少名称、内容身份或尚未恢复的状态与特殊提供器不会被占位实现放行。这些数量不是已获得或可玩的技能数量。

普通 type1/type2 的单函数魔法与计算恢复进入共用目标和效果事务。来源初始角色 1 已学会的 31/40 直接出现在魔法菜单；没有追加技能授予、修改 SkillLevel 或加入全局取得历史。费用、目标效果和失败回滚共用原有战斗提交。Runic、反射、不死例外、MP 被动修正与特殊费用仍按各自依赖阻塞。源图标标记只在界面投影中去掉，原始名称不改写。见 [能力目录](battle-ability-content.md)。

## 防御与状态生命周期

command2 → ability2 → function type15 → condition row1/type1 的来源链使用共用状态规则。防御只选择自身，效果提交后生效，不消耗 MP、不产生命中随机数；物理伤害按来源位置减半，魔法伤害不因它减半。下一次接受普通 ATB 行动时清除，取消和非法输入不清除，直接反击保留。尚未恢复的特殊行动清除规则仍拒绝。

防御状态不进入字段持有状态，也没有额外的持久布尔值。失败帧恢复条件、队列、时钟和随机流；死亡及战斗结束走来源清理。存活时选择来源 `ready` 姿态，优先于濒死；身体与装甲分别读取已有媒体别名。完整原生动画调度仍未完成。见 [防御](defend.md)。

## 字段入战与稳定保存

`GameSession` 从当前 `FieldGame` 读取来源入战上下文。地图全部活动实体组都已知且没有存档点对象时才能确定 `isSavePoint=false`；真实存档点的触发回调未恢复时保留未知。普通地图的 BeastField 单例和恒定地面子集按来源提供，不从画面或地图名称猜测。

字段另保存明确的初始化同步状态：来源地图入口从 pending 开始，任务、移动、对白和淡入全部完成后才确认同步。初始化中遇敌或阻塞不能提前确认，战后续段继续同一次入口。固定开场开发检查点没有这份来源证明，仍为 null。

field/world 检查点升级 v5，owned 保持 v6，外层 session 保持 v2。恢复按可信内容校验同步状态，不重跑初始化；pending 不准保存，旧格式明确拒绝。649 份地图元数据中 647 份可在同步后提供普通地面，2 份属性网格仍未知；这是提供器范围，不是可玩地图范围。见 [字段上下文](field-entry-context.md)。

## 验证与后续

本批通过 725 项 TypeScript、22 项 Python 测试；真实来源重新编译后，48组来源与集成检查通过，覆盖完整技能目录、原生区间绑定、260 个有界计划的纯目标投影、自然持有的治疗与火炎、字段入口、既有五次遭遇和 40 次稳定存取。来源静态恢复、受控宿主检查和浏览器实玩分别记录。完整命令、产物摘要及结果见本地 `build/reports/systems-v23-validation.json`。

后续继续恢复共用活动状态、装备被动、完整目标/调度、角色学习、新游戏初始化及商店/掉落/世界运输。完整系统门禁和最终迁移验收均保持未完成，不能由目录覆盖率推断游戏已迁移完成。
