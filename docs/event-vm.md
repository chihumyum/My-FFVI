# 共用事件状态与控制流

本批把 `Calc`、`Branch`、`Jump`、`SetFlag`、`ResetFlag`、`FlipFlag` 接入现有 `FieldGame`。地图事件、战后脚本和批量检查使用同一实现，运行时没有地区名、对白 ID 或具体剧情 flag 的分支。它是通用 VM 的已实现子集，尚未恢复完整任务和地图生命周期。

## 所有权和入口

- `src/core/event-state.ts` 拥有剧情/宝箱 flags、全局/区域/地图/脚本变量、选择结果、int32 运算和条件跳转。
- `src/compiler/field.ts` 把来源操作数编译为有类型的指令，并保留脚本局部变量定义。非法命名空间、地址、数值和参数形态不能被默认值掩盖。
- `src/core/field.ts` 持有状态实例，拥有任务、调用栈、等待、角色和对白；`startEvent` 与地图触发器使用相同执行路径。调用方可传入同一 `EventState`，为后续地图切换保留单一状态所有者。
- `loadCorpus` 校验导出快照和来源，再供能力队列和实际执行检查复用。批量脚本不重新实现操作码语义。

`EventState` 默认所有尚未恢复的值为 `null`。读取这些值会明确停止。`initialized()` 是显式全零初始化，只用于已知初始化或受控检查，不能拿来填中途检查点的未知剧情。赋值可以建立一个未知变量的值，但不能建立越界地址；其他依赖左操作数的运算必须先读到已知值。

`snapshot()`/构造器完成带版本的变量状态序列化与恢复，保留未知值，校验存储尺寸、flag 值和 int32 范围；输出与输入均不共享可变数组。这还不是完整游戏存档：队伍、地图、任务栈、媒体和其他状态尚未接入保存。

## 来源规则与定位

仅绑定当前 `GameAssembly.dll`：`1a7e12c90c6a734e17dda507dd6ab7555090dff6a1e96f3473a90c29916ca6dc`；metadata：`9b426d617a022020feee61cdfc19b16ce1a51c07542fe1dd59169e12f35a3e45`。反编译输出和范围摘要保存在忽略的 `build/native/event-state/`、`event-operators/`、`shared-event-vm/`，不能由工具的导出成功自动推导行为已验收。

| 已实现规则 | Native RVA / 静态证据 |
| --- | --- |
| 命名空间到存储类别的读取/写入分派；选择寄存器忽略 index | `0x82ECC0` / `0x82F600`，对应 dump 的 DataStorage.Category |
| 剧情、宝箱各有 1,024 位；四段地址为 `segment * 256 + index`，边界检查作用于物理地址 | `0x830220`、`0x82EB90` / `0x82F490`；跨段别名保留，非零写入为 true |
| 全局变量 16、区域 8、地图 8；普通变量为 signed int32 | `0x830220`、Get/Set 的对应数组分派 |
| 初始化清空持久存储和选择值；脚本变量为 null | `0x82F300` |
| 清地图变量同时重置两个选择结果和当前地图 ID；清区域另外清区域变量 | `0x82E870` / `0x82E810`；本批提供方法，尚未推断切图时应调用哪一个 |
| ScriptLocal 的标签数量决定容量；初值数量一致才复制，否则填 0，并重置选择结果 | `0x82E8B0` |
| 新根脚本有 ScriptLocal 才调用局部变量初始化；缺省时保留现存局部变量/选择结果 | `0x5F2530` 的条件调用，区别于存在但为空的数组 |
| 运算左地址为 `s[0]/i[0]`，操作符为 `s[1]`；右边 `s[2] == imm` 时读 `i[1]`，否则解释为变量地址 | `0x2BBB80` |
| Calc 把结果写回左地址；Branch 仅在结果等于 1 时跳至 `i[2]` | `0x2CA0F0` / `0x2CA840` |
| Jump 跳至 `i[0]`；目标范围由 PC 验证 | `0x2BBB20` / `0x834420` |
| Set/Reset 写 1/0；Flip 把原值是否为 0 写回 | `0x2BC5A0`、`0x2BB2B0` 与共用 DataStorage.Set |
| 全宽操作符的赋值、加减乘、比较；结果保留 int32 | `0x2CA200/210`、`0x2CA4E0/4F0/500/510/1C0/1D0`；赋值 `0x2CA1B0` 与乘法 `0x2CA220` 为共享 RVA，另核查实际指令字节 |
| 除零返回左值，模零返回 0；带符号除法向零截断 | `0x2BB230`、`0x2CA230`、`0x2CA380`、`0x2CA1E0/1F0` |

原始除法和余数回调使用 x64 `idiv`；`INT_MIN / -1` 和对应余数溢出在 Web 明确停止，不让 JavaScript 产生一个看似有效的结果。未知值是移植时的证据状态，原版本身没有这个表示；赋值不要求未知旧值已恢复，因为它不影响运算结果。

## 整批执行检查

```sh
npm run corpus:plan
npm run events:check
```

检查从全部地图包脚本按能力选取：至少有一个条件分支，全部指令可解码为控制流、等待、flags 或普通对白，且只有一个覆盖完整指令区间的 segment。选择在运行前完成，没有按执行结果丢弃失败样本。其他脚本的排除原因保存在同一收据。

对每份脚本执行全零受控状态，再按条件操作数产生单个变量/flag 的边界输入。执行前经过 JSON 状态恢复边界，自动确认对白，并重复执行验证确定性。记录来源、输入、对白键、状态变化、最终状态摘要和停止原因，不把受控状态称为真实存档。

本批运行 32 个资源包中的 87 份脚本，258 组输入全部终止；77 份出现随输入改变的对白，8 份出现状态写入。另核对 `Map_20051_10` 的双对白路径及 `Map_20110/sc_e_0226` 的有条件写标记，均没有增加运行时场景判断。收据：`build/reports/event-batch-check.json`。

这些是原始数据在新内核中的执行证据，没有证明所有路径覆盖、剧情状态可达、地图可玩或原版一致性。当前也没有恢复 segment 的任意入口/任务生命周期；检查明确限定单段全程序，不能把整个数组的地址检查推广为已支持任意源程序。
