# v45 公共运行框架与失败恢复

本批按用户的“系统骨架优先”修正推进方式。主交付是系统之间的公共运行接口和连续生命周期；来源开场的下一条表现指令只记录为缺口，不继续逐条追赶。

## 运行与状态

- `GameFlow` 独占宿主时钟、输入准入、暂停及异步操作票据。
- `GameSession` 串联字段、战斗、奖励成长与保存；`GameState` 继续独占名册、编队、库存、装备和学习状态。
- `GameMapLoader` 统一内容仓库读取 → 世界候选 → 宿主媒体/表现准备 → 原世界提交。不同地图只提供内容，不添加地图名分支。
- `CheckpointStorage.prepareSave` 将异步编码与同步写入分离；过期票据丢弃候选，一次写入共同发布当前和上一份进度。
- 浏览器绑定已发布的字段及表现。提交前失败保留旧会话和切图请求，可显式重试；返回标题取消请求，迟到候选不得发布。提交后的 UI 错误走停止路径，不能重放切图。

旧的切图失败处理会把 `map-transition` 改成 `unsupported`，丢掉可重试请求。页面现在保留原请求并提供“重试载入地图”，不自动每帧重试，也不通过清空剧情任务恢复。

## 既有音效工作的收尾

普通 `PlaySE/StopSE/SyncSE/ReadySE` 接入共享事件任务与音频媒体。声音使用独立实例句柄，脚本局部变量保管句柄；同步等待、异步叠加、停止、跨图候选及稳定恢复使用同一所有者。浏览器确认声音已提交播放后才推进其逻辑时间，避免短声音在解码帧被跳过。

媒体管线导出 628/649 条普通音效，21 条特殊程序明确保留缺口。原生混音、精确时间及设备听感不属于本批完成声明。详见 [脚本音效](field-sound.md)、[音效媒体](sound-media.md)。field/world 检查点升级 v10；owned v10、session v4 不变，旧字段格式不静默迁移。

## 验收分层

`npm run framework:verify` 汇总三种不同结果：

1. `frameworkContracts`：公共系统及事务接口是否通过受控组合检查，包括多图连续生命周期。
2. `batchAdmission`：指定来源内容批次是否完成依赖闭合及留出轨迹。没有指定批次时明确为 `not-assessed` 并列出缺口。
3. `sourceJourney`：来源新游戏实际运行到哪里，保留地图、时间和停点；不反推前两者。

多图轨迹采用可再分发的合成地图与真实内核：A → B → 战斗 → 结算返场 → 菜单 → 保存恢复 → A。只有显式读档替换会话；切图使用原会话。它验证接口和一次提交，不换算为来源地图覆盖。

## 已知边界与后续骨架工作

来源开场开发路线本批已执行 609 → 3 → 178 → 609，在 80,550ms 停于 `sc_e_0001_3:154` 的摄像机 Move 提供器；开场仍未完成。旧纳尔谢开发入口的五场遭遇/40 次恢复回归在第二场前被 `sc_e_0004:1 RideVehicleNPC` 阻塞。该能力门禁已存在于 v44：旧入口没有 framework transportation profile。本批保留失败，不用省略或伪造演员换取通过。

下一步优先解除启动入口对未使用内容的依赖，统一入口包与媒体准备；随后建立活动事件的保存/继续协议，再按明确批次做内容依赖准入。基础战斗、菜单、学习/成长和世界系统按代表性组合验收，特殊机制按批次实际需求增加。摄像机精修、粒子、混音、逐位数值复刻和 HD-2D 不抢占框架主线。
