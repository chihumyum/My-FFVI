# v67 菜单与读档后连续游玩

本批完成共同主循环的菜单输入和恢复续行接线。网页与批次继续复用 `GameCommands`、`GameEntryLoader`、`GameBattleHandoff`、地图装载和保存协调器；没有第二份角色、库存、剧情或战斗状态。工作单位是系统之间的连续流程，精细场景和 HD-2D 继续后置。

## 菜单输入

`GameMenuCommand` 表达道具使用、装备变更、编队调整及战斗偏好四类已有操作。公共入口立即验证并复制声明，再交给原菜单或设置接口检查当前会话、阶段和事务资格；有效输入也可能被实际游戏状态拒绝。

网页的库存、装备及偏好使用这份声明。队伍视图继续保留渲染时的预期编队，在实际变更前检查它，以免旧按钮覆盖新编队。批次的声明编队操作在派发时读取当前编队，同样通过原事务提交。

## 恢复后继续

路线可以声明 `menu` 和 `save-restore` 输入。中途保存和终局保存使用同一存储、内容仓库、摘要检查和会话发布流程。只有恢复提交成功后，运行器才绑定新会话的状态、世界和命令，重新建立宿主就绪状态并继续玩家输入。旧命令不能修改恢复后的进度；失败保留原会话。

恢复不重跑地图初始化、不重新消费道具、不重发已结算奖励。终局仍要求一次实际保存与恢复，中途恢复不能代替这个出口检查。

声明输入的顺序和参数进入扩展路线的依赖摘要。路线回执记录实际完成的输入数、菜单数、恢复数和中途恢复后完成的输入数；准入核对声明与执行数量，并保留地图、遭遇、来源纯度、运行时身份和检查点门禁。没有扩展输入的旧清单与依赖摘要保持兼容。
