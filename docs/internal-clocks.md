# 内部调度指令的全量批次

本批以完整语料中的 `Nop`、`Blank` 家族为单位。所有相关完整程序、来源地址、未支持指令和非字段使用点保留；通过现有统一语料和完整程序执行器成组检查，不改写原始脚本。

固定来源 DLL 的 `Internal` 字典将这两个确切名字注册到已核验的方法，主任务和 puppet 都先调用同一 `Core.Execute`。`Nop` 直接返回 Next，完全不读取操作数。原始编辑器留下的旧参数或缺省 operands 因而保留在 raw 数据中，不再被误当成未实现行为。这只适用于已证明的确切名字，未知指令保持阻塞。

`Blank` 读取原核心的 IsFirstClock：首时钟返回 Blank，后续时钟返回 Next。Web 直接让出已有 FieldGame task，已有 lastClock 防止同一逻辑时钟重复执行；没有第二个调度器或计时状态。未完成事件继续阻止稳定保存。事件保存屏障后的恢复仍由已有会话和保存 owner 完成，不会重复此前奖励。

`scripts/inspect-internal-clocks.py` 只读核验 DLL、符号、头文件、字典注册、叶方法、共同调度器和现有完整 Core.Clock 回执。静态证据不代表执行了原游戏。`npm run internal-clocks:check` 重建全部语料、执行完整字段程序，再将整个家族与该次执行结果及新鲜原生证据绑定；没有通过的来源程序和原剧情可达性继续单列。
