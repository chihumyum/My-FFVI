# 系统集成 v21

本批按系统优先继续 Web 迁移。普通宝箱、潜在角色战斗模板和入战来源提供器并行开发，集成线负责字段任务、入口校验、世界文案与回归。没有扩展区域剧情，也没有开展 HD-2D。GitHub 私有仓库只追踪源码、工具、说明和合成夹具；原始资源与生成物留在忽略目录。

## 宝箱任务与事务

普通交互使用来源 `after=false/message=true/se_id`；显式 `TreasureBox` 保留 `after=true` 与消息参数。宝箱外观打开和领取标记是不同状态。任务先提交共享库存，再显示消息，确认及收尾帧之后才写标记；满额提示不拒绝来源发奖，库存仍按来源上限截断。第一条 `close=false` 消息在收尾帧保留窗口，随后显示容量提示。重复按键不能跨过尚未呈现的一帧或再次发奖。

脚本宝箱只注册独立事件，包装任务不等待该事件结束，也不另外发奖。17 个来源脚本宝箱具有未使用的占位奖励模板；普通分支不因它们被误封，但显式消息路径仍需完整依赖。匿名 `entity_id=0` 使用已选中的 Web 实体身份，不能假装成显式原生查找 ID。

所有消息、参数、脚本和 flag 写入依赖在所选分支的首次发奖之前检查。失败的库存提交不改变图块或任务进度。活动宝箱不能保存；并发切图／入战不能丢掉已发奖而未写 flag 的任务。审查用两个失败回归复现了原来的任务丢失，再验证保护生效；脚本宝箱独立事件的合法交接仍通过。

世界编译现在使用同源、校验摘要与对象身份的 `system_zhc`，而非仅有剧情文字的 corpus。真实 320 个来源交互均可编译；世界产物内逐条核对 330 个实例、315 个唯一来源，剩余 5 个来源位于 map386/449/489，因未支持的碰撞范围而明确排除。数字不代表可达宝箱或可玩地图。

来源检查覆盖 25 条指令、1,035 个纯任务探针；其中三条真实有消息指令以未开、满额、已开三种状态完成 9 条共享状态与存取链。普通直接奖励、满额、空箱和 `sc_e_0880` 脚本交接另有四条存取链；`sc_e_0021` 的自动消息控制仍停在来源阻塞点。SE 使用已有显式静音开发通道，10 ms 帧边界与当前窗口不构成原生演出一致性。详见 [宝箱任务](treasure-task.md)。

## 战斗模板与入战来源

18 份普通角色模板使用同一个初始化、成长、装备和精确静态媒体编译器。它们进入潜在定义目录，不增加初始持有人，不改变剧情获得或已学习能力。加入后的现有 HP、等级、装备和能力覆盖模板初值。普通模板携带来源资格、当前状态和普通外观要求，由 GameSession 和 BattleGame 共同检查；开发静态入口不能放行空动作模板。

片头 `sc_e_0001[18] AddCondition(607,0)` 已证实向当前编队 owned 列表写入 condition row53，随后六段来源脚本将其带至开发检查点。target0 不是全名册，row53 也不是类型607；交通6和坐骑图片不能替代这一状态。来源编译产物的 `entryProviders` 保存完整脚本、表行和对象依赖。正式状态与魔导装甲表现尚未连通，因此开场仍明确使用 `development-static`，未伪装为完整来源入口。

入战提供器分别恢复地图禁用内容、兽原上下文与物品菜单资格：649 条地图规则、273 条物品／装备资格记录、50 项实源库存探针。未知交通、兽原或装备资格保持未知；来源可列出菜单项也不代表该道具效果已实现。原生证据包括 43 个方法与 15 段字节范围。详见 [普通角色模板](player-battle.md)、[入战提供器](battle-entry.md)。

## 验证与后续

TypeScript 与 Python 全检、当前来源编译、宝箱／普通角色／入战提供器检查、共享状态及旧五次遭遇和 40 次存取通过；准确数量、构建摘要、命令日志和浏览器结果由 `build/reports/systems-v21-validation.json` 绑定。字段与世界稳定检查点保持 v4、owned 状态保持 v6；内容摘要更新会拒绝旧开发目录存档，不覆盖用户原保存。

下一批先将已知 row53 的字段写入、持有保存、战斗初始化、装甲表现与清理连成闭环，再让动态来源资格替代临时开场菜单；其他状态、特殊战斗、完整学习、商店／掉落以及完整初始化继续按系统依赖推进。原生执行对照仍按用户指示后置，静态回执 `semanticsVerified=false`，纳尔谢／歌剧／全游戏验收门禁保持未完成。
