# Source control-condition batch

This batch keeps parties 116, 117, 290 and 291, complete abilities 577, 343, 140 and 305, and every corresponding original source entry. It does not rewrite story flags, party membership, HP, source instructions or their addresses. A decoded condition, a compiled ability plan, an executable Web battle and a reachable source story are separate claims.

## Ownership and source binding

`source-condition-application.ts` binds all three original function slots, the whole ability rule projection, process values, ordered forbidden conditions, content flags and elements. An omitted companion slot or altered dependency fails. It recognizes Sleep/type7/Until9, Confusion/type12/Until8, Temptation/type630/Until17 and Doom/type404/Until2 by their complete metadata, independently of condition row identity. Provider-bearing resistance dictionaries use the existing condition compiler. Referenced effects and sound masters are retained even when a declared presentation lane omits playback.

The existing `BattleGame` owns conditions, clocks, current combatants, queued actions and RNG. `conditionRecoveryHit` carries source Chanting/IsMagic classification; it is not a replacement RNG or a damage-derived hit guess. `conditionTraits.baseUndead` is only a fixed source parameter fact. Enemy definitions carry it directly; the shared read-only `playerConditionTraits` dictionary binds player facts by exact sourceId without changing `GameState.battleDefinitions`. Current Zombie/type34, FF6 accessory Armor.Id124 and the unsupported `isUndeadFromRampage` mutation remain distinct live inputs. Missing metadata does not mean false.

All four conditions are battle-local: the source return rule retains only Until3/19. The field compiler explicitly excludes these new behaviors, so their zero damage/sound fields cannot turn them into passive field statuses or checkpoint injections.

## Explicit Web policy

`web-source-control-actions-v1` declares a Web scheduler and automatic-action projection. Absence of this policy retains the strict gate. The policy uses the same owned commands, source command/ability qualifications, live unit owner and battle RNG. It does not claim native ActSelect parity. The admitted Stop composition also declares its bounded ready-interrupt fallback explicitly in [ordinary Stop](condition-stop.md): only known suspended current function owners may yield, while eligible interrupts retain priority and unknown authority/charge contexts keep the strict boundary. Unknown command, item, Tower, Umaro, special enemy-provider and undead contexts must remain reported stops rather than filtered candidates or a Fight-only substitute.

The production whole-world battle producer selects this through `source-battle-directory-policy-v2`. Version1 still has only its original handoff/entry fields. Version2 requires the exact additional marker; null, unknown markers, extra fields and an unavailable compiled control module fail. The strict source catalog does not receive the marker. The Web composition audits the entire common body before/after, the exact marker delta and unchanged initial owner hashes, while retaining every blocked party/diagnostic. Candidate tools call this same pure producer rather than editing the resulting catalog afterward. Publication and recipe reference rebinding remain the existing pipeline's responsibility.

Both initialized content selection and the published selection checker use `validateInitializedBattleSharedCapabilities`. Only the known policy may differ, with a version2 declaration and the exact complete before/after common bodies and owner hashes in `policyChanges`. Missing, stale, unknown or extra changes fail even after rehashing the catalog and report. All other common capabilities remain identical; source initialization and drop ownership keep their existing checks. A strict source baseline cannot carry this Web marker.

Range16 is available only for a complete control-condition action under this policy in normal formation. Its opposite-side group projection is a declared Web approximation; other range16 actions and native position-group semantics remain outside this admission.

## Native evidence

The portable inspector binds the original DLL, metadata, symbols, header, complete method ranges and decompiler receipts. It also binds the private implementation fields by their original metadata offsets and SHA1-named bytes:

- Doom pause types: metadata 0x4df480, `[17,627,11]`.
- Confusion command identities: metadata 0x4df6ad, `[1,7,8,9,10,11,12,14,15,16,17,18,21,22,23,26,30,31]`.
- FF6 IsMagic: complete original jump table at 0x4f7934 plus the separate ability261 comparison.

The current bounded packet has 73 complete raw method ranges (52,928 bytes), including 39 freshly exported unique methods and 16 reused complete cached exports. Shared tiny getters retain every alias. Original native execution has not been performed, and decompiled C alone is not a parity certificate. The portable inspector rejects altered C evidence before writing a success report.

The evidence directory defaults to ignored `build/native/source-condition-effects-v1`. It contains the three bounded requests, original exported C and completion receipts; none are committed. Reproduction uses the repository's `tools/native/ExportMethods.java` and the method lists in `native-request.json`, `native-support-request.json` and `native-consumer-request.json`. The first list explicitly separates shared methods, which are audited as raw bytes rather than passed to the unique-signature exporter. Existing cached evidence is independently rehashed against the same original files.

## Reproducible checks

Use an absolute isolated output directory while developing; do not compile into another lane's `dist`:

```sh
node node_modules/typescript/bin/tsc --outDir /absolute/isolated/dist
node --test /absolute/isolated/dist/tests/source-condition-application.test.js
.venv/bin/python scripts/inspect-source-condition-native.py --root "$PWD" --output build/reports/source-condition-native.json
node --max-old-space-size=8192 scripts/compile-source-condition-candidates.mjs --root "$PWD" --compiled /absolute/isolated/dist --output build/reports/source-condition-candidates
```

The explicit complete verified SystemReader supplies added condition effects, sound masters, Chanting classification and monster flags. `readConditionSourceBindings()` retains each actual read as a full raw row with its SourceRef, physical bundle hash/bytes and source-set identities. This is a separate capability audit; it does not expand or silently refresh the pinned `SharedBattleSource` selected closure. Missing or ambiguous physical bindings and source-row changes fail.

The candidate tool retains all 185 Encount parameters, their four weighted slots, all 89 possible parties and both strict/Web reports. It writes the fresh source base and strict catalog alongside the explicitly declared Web candidate. The complete `GameState`, the selected shared source hash and original source initializer remain byte-equivalent to the pinned source generation. New compiler metadata belongs to the battle capability dictionary and its separate read ledger; it cannot rebind owned state by stripping metadata or relaxing source identity checks.

`inspect-source-condition-batch.mjs` accepts `--battle-catalog` and `--battle-proof` pointing to a sealed source encounter candidate/proof. It compiles and preserves the complete source body/dependency inventory, including source map initialization. The large body and graph are separate hashed artifacts, not truncated statistics. The current initial inventory has six physical roots, three maps, twelve same-map programs/562 instructions and a full reference closure of 612 maps/2,341 programs. That graph still has 10,303 diagnostics; graph closure does not authorize those maps or establish story reachability.

That six-root inventory is historical. The final v100 public-runtime driver retains seven physical roots and fourteen complete same-map programs, including the still-blocked FinalAttackAct candidate. Twenty original-map/controlled-map attempts enter seven actual battles in the controlled lane: all seven end in natural defeat and fixed-entry retry, with no reward settlement. One legitimate no-battle branch finishes and survives storage restore. A separate five-party mechanism lane enters the four newly supported parties, each with natural defeat and fixed-entry retry; the fifth remains blocked. Conditions not drawn before defeat are not claimed as executed.

Continuous Session fixtures independently cover all four conditions through victory, one reward publication, storage restoration, a subsequent battle, Doom defeat and retry. These are controlled mechanism checks, not source victories or mainline reachability. The final same-runtime source receipts, compiler/native packets and controlled app report are byte-preserved in ignored `build/reports/v100/artifacts/`; their scope and hashes are indexed by `build/reports/v100-validation-summary.json`. Real-browser, original-game and full-campaign acceptance remain incomplete.
