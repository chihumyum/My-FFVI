# Shared resource absorption family

The exact source census retains all 1,530 ability rows (523 existing bounded
plans), all 474 AI master rows (423 bound bodies and 51 missing bodies), 4,299
explicit AI ability references, all 53 battle programs / 2,312 operations and
63 scripted BattleAction sites / 36 ability identities (33 with prior plans).
The 211 learning rows and 34 character potential directories remain references,
not owned abilities. No missing body is substituted.

The selected family is every source two-slot Function69 or Function77 followed
by Function13: 14 abilities, 67 references in 35 AI bodies and five learning
rows. Selection follows complete function types, operands and dependencies,
never ability identity or a script PC. Original raw rows, all companions and
unresolved source/actor/condition/phase dependencies remain in ignored audit.

Function69 uses the existing magic calculator and Function77 the existing
physical calculator. The primary clips its result to the caster's missing
resource; a full caster produces source HitType.Zero. Function13 value1=1/2
selects HP/MP with single-recipient, normal overflow. Its value3 selects the
source Chanting.ForAiType. Normal return is clipped to the target's prior
resource. These values are not interchangeable. Unknown shapes remain blocked.
The native PrevCalc jump table and truncated AbsorptionFunction GC-barrier
output require original PE instructions, not the decompiler's early return.

The typed plan retains a primary numerical slot and one absorb-resource slot.
A joint pure action projection returns both the target's paid resource and the
caster's detached resource draft. BattleGame publishes those drafts with the
existing payment, target identities, random stream, reaction AI and conditions
in the same transaction. Caster recovery is not another hit on that caster.
Ordinary menu, enemy AI, scripted and derived actions use this common path;
no second queue, resource owner or persistent battle save is introduced.

Undead/reverse recovery, Soul Saber equipment carriers, other resource selectors,
unknown active conditions and incomplete trait/equipment providers retain
specific hard gates. The existing owned provider must positively establish a
non-reversing context; a missing provider is not false. Current resource bounds,
self targeting and single-target scope are validated before calculation.

An explicit Web declaration binds the original effect/sound rows while deferring
native graphics and audio. Existing 400/900 ms action stages provide the
continuation policy; they are not native completion timing. UI shows actual
resource results and bars without inventing source beams. Stable Storage uses
the existing settled field return transaction; active battles remain unsaveable.

Acceptance separates complete source dependency auditing, controlled actual
source operands/Session transactions, native static evidence, App/BattleView,
and original story execution. Compiler plan counts do not certify playable
abilities, source scenes, opening/ending or native dynamic parity. The parent
owns the subsequent one candidate world compilation/publication.

(523 → 537), loses no previous plan and changes no unrelated plan. It retains

owners, RNG and VM state before a single retry. Self-target HP settles life only
after both slots, so an intermediate zero-resource draft cannot add death.
Static proof retains 13 newly exported methods / 13,360 PE bytes, two cached
provider methods, original aliases and the jump-table/GC-barrier corrections.
No original story program, world producer, browser raster or native dynamic
