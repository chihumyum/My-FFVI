# 系统集成 v31

本批将来源新游戏交接接入共用游戏会话：初始持有状态、PointIn、实际玩家与 puppet、镜头、渐变和字幕使用现有系统的唯一所有者。开发纳尔谢入口保留为既有回归。完整开场、完整 Web 迁移与原版动态一致性尚未完成；HD-2D 未启动。

## 新游戏与状态所有权

`GameSession.prepareNewGame` 通过来源初始化定义建立 `GameState`，不读取纳尔谢开发检查点的剧情与魔导状态种子。跨作用域的 battle、world、map 和新游戏包分别核对摘要，不能改写来源指纹使它们表面一致。标题全局渐变经真实协议交给字段；资源、场景与字段准备完成后，reserved script 优先启动，普通地图 initializer 不能先运行。

owned v8 增加明确的 `initialization` 及 `nativeState`。后者保留来源初始交通、停泊、仓库、关键词、魔法、魔石与计数器等元数据；`entrySeed` 是加载前的来源证据，不是另一份当前地图、玩家或交通状态。尚未接入更新系统的字段只允许原始初值，不能捏造统计更新。完整持有名册到原生脚本编号、三组队伍与 condition type 的投影从当前所有者读取。

55 个来源演员直接安装在同一个 `FieldGame.actors` 中；原生坐标、方向、层、动画和显隐通过这些对象的原生实体状态投影。实际玩家与脚本 `-1001` 的 puppet 别名分离，camera dummy 仍由独立镜头所有者持有。安装先验证全部媒体、别名和居民绑定，失败不替换原玩家；后续生命周期失败也不发布半套角色与剧情局部变量。

地图碰撞、实体碰撞和交互观察开关分别进入实际走格与触发器消费者。新游戏路径不能静默退回旧演员系统：原生演员切图、队伍刷新和稳定保存继续明确阻塞。外层 `GameSession.restore` 拒绝把来源新游戏 owned 状态拼入旧开发世界存档，避免借旧格式绕过原生演员保存门禁。

## 字幕与背景提供器

普通异步 `NoWindow` 字幕有唯一消息状态，支持已确认的单页、中心标签、页末等待和自动输入分支。第一页在消息更新后整页出现，消息内部等待不阻塞剧情解释器。播放将实体更新组设为 mask 9，关闭恢复 mask 3；本批工厂演员的 attribute 2 因而暂停动画与移动，镜头、图块、渐变和解释器继续。窗口仍保留文字时不能保存。字体和排版是明确受限的 Web 表现，完整自动换行及其他消息管理器保持未迁移；见 [字幕](source-messages.md)。

来源 FarBG 通过独立媒体适配器保存 sprite、texture、prefab 和 shader 的文件摘要及十进制对象 ID。普通完整中心纹理 repeat 分支编译为可重用背景定义，投影产生 Canvas 采样片段；不是按地图名称手写的视差效果。几何编译仅消费已准入的根图层，其他活跃背景、边框、自动滚动、前景和自定义 shader 仍保留阻塞。来源材质输入、Canvas 绘制与原版 GPU 一致性分别记证。

背景滚动使用剧情镜头位置，而采样网格使用来源独立渲染相机及 renderer 根位置。普通新建宿主的两者原点由 level0 的 CameraTileMap 与场景 MapRenderer 父链分别绑定，不能把正在移动的剧情镜头当成背景渲染相机；见 [背景来源与投影](field-background.md)。

## 验证与接续

运行 profile 为 `narshe-playability-v31`；owned v8，field/world v8、session v3，camera v2。当前阶段不支持旧版本存档迁移。

合成回归覆盖完整标题协议与新游戏会话交接、reserved 优先、无开发状态注入、来源/准备失败回滚、混合来源存档拒绝，以及字幕期间角色暂停而镜头、渐变、VM 继续的真实宿主行为。真实来源、浏览器和原版运行是独立验收层；原生回执的 `semanticsVerified=false` 不会因自动测试通过而改变。

最终验证：`npm run check` 的 1169 项 TypeScript 测试与登记契约、22 项 Python 测试、86 条来源检查命令全部通过。真实内容重编后，来源会话检查核对 4 个包、55 个演员与 3 个持有人；10 ms 固定步长和受控音频就绪条件下，执行至 11,020 ms，记录 4 次消息状态变化与 8 个镜头/渐变里程点。这些是共用系统与已准入分支的检查，不是全游戏验收通过。

浏览器实测两条路径：旧纳尔谢片段完成守卫对白、首战、96 EXP / 96 Gil / 一件恢复药的奖励、返回地图及继续移动；新的来源入口实际显示开场字幕、渐入画面和移动镜头，随后渐黑并在 `sc_e_0001` 的指令 18 停止。两条路径控制台均无警告或错误。本批没有读写用户的浏览器存档，未操作原有进度标签页。字幕字形与排版、GPU 材质和原版时序仍没有动态对照。

第一个明确缺口是向目标 0 施加 condition 607：当前队伍刷新会要求字段渲染器尚未支持的非零镜头偏移，因而事务拒绝提交；三名角色的 condition 仍为空，没有跳过指令或回填开发魔导状态。后续指令 19 的切图尚未执行。来源新游戏路径不能宣称已贯通到纳尔谢首战。

本批命令回执、内容摘要、浏览器截图与停止位置记录在本地 `build/reports/systems-v31-validation.json`。接续先补齐魔导状态引起的角色/镜头刷新，再完成来源演员跨地图工厂、生命周期与稳定保存，将已有战斗系统接到连续新游戏流程；不能用静态图层或指令计数替代可玩进度。
