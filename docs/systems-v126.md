# v126 全源调度与完整剧情验收

本轮调整工作单位和共用接口。任务从全量来源的共同依赖提名，开场首个报错只作为回归观测。设计与操作入口见[全源迁移](global-source-migration.md)和[完整剧情批次](source-story-batch.md)。

全源计划重新核验冻结 v125 的完整来源、649图候选、技能目录和原490／步行492请求战斗审计。3,304个程序、186,003条指令全部保留，包括2,804份Field、53份Battle、430份AI与17份未归类程序。实际工作集有798组缺口、79,804个指令或依赖定位及106,517条原始观测。原始正文与报告保留在ignored输出。

调度区分完整地图、独立程序和全局目录。每波按不同owner并行，最多为同一owner提名三个互补缺口，并公平轮转。含未知的地图仍能安排已知工作；其潜在准备度与严格依赖闭合分列。665组可安排，133组未知或循环依赖继续保留。当前649张地图没有因此获得严格闭合或剧情完成资格；1,150个结构cohort均没有完整故事合同。

`field-runtime-ports`集中分类会话、入口、地图准备与恢复的端口。真实host保持身份，缺失仍缺失；地图草稿、效果租约与路线策略由原owner组装。`sourceStoryExecution`只提供显式可选、有限的执行记录，不写入存档、不改变游戏推进。完整批次沿用现有Session、Flow、地图、战斗和Storage，核对正常Main、实际分支、入口／出口状态、必要战斗和真实检查点续行。未发布候选不会成为到达证据。

合并后核心回归4,838项通过；随后调度评分修正的最终25项联合测试、类型检查、32个实际app受控DOM／Canvas案例及47项入口案例通过。完整全源CLI运行通过，未生产或发布另一份世界内容。两个相接的合成剧情route与四次战斗往返只验证验收机制，实际完整来源剧情批次数仍为0。

v125的八组来源观察已全部终端：七组退出0，战斗共用观察因误把builder的payload Map传入纯数据快照而失败。新代码只传入其真实定义数据，保留原快照守卫；该失败结果不改写为通过，来源重放留到下一次统一候选。

下一轮按完整来源族并行推进字段UI、HP基础魔法公式和装备命令。解码数、假设准备度、受控机制测试及实际剧情贯通分别记录。真实新游戏仍未到结局，浏览器和原版动态对照未验收；完整Web迁移goal保持active，HD-2D继续后置。
