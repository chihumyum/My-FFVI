# FFVI Web 迁移与重制架构

## 目标与基线

建立能够持续理解、迁移和重制 FFVI 的本地工程。纳尔谢验证游戏行为与内容通用性，歌剧短片段验证现有二维与三维混合演出的转换；随后由陌生同类地图验证复用能力。

基线是用户提供的 Pixel Remaster 文件。已观察到 Unity 2019.4.20f1、IL2CPP 元数据和原生 GameAssembly、Addressables 索引、地图与事件 JSON、主数据 CSV。Unity 版本不代表游戏补丁版本。原版已可通过 Mac 兼容层运行；正式行为采样按用户指示后置。

优先级为正确性、清晰所有权、可重复生产，然后才是覆盖率和速度。完整迁移、表现重制和用户扩展分别记录状态。不会以能显示画面代替游戏正确，也不会以提取成功代替语义恢复。

执行上严格串行：原版 Web 迁移 → 全游戏迁移放行 → HD-2D 调查 → HD-2D 制作 → 用户扩展。纳尔谢或歌剧单个样本通过只授权扩大迁移批次，不能触发重制研究。现有歌剧材质、镜头及效果只在复现原版所需范围内恢复；是否能够推广为重制标准留到迁移放行之后。

## 数据流和所有权

当前优先搭建 [游戏系统框架](game-framework.md)：浏览器通过 `GameFlow` 管理标题、暂停、异步准备和会话发布，通过 `GameContentRepository` 装载内容；实际游戏状态仍由既有 `GameSession`、`WorldSession`、`GameState` 和 `BattleGame` 持有。精细表现恢复暂缓，先验证连续游玩与内容接入边界。

| 层       | 输入与输出                                        | 所有权                               |
| -------- | ------------------------------------------------- | ------------------------------------ |
| 来源适配 | 原始文件 → 带指纹的对象、表、引用                 | Unity 格式、64 位 ID、原始坐标与参数 |
| 内容编译 | 原始对象与审核标注 → 版本化内容包                 | 类型、稳定 ID、依赖闭包、诊断        |
| 世界知识 | 来源证据与审核 → 有适用条件的事实和关系           | 地点身份、剧情状态、矛盾与未知       |
| 游戏内核 | 内容包、输入、时间及外部完成信号 → 状态与表现命令 | 战斗、事件、队伍、随机数、保存状态   |
| 表现系统 | 状态投影与演出包 → 画面声音                       | 二维参考、HD-2D、镜头、材质、动画    |
| 重制工具 | 地图语义、资产库、规则、配方 → 场景包             | 空间标注、资源匹配、变体与派生       |
| 验收     | 原版观测与候选运行 → 独立结果                     | 证据范围、差异、缺口与放行           |

来源依赖只存在于适配层；内核和表现均不读取 Unity 私有结构。知识记录和内容包共享来源身份，但知识中的推断不能自动改变内核行为。首版采用一个仓库、直接模块依赖和本地 JSON 产物，不建立服务分布或通用游戏引擎框架。

当前地图生产链为 `export_world_media → compileMapGeometry/compileWorld → WorldSession → browser`。649 条地图记录使用同一编译器。WorldSession 拥有当前 FieldGame 和切图提交；GameState 拥有会话中的角色、库存与奖励记录；GameSession 协调独立战斗副本和返回事件；浏览器仅负责取包、摘要检查、媒体加载和表现。地图、实体和脚本提供数据，不向运行时添加地图名或坐标分支。异步准备与提交分离，旧请求、变化的剧情状态或更换后的目录不能覆盖当前会话。具体边界见 [地图生命周期](map-lifecycle.md)、[共享游戏状态](shared-game-state.md)。

当前系统批次为 v47：显式 Web 事件保存已接入唯一会话、世界、任务续行、持久化与浏览器。异步编码期间冻结进度；失败保留请求并可重试，写盘成功只确认保存，下一逻辑帧再继续事件。读档恢复调用栈、局部变量别名及入口生命周期，不重放保存前的奖励；旧空闲存档继续可读。此协议不冒充原版 AutoSave。下一步用明确内容批次建立系统依赖准入与连续路线检查，不追逐开场的下一条演出缺口。见 [v47 事件保存与续行](systems-v47.md)、[v46 独立入口](systems-v46.md)。

地图局部 NPC 保留独立来源资源身份；切图候选只带走常驻演员，但过期检查覆盖即将退休的 NPC。效果板拥有单独的状态集合，不冒充角色或复制其显隐状态。`GameState` 将完整持有名册与三组四格编队分开保存；格子保留成员身份、前后排和空位，当前队由 `selectedSlot` 选择。库存、编队、角色生命周期与地图步行效果使用同一个 `prepareFieldState` 候选草稿及草稿版本号，不能分别提交而覆盖彼此。外观准备读取候选成员身份；媒体、来源上下文或后续准备失败时，角色与字段状态整体回滚。地图发布前只写草稿，成功后端口都转向当前所有者；初始化期间已开始的移动允许在发布后完成一次，其他状态变化仍会使旧准备失效。

## 内容与身份契约

每个产物包含格式版本、源集合指纹、转换器版本和内容摘要。证据使用源文件 SHA-256、容器内路径、对象 ID 或表行定位。Unity signed 64-bit path ID 必须序列化为十进制字符串；文件 ID 与 path ID 共同构成引用，跨资源包引用不能误当成本地对象。

解析结果保留原始指令与所有参数。类型化指令转换必须说明语义依据、支持的参数形态和时序规则。读取到指令名称只产生待实现的能力需求。`SysCall` 必须细分选择器；未知选择器、动态跳转或无法解析的引用保持阻塞，不能跳过。

编译结果分为检查包和可运行包。检查包可容纳带位置的未知项，供研究工作台浏览；可运行包需要目标的所有必要能力、依赖、状态条件与验收闭合。检查包不能伪装成游戏构建。按用户当前可玩优先指示，另允许显式的 development profile：逐项记录临时规则与未实现能力、可独立运行实玩，但不能视为已验收迁移包。首战 profile 见 [可玩开发规则](battle-playability.md)。

## 内核与时间

内核拥有逻辑时间、随机状态、实体与地图状态、剧情标记、队伍和库存，以及事件任务的程序计数器、调用栈、等待原因和生命周期。输入按已定义的顺序推进。动画、声音、用户输入等外部完成信号必须可记录、重放，并与发出命令的任务身份关联，避免切图后旧回调推进新任务。

等待时间的单位、暂停与加速影响、并发任务顺序、数值舍入与溢出均以该版本证据为准。新的确定性调度器测试不能证明原版调度一致。随机对照需要原版状态或记录的随机输入；不可控样本不能标记逐次结果相等。

战斗普通队列和优先反击队列均由内核拥有。动作先计算目标状态，再以暂存结果运行来源反应 AI；费用、效果、敌人变量、AI 进度、队列和随机流构成一次提交，失败不会留下部分伤害或半组反应。反击完成不释放普通回合。当前仍是有明确限制的开发调度，见 [普通反击](battle-reactions.md)；不得把基础反击完成视为全部战斗生命周期完成。

道具内容 ID、物品行 ID 与能力 ID 分开保存，菜单/战斗函数组分别编译。行动保留能力或物品载体，复用纯效果投影；数量由 `GameState` 独占，菜单将效果与扣量一起提交，战斗借用库存副本并按队列预订，成功动作只消费一次，胜利再与角色和奖励一起归还。失败重试回到入场副本。当前准入普通固定 HP/MP 恢复、玩家复活与解除已支持状态，目标仍限我方；计划已编译不代表所有被引用状态都能实际运行。敌方物品反应和特殊品仍阻塞，见 [道具动作](item-actions.md)、[状态道具](item-status.md)。

来源物品和装备取得通过共享库存事务进入菜单与战斗。装备总持有数包含已穿戴副本及来源空件；实体空闲数从完整名册中 enabled 成员的六槽占用推导，空件 Count 只约束新选择、不作为登记数量预算；取得装备不自动开放未恢复的穿戴效果。普通换装重新确认十一项参数、所用武器手的物理值及元素，耐力采用当前来源的分阶段上限；每个参数只有一套共用计算，见 [装备](equipment.md)、[属性确认](character-parameters.md)。

存档格式有版本，需覆盖逻辑状态与可恢复的事件状态。原版存档导入是单独适配器与验收项目。游戏逻辑只依赖稳定的区域、实体和触发器身份；HD-2D 模型位置与逻辑入口的绑定由场景检查器验证。

当前 `GameState` 使用 `owned-game-state` 版本 10 保存名册、三组编队、库存、奖励及来源能力/历史/名称标签、成长和交通停车状态，`GameSession` 将它组合为 `game-checkpoint-v4`，包含剧情变量、世界/字段状态、音画进度、遭遇序号和即时/等待及速度偏好。字段与世界检查点均为 `idle-*-v10`，保存独立交通身份、演员外观、来源入口同步状态、演示组件上下文、渐变及有明确宿主的摄像机状态；活动演示 fader 不进入稳定存档；恢复须验证来源身份、内外层资产、交通 owned 记录及 release flag，不能用存档自报的值绕过规则。浏览器持久化保留当前与上一份进度，恢复先验证来源及依赖，在候选会话中重建，再发布；不重跑地图初始化。只允许稳定地图状态保存，活动执行器恢复、版本迁移及原版保存规则仍待接入，见 [检查点存档](checkpoint-saves.md)。战斗开始保留入场副本，重试重用它；胜利先验证全部成长与地图后继，再一次性发布共享状态并排入后继事件。

普通角色的来源初始化与成长提供器已连接共享名册；当前编译 18 条初始化与 18 份成长计划，另 16 条初始化明确阻塞。正式初始持有人仍为 1/31/32；source 2 的受控加入验证得到 Lv5、EXP400、HP48/max102，不改变正式初始队伍。自然等级学习随成长更新持有能力，不追加全局取得历史。菜单与装备操作按自身依赖准入，持有能力与可执行战斗能力分别校验；完整来源技能定义已独立编译，已为通过依赖检查的技能生成有界宿主计划；其余学习、特殊能力和角色提供器仍未完成。当前队内排序与前后排已接入菜单、地图演员、入战和保存；战斗换列经效果阶段更新并在胜利返场时提交，空队入战保持显式阻塞。

`FieldPartyActors` 使用完整候选成员和明确的 leader、puppet、状态替身、companion、多队伍、交通及摄像机上下文准备外观。来源资产 ID 与 Web 实体 ID 分开，骑乘外层与角色内层分别保存；隐藏原生实例保留状态，不凭空生成渲染位置。正式开场已恢复 outer38、inner1/31/31，骑乘队长刷新、保存与缺失媒体回滚已通过；普通来源 `MapSetup/PointIn` 已在 v20 接入；其他分支仍需各自提供器。恢复角色时还须读取当前脚本的 `KeepBadStatusVisual`：仅显式 false 准入，无标志或 true 保持阻塞。恢复隐含的刷新使用 `setDummy=false`；外层指令明确要求刷新时，最终刷新保留 `setDummy=true`。详见 [编队演员](party-actors.md)。

普通毒的地图伤害在玩家移动开始时准备、完成后且目的地事件前提交。交通身份独立于坐骑画面；旧开发检查点显式绑定 `currentTransport=6`，因此不走普通毒步伤。真实来源新游戏在 condition607 后直接请求 609→3；该条件不会自行选择交通6或装甲资源，不能把旧开发检查点的路线解释套到新游戏。受控已知交通身份仍用于验证通用步伤，其他交通切换不能套用开场结论。WAIT 偏好由会话保存，技能/道具列表和目标页向内核发布 UI 等待，基本命令页继续推进；渲染层不持有时钟规则。

## 世界知识与语义资产

地理身份、世界阶段、剧情标记、角色经历和地点局部状态是不同维度。同一地点允许多地图表示、多剧情版本和多个物理资产；相同图片不意味着同一个地点或可跨时期复用。状态未知不等于默认早期状态。

知识采用结构化事实、证据记录、适用条件和矛盾集，并生成给 Agent 阅读的上下文包。摘要可随时重建，不能成为脱离来源的第二套事实。详见 [世界知识](world-knowledge.md)。

## 两种表现与已有歌剧资产

二维参考表现验证转换和基础投影；HD-2D 使用同一逻辑世界。两者共享内核，彼此一致不能作为内核正确的独立证据。

歌剧的对象层级、正交/透视摄像机、动画/音频/启用轨先提取为来源对象图，再按明确支持的子集编译为 SceneIR/CutsceneIR。保留音频时间、轨道绑定、父子变换和自定义后处理需求。Unity 着色器与 OperaPostProcess 需要单独实现；读取参数不是实现完成。

固定镜头的舞台布景与可探索场景分别验收。镜头外的平面和遮挡可能不适合自由移动，不能直接据此推断全方向几何完整。

## 批次推进

一个批次由相连地图、剧情入口/出口状态、事件/战斗/音频依赖构成。计算必要能力闭包与共享资产影响范围；静态未知项与动态依赖都保留。通过同类样本和陌生留出地图后，再扩展该能力集合内的区域。飞空艇、多队伍、特殊演出等作为明确能力增量。

源集合、知识修订、资产版本、配方和工具版本全部固定。相同输入产生相同内容摘要。共享资产升级先生成受影响场景及差异，再成批升级依赖；不在运行时悄悄追随 latest。

## Agent 的研究边界

REA 的证据追踪与局部重构方法用于原生行为研究；UnityPy 用于资源格式；IL2CPP 类型/地址映射需要专用工具。REA 当前 managed-code 模块不解析 IL2CPP 元数据。研究任务以明确问题、证据位置、未定项和验证样例交付。

参考：本地 `~/Downloads/rea`，研究时版本 `f9ce32b4749026d3b6c05b8880f5549967cdb6ad`；[REA](https://github.com/morluto/rea)、[UnityPy](https://github.com/K0lb3/UnityPy)、[Il2CppDumper](https://github.com/Perfare/Il2CppDumper)。外部工具能力不构成本游戏已验证覆盖。

宝箱按来源任务分阶段提交：库存发奖在消息之前，领取标记在消息完成之后。活动任务禁止稳定保存；并发入战和切图不得丢弃尚未结束的宝箱任务。普通脚本宝箱只注册独立事件，不替脚本额外发奖。系统文案通过同源快照绑定后传入所有地图编译，不能依赖来源探针额外补入文案。参见 [宝箱任务](treasure-task.md)。

普通角色的潜在战斗定义与持有角色分开保存。定义携带来源资格与普通外观要求；入口和战斗构造器共同拒绝不满足要求的模板，不把空动作列表作为静态菜单回退。row53/type607 已定位到片头字段 AddCondition，v22 已接通持有、状态表现与来源开场菜单；v23 的技能定义扩充仍不授予能力，参见 [普通战斗模板](player-battle.md)、[入战来源](battle-entry.md)。

真正新游戏使用内容绑定的 `GameState.createNewGame` 创建共享所有者，复用来源模板、成长与完整初始 Count，不注入纳尔谢开发检查点的魔导条件。它已与事件存储、交通初值、55个常驻演员、镜头、标题渐变和首段字幕形成同一来源会话；完整开场仍等待后续地图粒子、合成、骑乘与事件能力闭合。广告 probe 只消费会话供应的显式组件上下文；不以缺 Web UI 推断 absent，不从剧情 flag 反推该组件。跨图候选保留上下文，未提交时禁止标题副作用，过期候选不能覆盖新状态。
