# v56：多阶段战斗与敌队整体生命周期

本批将完整敌队换轮接入游戏骨架。根脚本、玩家、共享剧情草稿、库存、随机流与原战斗 lease 持续存在，旧敌队退休后新队使用独立实例，最后一次结算与返场。不会因更换敌队重新执行地图事件、战斗 root 或领取中间奖励。

## 同一战斗所有者

`BattleParticipantState` 新增整体换队投影：先检查全部成员、原始槽位和实例分配范围，再将当前敌人全部退休，按来源成员顺序分配新 ID。相同怪物重复出现或相同槽位换轮不会重用旧行动身份。完整历史与原死亡掉落登记保留，EXP/Gil 范围仍由明确的 Web 策略决定。

`BattleGame` 在原帧事务中准备完整新敌队、所有 AI、条件计时器与随机初值，再发布。单槽加入与整体换队共用模板准备和退休清理。旧敌人的普通/中断行动退出队列；正在表现的行动若引用旧 actor/target 则取消，未开始的单体旧目标执行时失效。新 AI 看到完整新 roster。玩家保持原对象、HP/MP、成长与行为状态；正在执行动作的取消仍按既有完成规则处理 ATB。

切换保留原根 PC、栈和局部银行。请求在同一 PC 等待加入完成，同一时钟不重复执行；下一个时钟完成后续行。这个完成信号独立于当前执行器是否有动作。新队启动 AI 后保留原 no-act/更新许可，根脚本的 `SyncAI` 在结束轮 → 活跃新轮的变化中恢复进度，根时钟不会被进度暂停禁住。

原路径按条件 **type 506** 清除玩家状态，不能误作 conditionId 506；本表对应 row60。核心按冻结的类型表筛选当前条件。row60 的完整活动行为仍未准入，因此此清理操作不意味着新增该状态的来源能力。

帧回滚同时恢复原 combatants 数组和成员对象、队列/当前动作、AI、历史、生成序号、当前敌队 ID、布局、隐藏集合、条件时钟、根状态与随机流。第二个新单位失败或发布后的观察故障都不能留下第一单位或半个敌队。战败重试复用 v55 固定的完整入战合同，重新从初始敌队开始；所有换轮计划也固定。

## 内容闭包与显示

`participants.enemyParties` 保存来源 enemy partyId → 成员与布局。成员使用怪物 ID 和原始 1 基槽位，实际实例 ID 由宿主分配。当前布局随换轮切换；后续单槽加入读取当前布局。尚未做阶段控制流分析时，混合 root 的加入槽位必须在初始与所有选定轮次均显式存在，缺布局按原 PC 阻塞，不猜空槽坐标。

初始敌人、增援和换轮成员复用同一个模板编译器及 AI、技能、条件、媒体、掉落闭包。编译输入按目标 root 选择来源子敌队；源指纹、元数据、flags、子脚本和背景等原始记录保留在 `encounterReport.enemyPartySources`。Web 的形成、背景、逃跑/奖励策略暂留父战斗，差异明确列为开发策略；子 flags 或 root 的适用语义未闭合则继续阻塞，不能隐含丢弃。

隐藏标记由同一个 `BattleGame` 投影，renderer 读取它决定显示。逻辑单位和目标资格不另建一份，玩家可见性不受敌队隐藏影响。控制样本中后续单槽加入建立可见新实例，这是显式 Web 显示策略，尚未验证与原生隐藏父对象的全部消费者一致。

三个准确 selector 映射到 513/514/515，hide 为 false/false/true；来源 `sc_b_2022` 原 PC32/53/72 已保留原操作数验证。[来源合同](battle-party-transition-source.md) 记录 4 份 C 回执、27 个原始区间、7 项静态检查和 5 个来源 PC。

真实三队含 7 个成员，Power/Tiger/Machine/Magic/Rest/Lady/Kefka 的布局、AI 与能力来源已记录。特殊终末/循环/目标行动、flags/元数据的完整消费者以及根脚本内的玩家换队、音画和显示指令仍缺失。这些真实敌队没有被声明为可玩。53 个完整战斗程序仍有 52 个保留其他指令缺口。

`BattleAddFellow` 的入口已确认借用已有 owned 克隆，通过 source characterStatusId 查找、将其 owned Id 放入战斗空格。true 包含尚未启用编队的已有记录，不代表可创建任何来源角色。实际两个站点 33 和 1 未被替换为其他已有玩家。下一项公共能力需要统一角色借用、战斗实例/槽位与持有 ID，以及加入、退出、换组、战后回写和固定重试；原生结算回写范围仍待独立证明，本批不实现假玩家。
