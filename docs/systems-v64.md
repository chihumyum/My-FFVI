# v64 统一游戏入口与用户命令

本批按“游戏骨架优先”整理应用层的系统接缝。新游戏和读档复用同一准备、发布、取消合同；道具、装备、编队、商店、战斗和偏好输入复用同一会话命令入口。没有新增地图名、遭遇 ID 分支或第二份游戏状态，没有扩大来源机制准入。

## 所有权与接入

| 模块 | 职责 | 后续内容如何接入 |
| --- | --- | --- |
| `GameContentRepository` | 校验包身份、来源、摘要和依赖；返回分离的数据 | 编译到既有内容合同，保留未知依赖 |
| `GameEntryLoader` | 在原 `GameFlow` ticket 下准备和发布一个会话；取消回收未发布表现 | 来源新游戏、开发入口和检查点恢复使用相同候选结构 |
| `GameFlow` | 标题、暂停、I/O 仲裁和宿主就绪事实；不持有角色或库存副本 | 宿主报告可见性和媒体就绪，不复制游戏时钟 |
| `GameCommands` | 按准确 owner、阶段及宿主资格分派用户操作 | 菜单、商店和战斗 UI 传入内容参数，不直接改持有状态 |
| `GameSession` / `GameState` | 剧情、持有状态、战斗借用、成长与结果提交 | 既有字段、战斗和存档事务继续唯一持有数据 |
| `GameMapLoader` / `GameBattleHandoff` | 地图和战斗候选的准备、提交、失败重试 | 复用现有请求和 lease；入口整理不重建这些事务 |

## 系统合同

- 开发入口与检查点读取用 `attempt.prepare`；原来源新游戏保留其 fade 和帧驱动 launch，以 `attempt.commit` 进入同一发布边界。加载失败保留旧会话、暂停状态与存档；取消后的迟到候选只回收自身资源。
- 表现候选发布后交给 app 绑定。绑定异常是已发布会话的 fatal 错误，不被包装成可重放准备，不能重新发布或重复结算。
- 命令通道固定绑定 `GameSession`。暂停菜单使用单独的菜单资格；商店和战斗使用对应阶段资格。标题、I/O、后台、媒体未就绪和被替换的 owner 均拒绝用户 mutation。
- 战斗命令另外携带准确 `BattleGame` 实例，旧重试实例不能提交到新战斗。时钟投影仍是表现端口，允许清理等待状态，不冒充用户指令。
- 编队包含演员准备；最终提交再次检查命令资格，准备过程中发生会话切换或返回标题时不发布旧编队及演员。
- app 的五个用户操作视图在发布会话时绑定同一通道。保留的旧按钮不通过 `this.session` 转向新 owner。可见性变化立即撤销宿主就绪，回到前台后由新一帧重新确认。
