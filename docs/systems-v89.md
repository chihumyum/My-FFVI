# v89 完整批次的 NPC 活动系统

本次能力由南费加罗完整区域工作单选出：56张地图、135个入口中的36个 Area NPC，分布于14张地图。基础骨架已关闭，六组系统和七条代表流程保持原范围。本次交付是这批内容共同依赖的活动、碰撞、交互接管、保存恢复和地图退休合同，不以单个角色或场景作为实现单位。

## 来源与 Web 策略

`field-npc-activity` 编译器保存每个原对象、属性、mapobject行、地图范围、Area引用和来源摘要。缺失、冲突或无法派生的记录留在整批报告中。原始NPC定义、实体组、脚本、对白及blocked/conditional诊断不被替换；v4配方只附加独立的控制器sidecar和开发策略。

来源速度、等待间隔、步数和世界坐标矩形使用已保留的原程序证据。特殊速度ID15转换为枚举7，NPC速度表不扩大Puppet Move指令的准入。Area北边界为y，范围两端包含，不能以普通Tiled格子矩形代替。13个省略首次等待属性的对象采用明确的`source-ctor-true`解释，通用原属性解析器的缺口仍记录。

`framework-npc-area-v1`明确选择每演员Web随机流、固定步长来源顺序、格子预留碰撞及暂停并保留运动的接管策略。初始额外等待由定义摘要稳定派生，普通停止/朝向使用现有共同演员动画。这些选择不声称复现Unity Random、Guid调度、原raycast或完整原idling/PauseMove视觉行为。Polyline、Route、AssignMoveRoute和离开Area后自动寻路均没有被授予能力。

原`pushed`字段保留；本策略通过占格和运动预留阻挡玩家，没有新增玩家推动NPC的原物理行为。

## 同一演员与生命周期

运行时仍只有`FieldGame.actors`和它的`Actor.motion`拥有位置和插值。控制器持有定义、等待、随机流、命令票和精确演员/运动引用，不创建第二份可变坐标。新运动先准备碰撞、媒体和控制器候选，再共同发布。玩家及其他NPC使用既有碰撞网格；活动NPC预留起止格，竞争者按实体组/对象插入顺序推进，避免JavaScript数字键重新排序。

普通Talk及NPC脚本接管同一运动，保存其已进行时间并暂停演员更新。正常退出生成新票并续行旧运动；旧票、旧实例或已替换运动无法完成命令。玩家根消息按原更新属性暂停NPC，不冒充NPC交互接管。失败的媒体准备不能改变方向、动画、运动或随机流。

菜单和稳定保存允许准确受控的后台运动。新`idle-field-v12`/`event-field-v3`保存控制器元数据，与原生演员v2的单一运动寄存器共同校验。恢复使用当前可信定义、精确活动域和运动方向/命令关联，重新绑定世代与票，不调用Init、不再抽样。旧Wait和既有v10/v11/事件v1/v2格式继续保留原形。

`WorldSession`为候选及当前场景提供准确实例计时权限。未发布、废弃或退休地图不能推进活动；切图失败/取消保留原owner，重试创建新实例。战斗期间原场景运动冻结，奖励和返场仍使用现有`GameSession`、`GameFlow`及持有状态。

## 验收边界

连续受控会话覆盖真实公共入口、命令、碰撞、普通交互、消息暂停、菜单、Storage、加载恢复、切图失败/取消/迟到/重试和准备好的战斗往返。夹具在启动前编译封装，不改实时会话来制造通过。

来源检查重新派生完整36个定义并核对最终同一候选的sidecar。map38和219既有显示宿主阻塞占15个NPC，仍不具备真实部署提供器；其余实例的共同factory和真实参数控制实验另留证。原5条对白阻塞、其余事件及剧情可达性诊断继续存在。运行规则通过与来源剧情通关、实际浏览器和原版动态一致性分别验收。

最终证据统一记录在本地`build/reports/v89-validation-summary.json`。公共包使用一个候选、一次发布，保留完整旧JSON/媒体归档及旧进度续行。完整Web迁移目标继续active，HD-2D后置。
