# v19 角色成长、队伍外观与交通状态集成

2026-10-11。当前开发配置为 `narshe-playability-v19`，持有状态 v6，字段/世界检查点 v3，外层会话检查点仍为 v2。系统优先，完整 Web 迁移仍未完成；没有新增剧情区域，也未开始 HD-2D。

## 共享系统

普通初始化与成长目录均覆盖 18 条来源角色，另 16 条初始化保留明确阻塞。目录可用不授予角色：正式开场仍只有来源 1、31、32。首次加入、职业释放、名称标签、能力取得历史、装备登记、追加经验与成长在同一份候选状态中完成；后续任何依赖失败都会丢弃整份候选。菜单与装备使用持有参数，不要求先有战斗定义。

来源 `CorrectLevel` 写入追加经验，再由来源经验表计算等级。不能把目标等级直接写入角色。受控洛克首次加入得到 ownedId 4、Lv 5、400 EXP、48/102 HP、7/33 MP；没有恢复请求时不会随着最大值增加而补满资源。自然等级学习更新持有能力，不追加来源全局取得历史。全局历史仍按 owner 的原生取得顺序包含初始未学会条目。

胜利投影和持久提交使用同一成长提供器，校验实际经验分配、已执行能力观察记录及计算后的等级/上限。未获经验的死亡角色只走观察学习检查，不能按零经验调用完整升级分支。当前尚未恢复的蓝魔法、装备/背景学习与魔石增益仍阻塞；不能把空观察日志作为隐含默认。详见 [成长与恢复](character-growth.md)。

快照 v6 保存追加经验与六项追加属性，恢复时重算合法等级、技能、装备后上限、名称和历史。新来源模板没有对应战斗定义时可以持有、使用已支持菜单道具和装备，但进入战斗会停止；本批不宣称新增 18 个可玩角色。

## 队伍刷新与恢复

来源目录保留 47 个字段资源、角色/职业映射的来源行顺序、条件居民、队长位置、三组队伍演员及内外骑乘资源。魏吉与比格斯在当前职业下都选择来源字段资源 31；相同图片名称不作为合并身份的理由。

开场上下文由来源初始化和 `609 → 572 → 3` 前导绑定。玩家与前三个脚本 puppet 的外层均为装甲资源 38，内层人物分别为 1/31/31；第四个空位保留 dummy 1。隐藏原生演员保存身份与资源，不捏造坐标或绑定到同名 Web NPC。

`FieldPartyActors` 从待提交的持有状态准备完整刷新，先验证资源/动画和原生上下文，再和队伍一起发布。已加载人物资源的骑乘队长切换保留外层装甲，仅替换内层；缺少洛克地图媒体的队长切换整体失败。隐藏演员与玩家画面、缓存、队长均进入字段检查点，恢复拒绝篡改外层装甲、丢失内层、改写隐藏身份、伪造每队队长及字符串资源 ID。

`FullRecovery` 即使原先没有条件也调用 `ChangeAssetPartyCharacter(false)`，随后执行 `AffectLeaderWithCondition`，最后才可能按外层请求再次执行 `ChangeAssetPartyCharacter(true)`。只有当前来源脚本明确 `SystemFlag.KeepBadStatusVisual=0` 时，额外视觉保留分支才可跳过；缺失或非零不能默认。当前字段在该条件和完整演员宿主均满足时支持已准入状态的恢复；`setDummy=false` 与普通完整刷新的 true 分开传递。详见 [演员来源与边界](party-actors.md)。

通用事件入口、companion、条件碰撞、非零相机偏移、上下车和跨地图 `MapSetup` 仍未完整恢复。正式带演员上下文的跨图请求明确停止，不复制旧地图演员状态冒充初始化完成。

## 交通身份

普通新游戏初始身份是 1，实际前导在地图 609 通过来源 `SetVehicle(6)` 与上魔导装甲 SysCall 写入身份 6，后续地图入口保留其 type 12 状态。当前纳尔谢开发入口因此使用独立的 `currentTransport=6`，不是从坐骑图片推断。该交通不执行普通毒步伤；受控交通 1 仍通过同一提供器产生每步 HP/32 损失。交通可用标记、地图入口选择与身份投影已有来源模块，完整交通事件/空间位置/碰撞与保存格式尚未接入。见 [交通状态](transportation.md)。
