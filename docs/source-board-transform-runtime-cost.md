# Source board transform runtime cost

This change reduces repeated validation and copying in the shared board motion path. It does not admit another source instruction, board, media type or presentation phase. The mutable public-content contract remains strict: every relevant entry still validates the complete current source policy, and every existing opaque lease/host boundary is followed by fresh checks before publication.

The full transform validator creates local indexes for map and raw-object membership inside each invocation. It still checks all map sources, raw objects, admitted bindings, exact source references, original properties, logical-media proofs and Birdview flat bindings. It retains no caller object or trust between calls.

A combined synchronous context/ref entry performs one complete policy validation plus the actual current map/entity, instance id, ref, definition and geometry checks. FieldGame captures lease callbacks and internal snapshots before that entry; it does not repeat the same full validation in the same callback-free interval. Subsequent lease checks and all opaque preparation/validation still trigger fresh full checks. The public standalone binding entry continues to validate its caller independently.

FieldEffects ordinary publication reuses its existing private catalog identity. Genuine candidate catalog replacement still clones and prepares the complete next catalog before the owned commit fence, then installs it only on successful publication. Public snapshots and host plans remain detached copies. The manager and disposable candidate derive private canonical comparison pins from their own catalog clones; every actual caller comparison still canonicalizes the complete current caller value. No external object is cached or frozen. Map media comparisons retain the original subset rule, and the standalone transform comparison retains its original scope. Encoding failures in otherwise unused media remain deferred until the existing comparison would use them.

Checks cover mutable policy changes between calls, exact current map/entity/definition/runtime matching, host mutation during prepare and validate, private copy isolation, candidate discard, failed owned publication, successful retry, media subset identity, and actual Session/Storage continuity. Existing transaction checks retain stale-generation, reentry, retirement, same-id recreation, late completion and host failure boundaries. Fallible copies and pin creation remain before owned publication; an opaque host commit failure is still terminal and cannot be described as rolled back.

Performance evidence uses a locked original source catalog with 649 map sources, 914 raw objects and 73 admitted bindings. The benchmark runs actual FieldGame, Puppet VM, clock and FieldEffects with the complete directory and original Lerp parameters, using a clearly controlled caller. Its 21 ten-millisecond updates are a prefix of a 117-second command. Exact state traces and source-catalog hashes must match before and after. This is not original-body execution or source-story reachability. Separate compiled-overlay ablations identify the initial indexing and private-publication contributions; they are diagnostic overlays, not independently compiled release candidates.

CPU and wall time are reported separately in the ignored family receipt. This first stage remains above the 10ms update budget and does not claim to solve source-game playability. A distinct reviewed immutable-source admission contract would be needed to remove full-directory rescans from the hot path. No such contract or policy version is granted here.
