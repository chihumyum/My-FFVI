# v42：地图、战斗与学习系统

本批继续扩充已经能连续运行的游戏骨架，三个模块并行开发，共享内容编译、状态和发布集中集成。游戏流程仍由 `GameFlow` 和 `GameSession` 串联。来源内容通过类型化目录接入，不按地图名、敌人名或技能 ID 添加运行时分支。

## 共用系统

**地图对象生命周期。** 来源 MoveArea 是 NPC 控制器使用的移动区域，归现有累积实体集合管理。激活实体组先验证所有区域，成功后整体发布；按来源注册顺序查询，地图初始化清空旧集合，稳定恢复从可信内容重建。它不生成精灵、触发器或碰撞，也不代表自主游走控制器已经实现。详见 [移动区域](field-move-area.md)。

**战斗事件上下文。** `IsOnlyAlive` 和 `IsUnitAliveCount` 使用各自来源条件字段。AI 读取实时单位或本次行动的完整候选单位，因此同一次行动导致的死亡可以影响随后反应。当前战斗单位仍只有一份生命状态；失败时伤害、AI、队列和随机流整体回滚。类型 602 特例、单位移除和临死行动宿主仍独立阻塞。详见 [战场人数条件](battle-event-context.md)。

**能力学习与保存。** 观察资格在行动开始时取得，成功结算后才进入战斗记录。胜利事务按角色资格和来源目录更新既有持有能力与唯一的全局魔法记录，菜单继续读取同一角色。成长记录保留学习发生顺序，恢复时与自然等级学习交错重建，再核验存档中的结果；失败或重复确认不能部分学习或重复发奖。来源初始域缺失的开发检查点不能凭空得到原生魔法记录。详见 [观察学习](character-learning.md)。

普通 Lore 魔法伤害复用现有魔法计算、目标、命中、费用和原子行动流程。类型 504 只增加这个受限分支，其他效果、特殊范围与技能等级规则仍由原门禁拒绝。学会能力与能够执行能力分别判断，未给开场队伍增加角色或技能。

**战斗返场事务。** `GameState.prepareVictory` 提供尚未发布的战后角色投影。`FieldGame` 用同一演员草稿完成旧事件收尾、队伍外观刷新与后续事件初始化，然后与奖励统一提交到原有状态所有者。来源、演员、镜头或媒体准备失败时不发奖、不学习、不丢失胜利画面；重复和过期事务拒绝再次发布。普通战斗保持名册、队伍格子和启用身份，条件变化交给已有外观提供器，额外编队和交通转换继续要求对应系统。返场尚不能保存的并行移动、窗口等活动在入战前即明确拒绝，防止战斗冻结字段之后无法返场。详见 [字段战后返回](field-battle-return.md)。

## 验收口径

基础连续轨迹仍为标题 → 探索/事件 → 库存与装备 → 战败/重试 → 胜利、奖励与成长 → 地图及菜单 → 稳定保存/恢复。新增机制使用受控来源样本检查跨系统交接与失败回滚，真实来源路线另记录当前边界。

编译数量、受控机制检查、浏览器实玩和原版行为对照分别记证。原始游戏未在本机执行；原生静态回执的 `semanticsVerified` 保持 false。完整新游戏、主线、特殊机制和全游戏 Web 迁移尚未完成。

框架来源路线仍在 25,540 ms 请求地图 178：kind 13 依赖已经通过，当前具体边界变为原生地图透明主体的合成生命周期。地图准备失败保留原地图和持有状态。本批保持既有开发配置的视觉省略范围；该表现提供器不会取代当前系统交接工作。严格来源入口仍保留先前粒子门禁。

## 版本和后续

共享状态为 owned v9，外层 game v4、field/world v9 和战斗 profile `narshe-playability-v35` 保持不变。内容摘要重新绑定，旧存档明确拒绝，没有自动迁移或覆盖用户进度。

下一阶段继续以系统交接为单位推进：让来源新游戏通过共用地图生命周期进入可交互流程，将同一战斗、菜单和保存框架用于后续内容。区域内容按已支持能力的依赖闭包接入；当前批次用到的新机制集中补到共用模块。完整特殊技能和精细表现不作为搭建骨架的前置条件，HD-2D 保持后置。
