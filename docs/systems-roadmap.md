# 游戏系统推进计划

2026-10-14：先交付整体游戏骨架，再批量填充内容。以一个能操作、能连续游玩、能存读档的入口作为交付物；不以研究完所有原版细节作为骨架前置条件。

当前以 [v78 公共骨架交付](systems-v78.md) 为主线：默认入口和六组连续合同、公共包构建、骨架到批次准入、系统级内容工作单。新增内容能力以整块系统实施，不再因下一个 NPC 或演出指令重新打开骨架里程碑。

[v77 已接入来源内容](source-content-v77.md) 保留为独立回归：费加罗22/23经同一会话、切图与保存接口运行。直接起始放置和简化材质是明确的开发策略；完整剧情及14条来源依赖诊断仍未放行。

## 骨架范围与所有权

| 系统 | 现有 owner / 公共接口 | 本阶段交付 |
| --- | --- | --- |
| 启动与流程 | `GameFlow`、`GameEntryLoader`、`GameContentRepository` | 标题开始、暂停、内容载入、独立进度、失败重试和过期请求拒绝。 |
| 探索与事件 | `WorldSession`、`FieldGame`、`GameMapLoader` | 移动、碰撞、交互、对白、选择、剧情状态、地图切换及世界/地点往返。 |
| 战斗往返 | `GameSession`、`BattleGame`、`GameBattleHandoff` | ATB、行动、目标、AI、状态、道具、胜败、固定入场重试、奖励一次提交、返场。 |
| 持有与菜单 | `GameState`、`GameCommands` | 名册、编队、装备、库存、商店、Gil、经验、能力与魔石学习；各界面使用同一持久状态。 |
| 保存恢复 | `CheckpointStorage`、`GameEventSaveCoordinator`、入口装载器 | 当前/上一份进度、内容身份校验、私有候选恢复、恢复后继续游戏；不重跑初始化。 |
| 批量内容 | compiler、内容包引用、批次 runner/admission | 数据接入、依赖闭包、按公共能力归并缺口、声明路线执行、构建绑定的准入证据。 |

这些模块已在已有内容范围内接线。来源新游戏初始化的系统训练场可操作战斗、商店、装备、编队、魔法、魔石与保存；世界旅行包使用同一会话和保存边界。训练事件与旅行导航是明确的作者内容，原版主线没有因此完成。

## 可运行骨架

1. 默认 `/game/` 进入系统版标题；同一标题可选择系统版、世界旅行或原迁移样本。各包继续使用既有公共 API 和独立保存命名空间。
2. `npm run skeleton:check` 构建公共包并运行代表性完整流程，按上述系统分组给出新鲜结果、失败位置和未验证范围。`framework:verify` 保留完整细项回归；批次准入默认消费骨架证据，仍单独要求完整依赖与连续路线。
3. NPC 路线建立保留全部源字段的类型化数据接口、地图包内绑定和未知能力清单，供批量内容生产消费。本轮不以恢复全部自主控制器为骨架验收前置。

使用方法与准确范围见 [可执行骨架](game-skeleton.md)。历史实现和验证记录保留在各 `systems-v*.md`；历史测试数量不是当前构建结果。

## 后续工作单位

骨架流程通过后，选择一组相连地图、事件和敌队生成同一批次清单。`npm run systems:plan -- <manifest.json>` 从当前包汇总入口状态、脚本、出口、演员、战斗和媒体依赖，输出按公共模块归并的工作单；同类参数只需数据填充。未走分支也保留在依赖闭包内，不能过滤未知敌队或把未知指令当空操作。未分类指令单独保留，不能从错误文本猜其 owner。

NPC 自主活动/事件接管、剩余普通战斗规则、车辆/多队伍旅行是可复用系统增量。仅当选定批次需要它们时，按完整生命周期实施，包含取消、失败、重试和保存恢复；不按单个 NPC、技能或场景建立特例。本轮 NPC 调查和未集成代码已收拢至本地 ignored WIP，不向来源包授予运动能力。精细演出、逐位数值和特殊技能不自动扩大骨架前置清单。

并行工作按独立文件和明确接口拆分：内容编译、纯规则、界面、连续流程。集成线独占 `GameState`、`GameSession`、Field/World 的提交边界及保存版本。所有系统保持一个持久 owner；禁止创建仅供演示的第二套玩法内核。

持续填充时还需一个内容版本系统：当前恢复严格绑定 entry/world/battle 摘要，重建同一包后旧进度可能不再匹配。后续应保留可信旧依赖或提供显式、可验证的升级协议，不能删除摘要门禁。实际浏览器连续复演也单独留证；受控 UI 检查不替代它。这两项按完整公共合同推进，不拆成场景特例。

骨架门禁、来源批次准入、浏览器实玩、原版对照及完整迁移分别留证。用户已将原版对照后置；完整 Web 迁移目标继续 active。HD-2D 调查与制作在完整 Web 迁移放行后开展。
