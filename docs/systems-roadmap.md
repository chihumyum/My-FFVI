# 当前游戏系统推进计划

2026-10-14：按用户要求，先搭建可连续游玩的完整系统骨架，再批量填充内容。工作单位是跨系统的完整流程；单个场景、单条演出指令和单个特殊技能不作为主线任务。

## 已接入的骨架

| 系统 | 当前公共合同 |
| --- | --- |
| 启动与流程 | 标题、新游戏、按内容包读取进度、暂停、后台和媒体就绪；过期请求不能替换当前会话。 |
| 地图与事件 | 移动、碰撞、交互、消息、选择、剧情变量、地图装载与切换；事件和菜单使用同一持久状态。 |
| 战斗 | 行动、目标、ATB、AI、状态、道具、战斗脚本、动态参与者和多阶段敌队；固定入场重试、一次结算和返回地图。 |
| 角色与经济 | 持有名册、三组编队、装备、库存、普通商店、经验、自然学习、Gil和奖励；取得身份与效果准入分开。 |
| 地图菜单与保存 | 道具、换装、编队、持有魔法和MP；稳定检查点保留角色、剧情、位置及随机流，恢复后重新绑定操作。 |
| 内容生产 | 同一编译器、可信摘要引用、批次依赖规划及连续执行接口；内容不向运行时加入地图名或敌队ID分支。 |

上述是已支持内容的公共骨架，证据范围见 [v69](systems-v69.md)、[v70](systems-v70.md)、[v71](systems-v71.md)。各系统已接入不代表全部来源机制、主线剧情或所有内容都已迁移。

## 下一阶段的两块闭环

普通商店的核心交易和页面买卖已实现。先补批次路线的声明交易输入及离店续行，贯通“购买/出售 → 使用或装备 → 下一战 → 保存恢复”；当前 runner 的 `shop-input-not-declared` 保留为明确缺口，不能把核心交易测试当成这条连续链已经完成。

主系统增量是魔石、学习与成长：

一次完成取得、装备/转移/卸下、战后部分熟练度、学会后的字段与战斗使用、逐级奖励以及保存恢复。召唤使用临时能力，不把它授予成永久已学能力；它的资格、一次使用和重试周期进入同一战斗合同。

`GameState` 继续唯一持有魔石与角色进度；战斗租约冻结实际装备，结算带实际 MagicPoint。升级保存有序成长依据，不能用当前装备回算过去等级。来源未知的召唤效果和禁用角色转移保留诊断，不阻塞已支持的普通学习流程，也不放宽现有来源守卫。

并行分工为完整内容编译、纯持有/学习/成长规则、菜单操作三个模块；集成线独占 `GameState`、`GameSession`、存档版本与发布。验收是一条完整连续流程，加失败、取消、重试和读档后的续行。

## 接续与批量填充

商店连续链与魔石之后按完整系统归并实际缺口：战斗扩展使用同一行动/状态/参与者接口；世界旅行使用同一地图装载、交通与保存所有者；经济取得使用同一库存和交易事务。特殊效果由内容能力需求驱动，避免无限扩大骨架前置清单。

代表性组合通过后，成批编译区域、事件和敌队，并用留出路线验证同一运行时。一个批次的未知机制作为公共增量实施，不能跳过后计入可玩覆盖。骨架合同、来源批次放行、浏览器实玩和全游戏迁移分别留证；HD-2D 在完整 Web 迁移后开展。
