# Explicit Web lifecycle for all-loop field effects

`web-logical-all-loop-field-effects-v1` preserves the existing `FieldEffects` manager, board leases, source group registration, automatic/positive playback, reference counts, camera identities, elapsed shader-clock values and ordinary map retirement. Particle, material and effect-minimap images are explicitly deferred. It is a development policy, with `nativeParity:false`; strict source packages retain their original particle/material/provider gates.

A complete lossless export is produced by `tools/export_field_effect_media.py`. Nonfinite decoded floats use `$unityDecodedFloat64` with classification and exact decoded binary64 bits; they are never replaced by zero or supplied as particle simulation values. Every original serialized object also retains content-addressed bytes and its source identity. Those original bytes are authoritative for source float width and NaN payload. All PPtr path IDs remain decimal strings. Reserved scalar tags cannot alias original objects.

`scripts/compile-logical-field-effects.mjs` consumes the verified export snapshot and original source manifest. It verifies original files at both ends, raw object payloads, and runtime identity. Its local output is a prerequisite, outside public package/release collections. `compileWebLogicalEffectCatalog` keeps rejected graphs and original strict-media failures visible. Only complete graphs consisting of GameObject/Transform, exactly one camera, and looping particle systems/renderers qualify. Particle stopAction must be None; Collision, Trigger, SubEmitter, ExternalForces and Lights must be explicitly disabled. Animator, callbacks, collision/building effects and unknown component dependencies do not qualify. Null material failures stay recorded while display is deferred.

The pure `deriveLogicalFieldEffects` API requires `web-logical-field-effects-declaration-v1`, the exact source-set identities, compiled catalog hash, complete selected map IDs and a human-readable reason. It accepts existing explicitly authored framework derivatives; it neither grants this policy to strict source maps nor upgrades an existing declaration implicitly. Only the new profile metadata and shared immutable catalog are added. Scripts, locals, source flags, actors, inventory, source geometry and all omissions remain unchanged. The caller then uses the existing `compileFrameworkNewGame` to bind a new entry identity. It does not publish. The common package producer now declares its logical Web variant explicitly: `compileSourcePrerequisites({logicalFieldEffects:{kind:"web-logical-field-effects-input-v1",input:"build/field-effect-media",reason}})` locks the entire lossless snapshot, every referenced serialized object and all original corpus source bytes. Its exact `source-prerequisite-input-lock-v2` is revalidated at the publication boundary. The complete group cohort must equal the asset groups of every kind-11 board in the freshly compiled world. `compileWebLogicalEffectCatalog` runs once; its single output is passed through `compileFrameworkContent(strictCatalog,strictMaps,strictEntry,{logicalFieldEffects:{catalog,declaration}})` and URL linking. All indexed framework maps, including unavailable and empty maps, carry the same catalog and marker; catalog and source-entry identities bind those map payloads. Strict maps, original instructions and the source entry remain unchanged. The optional fourth argument leaves room for independently declared presentation policies; it does not infer them from logical FX.

`scripts/prepare-field-effect-media.mjs --candidate <separate-lossless-export>` validates an exported candidate before installing the canonical prerequisite at `build/field-effect-media`. Only verified snapshot files are copied; existing legacy, failed or prior directories are retained as `build/field-effect-media.previous-*`. It publishes no game package. A legacy decoded-only export is rejected and must be re-exported by the lossless exporter. The producer does not silently change or repair decoded resource data.

Pinned recipe inputs require the separately versioned `compiled-framework-profile-upgrade-v2`: the exact logical marker, real compiled display host and the same compiled catalog. Only that audited catalog projection may be added; before/candidate evidence and full identities remain in the receipt. Source sets, physical map assets, other policies, game-state initialization, media bindings, omission membership and every other identity still compare normally. Existing v1 marker declarations and absent-option compiler calls retain their old behavior. A save, recipe or matching source hash cannot independently grant this profile. Publication remains exclusively the common package pipeline.

This public integration covers the complete base `/framework/` world/entry/map collection. Independently authored variants such as systems playground, world travel and initialized content batches retain their own explicit policies and producers; they do not automatically inherit this marker or catalog from a strict input. Research fixtures that explicitly derive the logical policy are labelled separately.

`createWebLogicalFieldEffectsHost` is the production app's stateless display host. It has no particle simulation, RNG, gameplay state or renderer owner. Its typed `all-loop-completion-independent-v1` observation means completion does not inspect particle `isPlaying`; it is not a fabricated Boolean vector. The shared manager still executes every admitted operation. Positive loop limits advance once per eligible manager update, automatic loops remain indefinite, and the existing update mask controls the clock. The Web battle scheduler pauses this field manager during battle and preserves it on return.

All maps in a logical world, including empty maps, bind the same catalog and marker. Map candidates fork the original manager, prepare release-before-create in source order, and publish atomically with the existing owned/native actor transaction. Cancelled, failed or stale candidates cannot alter the live manager. A retired field cannot tick its former lease. No delayed source callback, unknown RNG result or unsupported instruction is drained or replaced by a no-op.

Stable saves use `idle-world-v11`; event barriers use `event-world-v2`. They persist logical manager state, catalog hash, map scope and the next scope counter. Saved data carries no proof authority. The trusted entry and pinned map catalog reconstruct the contract; stable restore prepares no replacement FX creation/setup publication and does not replay initialization. Invalid references, extra fields, unknown groups, forged board definitions, foreign source profiles and catalog changes are rejected. Existing native particle/RNG save barriers remain unchanged.

A prior research no-observation claim covered only map-bound source analysis. The superseding full namespace audit includes installed Resident programs. Named passive omission candidates remain unassessed. This policy retains boards and their real logical state, so future source ID observations do not invalidate its proof. The existing anonymous policy is neither expanded nor reinterpreted here.

Verification lanes remain separate: synthetic lifecycle and production-app/controlled Renderer integration, exact export replay, full source graph/namespace inventory, real original initializer attempts, explicit source program attempts, and native-game or browser pixel acceptance. Static graph or map counts are never reported as completed plot migration.


After the common pipeline publishes the complete collection, run `node scripts/check-logical-field-effects-lifecycle.mjs`. The default lane requires a successful same-runtime publication receipt and every scanned source byte, independently recompiles the canonical lossless media catalog, checks every published framework map against it, and attempts every kind-11 map initializer plus complete related source roots. All installed Resident programs, external dependencies, unknown choices and provider failures remain in the report. Generic PointIn/ordinary-flat-map research states are explicit; they are not story reachability or coverage of independently declared periodic-world variants. `--candidate-directory <private-complete-source-dir>` is a separate unpublished research lane requiring that candidate's exact runtime and source-input lock. Neither lane uses an old readiness report to grant source playback.

`plan-story-runtime.mjs` accepts exactly source-input-lock v1 and v2 for provenance. Both still require the complete same-runtime compiler/producer chain, successful publication stages, all scanned bytes and source inventory; unknown versions or any mismatch remain unassessed. Recognizing v2 is not evidence that a particular v2 publication has occurred.


The whole-family checker classifies every compiled kind-11 actor/group root as accepted-related, rejected-only or mixed. Rejected graphs are not removed from the denominator; the original initializer is attempted first and a failed prerequisite marks its complete roots explicitly unexecuted. An initializer that is itself a target root is counted from that original execution and is never rerun to manufacture coverage. Static targeting/source-site counts do not claim instruction executions. Unresolved source shapes remain visible in the complete namespace and diagnostics.

For a deliberately expanded read-only checker, unpublished research may use `--candidate-observation-runtime <exact producer runtime>` after verifying every frozen compiler/source input and object byte. Its receipt records separate producer and observation runtime hashes, `sameWholeRuntime:false` and no publication claim. The default public lane still requires a successful actual same-runtime publication and the exact published framework world/entry producer hashes. This research continuation does not relax the public gate or grant a new gameplay policy.
