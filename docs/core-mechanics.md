## 系统闭环检查

按最新用户指令，以下检查完成之后才进入区域批量填充。完整系统门禁尚未完成；共享状态和稳定存档已有受限闭环，开场回归不能替代完整范围。

- [ ] 普通物理、魔法、恢复、物品、状态、死亡/复活、单体/群体目标共享行动结算；资格、消耗、效果和退出状态一致，未知组合不会部分提交。
- [ ] ATB、等待、行动队列和通用敌方 AI 贯通；不同敌人及战斗脚本通过数据接入，不新增 Guard 式模板。
- [ ] 全局角色名册、编队、库存、装备、能力学习、成长与奖励有单一状态所有者；字段、菜单和战斗读取与修改同一份数据。
- [ ] 检查点保存持久化到浏览器；刷新、加载、离开重返后保持角色、物品、剧情和地图状态，旧版本与错误数据有明确处理。
- [ ] 新游戏初始化、字段事件、切图、进入战斗、结算及返回组成连续流程；用来源样本和不同输入检查重复消费与重放。

这组检查是开始成批接内容的系统条件，不替代最终全游戏迁移验收。单个模块已有隔离测试时，该系统项仍保持未完成。

## 后续实现次序

当前已把普通道具、复活/解除已支持状态、普通装备变更和字段库存事务接到同一持久状态。下一批从真实角色与物品流程的剩余依赖推进；系统门禁仍未关闭，不恢复以空闲地图入口数量为目标的工作。

1. **剧情角色与取得入口。** 恢复新游戏初始化、角色加入/离队、编队及其装备占用规则；补来源库存查询、装备/魔石授予，以及宝箱、商店、掉落/偷取所需的共用状态接口。每个子集先确认来源规则、再接共享事务，不用测试发放冒充剧情取得。
2. **状态、装备效果与能力学习。** 按上述流程实际使用的依赖恢复其他活动状态、持续/周期效果、穿戴效果、耐力等参数提供器及学习/解锁。保留菜单与战斗独立资格；未知状态、被动或函数组合在提交前阻塞。普通换装已完成的动态重算继续复用，不另造一套属性公式。
3. **调度与通用战斗。** 补 ATB 等待/暂停/蓄力、临死与恢复反应、动态能力、完整目标和其他 AI 条件；使用陌生来源敌人/编组验证同一实现，继续保留既有反击与五次遭遇回归。无来源的时序和随机数选择仍列为开发规则。
4. **跨系统保存与连续流程。** 每增加一种角色/库存/状态变化，验证菜单 → 字段/切图 → 战斗 → 结算 → 检查点恢复的所有权、失败回滚和不重复执行；补完整初始化与区域边界，再扩大事件中途恢复及目标浏览器检查。
5. **系统通过后成批填充。** 使用来源依赖闭包、真实入口和剧情退出状态成批接入相连区域，补世界地图、多队伍和演出。字段指令准入、装备数量和隔离预览次数不换算为完整可玩覆盖；HD-2D 等待全游戏 Web 迁移放行。

角色/库存入口、状态/装备效果、战斗调度可按独立文件和证据批次并行；共享状态、版本化检查点与最终构建由集成线统一收口。原生数据库导出仍串行占用，避免并行改写同一研究产物。

这些是工作顺序，不是已完成清单；不能声称源反编译输出已等同于已验证公式。每项分别记录来源证据、Web 实现、隔离检查、组合场景、浏览器实玩和待做原版对照。

## 下一批验收口径

- 新角色/敌人/能力应通过来源表与已支持分支接入，不能要求添加具体战斗 ID 的运行时分支。
- 选一个确实依赖新机制、且不属于开场 Guard 模板的来源动作作为迁移样例，再检查其他来源使用点。
- 同一状态与随机输入可重放；消耗/伤害/奖励不能因帧切分或重复确认而重复提交。
- 同时列出成功、未知和失败的动作/状态组合，不把未知规则改成固定伤害、默认命中或空效果。
- 保留开场五次遭遇回归；机制检查通过与完整游戏可玩仍分开报告。
