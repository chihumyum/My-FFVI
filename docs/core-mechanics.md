# 核心机制迁移盘点

2026-10-11。结论：尚未摸清或迁移完整核心机制。地图和字段事件已有共用实现，战斗仍是开场开发子集。地图包、空闲入口和孤立脚本的数量不能代表战斗、角色、物品或保存系统的完成度。原版一致性对照按用户指示后置，HD-2D 不进入当前工作。

## 当前证据与缺口

| 系统 | 已恢复或已实现的范围 | 仍缺少的核心部分 |
| --- | --- | --- |
| 字段事件与剧情状态 | 来源绑定的控制流、算术/分支/变量、任务、实体组、部分地图初始化；见 `event-state.ts`、`field.ts` | 系统调用、角色/物品相关条件、完整新游戏初始化和故事状态演化；未知 flag 不默认 false |
| 地图与交互 | 通用地图装载、入口/出口、碰撞、斜坡、静止 NPC、门、图块/角色动画、BGM/环境音 | 世界地图运输、多队伍、游走控制器、宝箱/商店/特殊机关、完整可达性 |
| 行动条 | 本版本 `ATBCalc 0x675950` 的增量算术、float32 顺序与表常量已核对，位于 `atb.ts` | 原生初值抽样、暂停/等待模式、完整蓄力、反击与插队调度；当前战斗队列和随机数仍为开发规则 |
| 属性与装备 | 开场三人的来源基础数据、部分装备加成与负重连接；部分原生确认链已有研究 | 完整最终属性链、特殊装备/被动、状态修正、能力解锁；基础表不能当作最终数值 |
| 行动与伤害 | 三种魔导射线、治愈和守卫/狼犬普通攻击能执行；物理和魔法原生函数已有研究输出 | 完整命中、物理/魔法分派、元素、反射、范围、死亡/复活、特殊技能；现有公式是受限分支，不能推广给所有技能 |
| 敌方 AI 与战斗事件 | 开场 Guard 模板和低等级狼犬分支，五次连续遭遇回归 | 通用 AI VM、完整条件、目标规则、反应/计数器和 Boss 战斗脚本；权重表不是完整 AI |
| 状态系统 | 数据可提取，行动条接口接受聚合修正 | 状态施加/抵抗/移除、持续时间、周期效果、互斥和对行动/目标/伤害的影响，尚无完整状态引擎 |
| 成长与结算 | 开发版经验/Gil、有限升级、胜负返回和奖励一次性消费 | 完整经验资格、成长修正、掉落/偷取、魔石学习与装备成长；掉落仍明确 pending |

| 存读档 | 逻辑状态与重放基础已有结构 | 完整游戏快照、持久化、版本迁移、加载恢复和原版存档导入；刷新页面会重置当前开发会话 |

盘点依据是当前 `src/core/battle-content.ts`、`battle.ts`、`game-session.ts`、`atb.ts` 及其编译器，而不是解析计数。`BattleContent` 仍明确限制为 `opening-battle-development` / `narshe-playability-v2`，`AbilityDefinition.kind` 只有 beam/heal/physical/unsupported。完整战斗的数据模型与执行覆盖尚未形成。详见 [战斗研究](battle-migration.md)、[开发规则](battle-playability.md)。

## 后续实现次序

当前调查点/隐形碰撞物批次完成验证后，优先转入共用战斗与角色机制，不再以新增空闲地图入口作为主要推进目标。

1. **属性与行动契约。** 沿原版 confirmed-parameter 和能力 function/content 引用恢复类型化输入，列清实际使用的运算分支、状态依赖和目标约束。保留开场开发 profile，不将其临时假设升级成全游戏规则。
2. **行动结算与状态。** 分离目标合法性、消耗、命中、效果和数值提交；按原生分支接入物理/魔法/恢复及其实际依赖。记录随机输入、舍入顺序和效果结果；未支持的 function/状态组合在执行前明确停止。由这些真实需求决定模块边界，不先制造通用引擎框架。
3. **调度与 AI。** 恢复 ATB 周边调度和通用 AI 指令/条件/目标。用不同地区、不同敌人及陌生编组验证同一实现；不继续加 Guard 风格的专用模板。
4. **全局角色与物品状态。** 完整队伍、装备、库存、成长与奖励由同一持久状态拥有，字段脚本、菜单和战斗共享它；随后完成稳定检查点的存读档，再扩展事件中途恢复。
5. **完整流程扩展。** 新游戏初始化、相连区域和剧情边界使用上述系统成批运行，逐项保留尚未实现的演出/世界地图能力。

这些是工作顺序，不是已完成清单；不能声称源反编译输出已等同于已验证公式。每项分别记录来源证据、Web 实现、隔离检查、组合场景、浏览器实玩和待做原版对照。

## 下一批验收口径

- 新角色/敌人/能力应通过来源表与已支持分支接入，不能要求添加具体战斗 ID 的运行时分支。
- 选一个确实依赖新机制、且不属于开场 Guard 模板的来源动作作为迁移样例，再检查其他来源使用点。
- 同一状态与随机输入可重放；消耗/伤害/奖励不能因帧切分或重复确认而重复提交。
- 同时列出成功、未知和失败的动作/状态组合，不把未知规则改成固定伤害、默认命中或空效果。
- 保留开场五次遭遇回归；机制检查通过与完整游戏可玩仍分开报告。
