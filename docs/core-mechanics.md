## 系统闭环检查

按最新用户指令，以下检查完成之后才进入区域批量填充。当前全部尚未完成；已有开场回归只能证明其中的受限路径。

- [ ] 普通物理、魔法、恢复、物品、状态、死亡/复活、单体/群体目标共享行动结算；资格、消耗、效果和退出状态一致，未知组合不会部分提交。
- [ ] ATB、等待、行动队列和通用敌方 AI 贯通；不同敌人及战斗脚本通过数据接入，不新增 Guard 式模板。
- [ ] 全局角色名册、编队、库存、装备、能力学习、成长与奖励有单一状态所有者；字段、菜单和战斗读取与修改同一份数据。
- [ ] 检查点保存持久化到浏览器；刷新、加载、离开重返后保持角色、物品、剧情和地图状态，旧版本与错误数据有明确处理。
- [ ] 新游戏初始化、字段事件、切图、进入战斗、结算及返回组成连续流程；用来源样本和不同输入检查重复消费与重放。

这组检查是开始成批接内容的系统条件，不替代最终全游戏迁移验收。单个模块已有隔离测试时，该系统项仍保持未完成。

## 后续实现次序

调查点批次已结束，当前推进共用战斗与角色机制，不再以新增空闲地图入口作为主要推进目标。属性确认算术、三槽技能分派已接入；状态列表冲突与首个活动沉默子集已接入，玩家死亡/复活及濒死派生状态已形成受控链路。普通行动 AI 已接入来源控制流和逐敌行为参数；接下来推进反应/插队、连续行动等调度缺口，以及技能/事件对共享参数的修改，再接共享角色/物品；其他状态行为、装备来源与特殊生命周期仍需恢复。

1. **属性与行动契约。** 数值确认模块已建立，上游输入解析仍有缺口；能力 function 引用已完整保留，下一批补其状态、命中、目标和数值提交的实际依赖。保留开场开发 profile，不将其临时假设升级成全游戏规则。
2. **行动结算与状态。** 分离目标合法性、消耗、命中、效果和数值提交；按原生分支接入物理/魔法/恢复及其实际依赖。记录随机输入、舍入顺序和效果结果；未支持的 function/状态组合在执行前明确停止。由这些真实需求决定模块边界，不先制造通用引擎框架。
3. **调度与 AI。** 恢复 ATB 周边调度和通用 AI 指令/条件/目标。用不同地区、不同敌人及陌生编组验证同一实现；不继续加 Guard 风格的专用模板。
4. **全局角色与物品状态。** 完整队伍、装备、库存、成长与奖励由同一持久状态拥有，字段脚本、菜单和战斗共享它；随后完成稳定检查点的存读档，再扩展事件中途恢复。
5. **完整流程扩展。** 新游戏初始化、相连区域和剧情边界使用上述系统成批运行，逐项保留尚未实现的演出/世界地图能力。

这些是工作顺序，不是已完成清单；不能声称源反编译输出已等同于已验证公式。每项分别记录来源证据、Web 实现、隔离检查、组合场景、浏览器实玩和待做原版对照。

## 下一批验收口径

- 新角色/敌人/能力应通过来源表与已支持分支接入，不能要求添加具体战斗 ID 的运行时分支。
- 选一个确实依赖新机制、且不属于开场 Guard 模板的来源动作作为迁移样例，再检查其他来源使用点。
- 同一状态与随机输入可重放；消耗/伤害/奖励不能因帧切分或重复确认而重复提交。
- 同时列出成功、未知和失败的动作/状态组合，不把未知规则改成固定伤害、默认命中或空效果。
- 保留开场五次遭遇回归；机制检查通过与完整游戏可玩仍分开报告。
