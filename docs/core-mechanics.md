# 核心机制迁移盘点

2026-10-12。结论：尚未摸清或迁移完整核心机制。地图和字段事件已有共用实现，战斗仍是开场开发子集。地图包、空闲入口和孤立脚本的数量不能代表战斗、角色、物品或保存系统的完成度。原版一致性对照按用户指示后置，HD-2D 不进入当前工作。

用户本次要求先搭建游戏骨架，避免继续消耗在细节复刻。当前优先验收“连续流程与状态所有权”：标题、探索、事件、战斗、奖励、菜单、存读档通过同一会话运行；地图与故事随后按内容包接入。下表保留完整迁移缺口，但不再将每项数值或表现缺口作为开始搭建骨架的前置条件。详细执行范围见 [游戏系统框架](game-framework.md)。

当前系统批次为 v46：标题允许无会话、零内容读取；来源新游戏与来源存档按各自依赖加载，不再被旧纳尔谢开发包阻塞。入口统一准备媒体后发布，失败或取消保留原会话；战斗与库存界面绑定新会话目录。切图及保存继续使用 v45 的共用事务，所有存档格式保持不变。下一步建立活动事件保存/继续协议；来源开场的后续演出缺口不抢占骨架主线。见 [v46 独立入口](systems-v46.md)、[v45 公共运行框架](systems-v45.md)。

## 下一批验收口径

- 新角色/敌人/能力应通过来源表与已支持分支接入，不能要求添加具体战斗 ID 的运行时分支。
- 选一个确实依赖新机制、且不属于开场 Guard 模板的来源动作作为迁移样例，再检查其他来源使用点。
- 同一状态与随机输入可重放；消耗/伤害/奖励不能因帧切分或重复确认而重复提交。
- 同时列出成功、未知和失败的动作/状态组合，不把未知规则改成固定伤害、默认命中或空效果。
- 保留开场五次遭遇回归；机制检查通过与完整游戏可玩仍分开报告。
