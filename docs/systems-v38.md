# 游戏框架 v38

本批在 v37 的统一流程、内容仓库和连续游戏循环上补齐队伍操作与通用遭遇内容接入。来源编译、运行定义、队伍菜单三线并行，统一构建后接入浏览器。基础骨架闭环通过；完整规则、剧情和全游戏迁移仍未完成。

## 系统交付

暂停菜单新增当前队伍排序、前后排、角色成长和已持有能力查看。编队仍由 `GameState` 唯一持有，`GameSession` 同时准备状态事务与地图演员外观，再同步发布。菜单改动沿用现有入战、奖励与存档契约；缺媒体或过期请求拒绝整次变更。只编辑本队现有四格，不授予备用角色、剧情权限或新技能。详见 [队伍菜单](party-menu.md)。

战斗导出支持重复的 `--encounter-id`，来源编译不再要求恰好是开场四组。编译器保留来源槽号、坐标、组别、六种队形标志和脚本身份，再交给已有参数、AI、能力、掉落及会话系统。逐组诊断区分无法构造、条件分支依赖和明确的开发偏差；单个局部缺口不会丢掉整个目录，共用规则损坏仍使构建失败。缺失遭遇在实际游戏入口报告对应编译原因。详见 [遭遇管线](battle-catalog.md)。

来源留出编组 3002、3035 通过相同管线生成，没有新增战斗 ID 的运行时分支。它们只用于系统验证，没有注入原故事脚本。当前选择的 6 条编组均生成定义，其中 4 条保留狼犬能力 696 的条件分支依赖；6 条均记录开发宿主的表现或逃跑偏差，既有四组另记录未执行的 `sc_b_0239` 和旗标 14。定义数不代表剧情覆盖或完整战斗迁移。

## 接续边界

公开 profile 仍为 `narshe-playability-v35`，owned v8、field/world v9、session v4 不变。内容目录摘要已随来源选择和诊断更新，旧摘要绑定的存档仍按现有规则拒绝，不能偷偷迁移。正式新游戏包已重建摘要绑定，来源开场 609→3 的表现缺口仍保留；本批没有恢复粒子细节或启动 HD-2D。

接下来以共用事件链、世界/交通状态和内容依赖闭包为单位推进。已支持的内容沿同一管线接入；缺口按系统能力聚合，优先处理影响连续游玩的大类，再验证代表性旅程。不要重新把每个地图坐标、每条台词或单个画面效果变成独立迁移任务。原版一致性、完整技能/角色与世界主线验收继续单独追踪。
