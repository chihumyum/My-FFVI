# 共用服务事件与骨架续行

本轮保持整体骨架优先：默认 `/game/` 使用系统版；探索、事件、战斗返场、持有菜单、地图切换与存读档继续共用现有会话。代表性连续流程仍使用六组系统、七个检查器，不把个别来源镜头或原生观察器扩为骨架前置任务。

## 共用事件合同

来源脚本中的商店调用使用同一 Field 任务和现有 shop owner。打开时保留原 PC、任务身份及指令摘要；关闭后继续原脚本的告别消息与 Exit，不复制商店前后的对白或创建第二套库存。缺少商品组、来源领队或共享状态提供器时，事件明确停止，不跳过该分支。

领队分支读取当前地图保存的 Corps 位置，再经同一持有名册确认角色的来源身份。缺失位置、空队格、含糊身份或地图与编队快照不一致都不能被解释为“不是该领队”。分支目标采用来源 label 后一条指令，完整脚本及未走分支都进入依赖检查。

`FieldGame`、`GameSession`、`GameCommands` 的 `closeShop(expectedVisitId)` 现在要求调用方提供捕获的访问 ID。UI 与批次 runner 传递打开窗口时的 ID；缺失或过期 ID 返回 false。实际复现的缺陷是：关闭第一家商店可能同步续行并打开下一家，旧关闭回调再次执行会误关新窗口。新的合同在这条连续流程上拒绝旧请求，且不改变当前窗口或持有状态。

## 来源与范围

八个已核清的来源回调绑定商品组64–67及89–92；来源四个完整程序均保留两个领队分支。静态检查核对实际注册、原生包装器、来源脚本和商品表。它与运行时生命周期验收分别留证，静态通过不授予源地图到达资格。原十条指令在明确的 empty-actor 包络内验证控制流，原 SystemFlag 完整留证，但没有验证来源演员初始化；该包络仍拒绝稳定保存。真实系统版的经济、保存恢复与恢复后续行另走公共会话接口，两条证据范围分别记录。

完整南费加罗区域继续保留56张地图及全部原始缺口。商店柜台 Relay 的类型与纯几何原型归档到 ignored `build/wip/v92-relay/`，公开编译器仍保留 kind16 门禁。旅店、多层/交通/锁定观察器、粒子及水层宿主、正式故事时期与来源可达性均没有因服务事件合同闭合而放行。后续按整批依赖工作单选择公共能力，不以这些细项重新开启骨架里程碑。

## 验收与交付

本轮结果集中记录于 ignored `build/reports/v92-validation-summary.json`。包含代码与 Python 检查、同一候选的公共内容发布、六组代表性骨架流程，以及来源服务程序在明确受控宿主中的执行。稳定恢复和恢复后新输入使用原有保存/入口接口；内容包与历史进度仍保留严格来源身份。

受控 DOM/媒体与作者设施用于验证公共系统，不能代替浏览器实玩、源柜台交互、原版对照或完整主线。完整 Web 迁移目标继续 active，HD-2D 后置。
