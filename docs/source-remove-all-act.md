# Source RemoveAllAct common execution

This family admits the complete `SysCall("RemoveAllAct")` shape under the existing explicit `web-source-battle-event-controls-v1` runtime policy. Both eight-cell numeric arrays must be zero; only string cell zero may contain the selector. Altered or missing operands remain hard errors, including on an unvisited branch of a source program. The VM emits one immediate request, advances with native `Next`, and retains the following source instructions. It neither forces an outcome nor invents an `Exit` or wait.

The nomination preserves all 53 battle programs and 2,312 operations, all 490 requested parties, and the 52 exact battle-export bindings plus the explicitly unbound Common source. Six calls occur in five complete source bodies containing 592 operations and have 406 party dependencies. These are original source parameters; the runtime has no program, PC, party or encounter-ID exception. `scripts/inspect-source-remove-all-act.mjs` verifies the whole family and compares an independently compiled baseline, conserving every other operation, header and non-script catalog diagnostic. Decoding does not certify continuous source gameplay.

## One executor and the commit fence

Every ordinary, controlled, item, scripted, AI, derived and counter action published through `BattleGame` receives a monotonically increasing battle-local ticket. The same accepted action is recorded in the fixed-player index using its source character identity. This index contains reference tickets, not a second executable action queue. Its diagnostic projection is detached from the owner. Tickets and cancellation history are transient and never added to saves or owned character state.

A reached removal validates all actual staged and queued actors and tickets before changing anything. Unknown actors, missing or out-of-range tickets and duplicate tickets cannot disappear as an apparent success. It clears ordinary and interrupt queues, the fixed-player index, staging, and each combatant's queue reservation in one transaction. It increments the real battle UI revision and releases obsolete menu WAIT gates. Host pause, all ATB gauge values, AI continuation and variables, source messages, and independent global battle effects survive. The source can immediately execute its following instruction, and later actions use the same executor normally.

Cancellation is a distinct staged-action exit. It does not call ordinary ATB completion, reset an AI, apply a deferred hit, or refund a paid cost. The existing Web action pipeline applies an effect at 400ms and completes presentation at 900ms. Before the effect commits, cancellation releases MP/item availability reservations and spends nothing. After commitment, HP/MP, conditions, item consumption, confirmed results and randomness remain committed; remaining reactions and presentation are cancelled. Ordinary completion and actor retirement still use the existing ATB completion path. A held completion is accepted only for the exact currently staged action in an active, unretired battle; a cancelled, replaced or retired reference cannot affect a new action, retry or restored Session.

The frame rollback includes action tickets, fixed references, queues, staging, cancellations, menu revision and the existing message/effect/VM/resource owners. A later operation, message preparation or effect resource commit failure restores that frame before a zero-time retry. Effects committed in an earlier successful frame stay committed. No new owner or parallel battle state machine is introduced.

## Bounded native evidence and explicit Web differences

`tools/native/check_source_remove_all_act.py` binds 18 complete methods from existing receipts and one four-method packet to the original PE, symbol file, header and native-range digests. `CreateStateMachine` identifies seven state registrations through exact `Method$` metadata references, without assigning semantics from a shared generic alias. The only registered exit callback is `EndFinishingState`. Additional generic shared bodies are recorded as raw bytes with every alias.

The source wrapper calls `ClearPlyerAct` then `ClearEnemyAct`, then returns zero (`Next`). Player clearing first nulls staging unconditionally, filters actual player-typed attackers from the ordinary and interrupt queues, clears the source-character keyed fixed-player dictionary, and transitions to state zero through the old exit and new entry callbacks. Enemy clearing filters enemy-typed attackers from both queues. The fixed-player registration bodies use owned `characterStatusId` and replace that character's latest accepted action reference.

Native `InitNone` can dispatch a surviving interrupt during the intermediate player-clear transition, before the enemy filter runs. This Web implementation deliberately publishes both filters atomically before idle under the existing Web control and action-stage policies. It does not claim native intermediate dispatch, exact Unity frame order or `EndFinishingState` side-effect parity. It uses the Web executor's existing condition/end-judgment lifecycle rather than copying native finishing callbacks into a second state machine. The native ATB callback is skipped once staging has been nulled; cancelled Web actions likewise do not take ordinary ATB completion.

`InitActionState` performs message/learning work and calls `BattleActLog.AddLog` before the act-function start. This evidence does not grant Shadow participation-log support or convert Web presentation/learning logs into that native owner. Shadow/Gau owned departures, reserve-script lifecycle and every unrelated source/provider gate remain separate.

## Acceptance lanes

Synthetic executor tests cover pending turns and item reservations, staged cancellation before an effect, cancellation after confirmed MP/damage/item effects, real counter queues and AI waits, preserved ATB, malformed and unknown action ownership, detached projections, and a shared Msg/global-effect frame failing and retrying atomically. Actual `GameSession`/`GameFlow`/`GameBattleHandoff`/`GameCommands` tests cover entry media failure, cancelled and obsolete media completion, a cancelled source action followed by a real winning action, failed return and retry, Storage failure/restore, a subsequent battle, defeat retry, and late action completion against a retired owner.

Full-source compilation, synthetic Session execution, app checks and native static research are separate evidence lanes. This family does not report native dynamic parity, extra playable source encounters, a completed campaign, or a map/content publication.
