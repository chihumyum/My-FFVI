# 验收与证据契约

## 独立结果

每个目标分别报告 source、structure、behavior、visual、browser、transfer 六条验收结果。结果为 pass、fail、unknown；没有证据就是 unknown。检查包的产生不代表可运行验收通过。

每条通过证据必须匹配源集合、内容包摘要、能力版本、目标和场景；旧运行不能为新产物背书。必要结果全部通过且没有未知依赖、矛盾、缺失对象或未审核资产，才允许 accepted。

source 通过表示导入时的原始文件散列一致、编译时的导出快照散列一致。它不证明当前安装目录未改变，也不证明解码和游戏语义正确。HD-2D 的研究/制作须等待全游戏 Web 迁移放行，单目标通过不能越过该顺序。

## 对照方法

- 结构：资源/对象身份、表关联、地图尺寸、图块与引用、指令参数、时间线绑定。记录范围与未解析对象。
- 行为：独立原版运行的存档、输入、环境、随机条件和检查点，与候选状态变化比较。共享新内核的两种渲染器不构成独立对照。
- 视觉：固定相机/时间点对照、材质与混合、遮挡、像素密度、镜头与音画同步；人工美术验收独立保存。
- 浏览器：真实浏览器运行与交互、资源加载、暂停恢复和性能。静态构建不能替代浏览器执行。
- 迁移能力：陌生同类场景不增加内核特例，必要能力外的场景准确阻塞。

运行轨迹比较只比较已建立契约的状态与因果关系，不强迫尚未研究的并发行为符合任意全序。原版随机不可控时，逐次结果保持未定。

## 当前检查与目标验收

`npm run check` 是工具自身的类型、测试、登记清单检查。`npm run pipeline` 生成检查包与缺口报告，允许以 unknown 保留目标。`npm run accept -- <target>` 以严格门禁判断目标；未完成返回非零。

首版不提供通过手填布尔值批准行为验收的捷径。正式证据导入需要后续实现：记录真实性/完整性检查、源与产物绑定、测试覆盖、人工审核身份与条件。测试 fixture 只证明门禁逻辑，不可用于真实游戏验收。

## 失败归因

每条诊断包含稳定 code、target、source locator、detail 和 next action。区分源改变、解析失败、引用未解析、参数语义未知、行为不同和艺术问题。局部失败只阻塞依赖它的目标，但不能隐藏共享依赖的影响。
