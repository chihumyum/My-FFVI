# Complete battle directory for the original newgame route

The framework title/newgame role previously referenced the small strict battle baseline. The separately compiled whole-source directory served selected initialized batches, so adding common battle capabilities did not make those definitions available to the original newgame route. This change connects that existing directory to the actual framework source entry and its restore path.

`bindFrameworkSourceBattleDirectory` reuses `selectInitializedBattleCatalog` to validate the complete request set, every map binding, current dependency analysis, blocked and conditional diagnostics, drops, shared capabilities and original initializer. It verifies the original entry/world/catalog pins and compares the entire source route/factory body with its framework derivative. Only the derivative's battle catalog reference changes. It creates no gameplay owner, character, event flag, resource, position or replacement script.

The strict source entry and battle remain unchanged. Legacy private framework objects also retain their existing URLs and contents. Shared candidates add explicit `full-new-game`, `full-battle`, `full-content-refs`, binding and directory proof objects. Consumers select the complete variant through the existing `GameContentRepository` reference contract. Missing or changed bodies fail their exact pins; there is no fallback to the smaller battle cache. The directory policy's exact bytes and real path join the same candidate input lock, which is checked before and after consumption.

The public collection uses its one existing whole-source directory compilation for both initialized batches and the original framework newgame role. Base package preparation occurs after that directory is available. It publishes the bound framework entry and its own battle reference together, with the strict source role still referencing its original catalog. It does not rebuild maps or run a second independent publication.

Controlled tests use redistributable source-shaped inputs and the real directory compiler, repository, title/newgame preparation, Session, map owner, checkpoint Storage and battle handoff. A saved original-route session restores with the complete catalog and enters a compiled encounter absent from the small baseline. Other fixture cases retain an unimplemented AI dependency and blocked formation, and reject changed owners, removed directory requests, changed route/factory inputs and stale battle bodies. Successful entry is not victory or full-story completion.

This family performs no original source program execution, 649-map production, public publication, browser verification or native dynamic comparison. The next joint candidate must consume these author changes with the other common capability families and produce fresh source-route evidence. The full migration goal remains active.
