# v48 批量内容接入框架

本批在已有游戏骨架上补入统一的内容依赖与连续路线检查。接入单位是一份批次清单，不增加地图名分支，也不另写战斗、奖励或存档执行器。共享游戏状态与浏览器主循环沿用 v47。

## 接入合同

`content-batches/*.json` 声明 profile、地图集合、依赖入口和必须完成的路线。每条路线包含终点、必经地图、必胜遭遇、最大逻辑帧数，以及玩家移动/确认、选项答案和战斗能力输入。运行器按路线 ID 从清单取完整输入，不能另传删减版路线并借用原摘要。

`planContentBatch` 重验包的实际内容摘要与世界目录交叉引用，绑定入口、世界、战斗和每张地图。地图/脚本图按地图上下文展开 PointIn、后继或初始化脚本、活动实体组、切换脚本、战斗返场和指令目标。显式初始活动组与 SetEntities 引用都参与检查；分支保守展开，未知世界状态不裁掉分支。遇到批次外出口、缺少引用或 blocked 指令保留诊断。

战斗适配器复用已有编译结果、能力计划和校验器，区分依赖 ready、conditional 和 blocked。来源 AI 的条件分支仍需未知能力时，不能因另一条分支可运行就消除诊断。开发省略保留在 limitations；本批不会把开发战斗目录升级为原版一致性证明。

静态图仅检查编译包暴露的引用，不证明完整原始数据依赖，也不证明剧情可达。媒体解码、当前队伍资格、动态提供器及状态耦合继续由运行时检查。`referenceClosure=closed` 与 `runtimeAdmission=unassessed` 可以同时存在。

## 连续执行与准入

`runContentBatchRoute` 使用真实 GameFlow、GameSession、GameMapLoader、GameEventSaveCoordinator 和 CheckpointStorage。事件由地图触发和玩家输入进入，不直接调用 startEvent，不改旗标、HP 或胜负。标题来源入口直接读取自己的战斗依赖，独立于旧开发字段包。每次地图准备前核对世界目录和地图摘要，战斗必须属于已扫描依赖。

路线必须到达声明终点，经过所需地图并结算所需遭遇，返回稳定字段与菜单，再保存、通过 Repository 重建会话并比较完整检查点。半程 unsupported、战败、缺输入、超时或恢复失败都拒绝。来源路线与合成系统路线分别记录，成功范围只到 `declared-routes-only`。

运行前后重新计算清单、内容依赖和运行时代码摘要；框架报告必须来自同一构建。过期报告、重哈希后的新内容、漏验成员或多份不完整轨迹拼接都不能获得准入。回执来自受信检查器；摘要绑定并不能证明任意外部 JSON 真正执行过。

```sh
npm run batch-pipeline:check
npm run framework:verify
npm run batch:plan -- content-batches/framework-opening.json
npm run batch:check -- content-batches/framework-opening.json
```

plan 输出静态需求且不授予运行资格；check 在未准入时退出 1。系统总检查新增合成批次通道，仍不替具体来源批次放行。清单仅含作者编写的身份与输入；原始资产、来源编译包和检查回执留在本地忽略目录。

## 本批证据

两地图合成清单通过同一运行器执行：走到触发点 → 获得物品 → 事件保存 → 真实战斗 → 一次奖励与返场 → 切图初始化 → 菜单就绪 → 保存与恢复。两个敌人由既有共用编译器从合成来源形状记录生成，结算 14 Gil；没有手写胜利结果。该检查覆盖批次接入机制，不能计入来源地图覆盖。

提名的来源开场批次为 609、3、178。实际轨迹仍是 609 → 3 → 178 → 609，80,550 ms 停在已有 Camera Move 提供器边界，未到稳定出口、未完成保存恢复。静态扫描另保留批次外出口、来源消息形态和角色资源缺口；这些来自保守分支集合，不代表当前剧情必定执行每一项。该批次应当明确 blocked，而不是因路线边界检查成功记为通过。

`npm run check` 的 2043 项 TypeScript 测试、注册表检查和 39 项 Python 测试通过。`framework:verify` 的 19 条系统通道通过，新增批次通道含 10 项连续流程及失效证据检查。独立审查发现的世界目录错配、初始活动实体组漏扫和路线输入错配均已补上拒绝路径与回归。

完整结果见 `build/reports/v48-check.log`、`v48-python-tests.log`、`framework-systems-check.json`、`content-batch-pipeline-check.json` 和 `content-batch-framework-opening-to-field.json`。本批没有修改浏览器游戏交互或启动新的原版对照。

## 后续实施

按批次诊断归并共用事件、战斗与地图生命周期能力；新增来源内容继续走相同清单和真实连续路线。当前保守图会包含潜在分支及批次外出口，后续若引入剧情状态约束，必须提供可复验的状态依据，不以删掉失败边缩小范围。随机遭遇、完整角色/能力、世界交通和全主线仍属于迁移任务；本框架通道通过不代表这些内容完成。HD-2D 继续后置。
