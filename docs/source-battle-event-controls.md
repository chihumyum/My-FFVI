# 来源战斗 UI 与输入控制

本家族保留全部 53 份战斗脚本、2,312 条原指令及其 490 支敌队依赖。共同选择器为 `HideBattleUI` 22 处、`ShowBattleUI` 14 处、`StopAutoBattle` 8 处和 `RemoveAllAct` 6 处。来源身份、原地址和完整 8/8/8 操作数保留；未知尾参数仍阻塞。

前三种选择器产生一个立即推进的 VM 请求。执行者仍是 `BattleGame`，显式 Web 策略为 `web-source-battle-event-controls-v1`，由实际 App 和共享重放端口通过原 `GameSession` 构造路径提供。缺少策略时不能发布相应战斗；存档不能授予策略。

`BattleGame` 保存菜单可见性、暂停锁和菜单修订。`uiControls` 仅返回独立投影，外部不能反写。消息和脚本动作仍使用原消息 owner、队列、反应、费用及随机流。UI 请求和 VM、消息、动作处于同一帧事务；后继失败整体回滚。

原生 Show 协程仅等待 UI 初始化，然后更新菜单和暂停根以及控制器 `IsShow`。Hide 另写 `IsLockOffPause=true`；控制器每次更新遇到该位会清除 `IsPause`。Web 内容和 UI 在 VM 前完成准备，因此本策略同步提交显隐；Unity 协程更新顺序仍未动态验证。Web 暂停请求继续由 `GameFlow` 拥有，隐藏时拒绝用户暂停，浏览器后台等宿主暂停保持独立。

隐藏菜单不接受玩家命令或撤退，也不留住已失效的 WAIT/特殊输入等待。`BattleView` 消费相同投影，任何 Hide/Show 修订都会使旧菜单回调过期，包含两次显隐发生在下一次绘制前的情况。菜单可见性不结束战斗，也不关闭独立的共享剧情消息窗口。终局返回和败北重试仍走原交接事务。

原生 `StopAutoBattle` 调用 `SetIsAuto(false)`，只写控制器自动位并关闭自动图标/动画，没有清队列。Web 复用既有仅手动输入的控制器；该选择器不取消已选动作、不清反应、不开放尚未实现的自动行动。实例重试从固定入口新建其 UI/手动控制状态，不接收旧实例回调。

`RemoveAllAct` 继续明确不可执行。原生先清 staging，按攻击者类型过滤普通和 interrupt 队列，清 fixed-player 栈并执行状态机状态 0 的退出/进入回调，再过滤敌方动作。取消回调与动作资源生命周期尚未闭合，不能以 `queue=[]` 或空操作替代。六个使用点完整保留。

合成检查覆盖参数拒绝、VM 请求边界、同帧失败回滚、真实 Session/Flow/Commands、隐藏时动作与消息并发、败北取消/重试、实际 App 按钮和 Storage，以及真实 `BattleView` 的显隐和过期菜单。纯来源检查器保留完整正文与依赖，独立报告 44 个已转换使用点和 6 个取消生命周期缺口。这些结果不证明原主线可达、原版动态一致性或浏览器像素验收。
