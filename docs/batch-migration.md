# 按共用能力推进 Web 迁移

2026-10-10 用户指出逐场景迁移不可持续。此前纳尔谢开发片段用于打通输入、事件、战斗和返回地图；继续沿着街道逐个补例外，不能产生全游戏迁移能力。当前改变实现单位，正式一致性对照仍后置，HD-2D 仍不启动。

## 生产路径

原始资源包 → 全量内容索引 → 类型化指令和数据 → 共用运行时 → 批量地图包 → 实玩回归。

地图、NPC、敌人编组、对白和剧情脚本由来源数据决定。工程交付单位是可复用的指令语义、状态系统和资源适配器。一个能力合并后，重新编译所有使用点和依赖地图；不能为每个使用点复制代码。原始精确参数签名保留用于定位和回归，坐标、对白 ID 不再各自变成一个待实现任务。

目前 `compileField` 的开场检查点、固定实体组和战斗 AI 模板仍是开发样本中的局部约束，不是批量架构。保持样本可用，但不再扩大这些硬编码；逐项由下列共用模块接管。

| 实现批次 | 共用交付 | 能证明推进有效的结果 |
| --- | --- | --- |
| 内容闭包 | 所有 Addressables 容器的 JSON/脚本索引，地图包绑定，指令家族和引用定位 | 能自动列出受某项能力影响的地图；缺失/歧义引用保留 |
| 事件与世界状态 | 通用任务 VM、调用/跳转/条件、变量与 flags、实体组选择和脚本切换 | 同一实现执行不同地区的原始脚本，不按场景名称写分支 |
| 地图生命周期 | 按包加载地图、进入/退出/重返、实体和资源生命周期、版本化状态保存 | 相连地图可往返，剧情变化与存读档一致；场景只提供数据 |
| 战斗系统 | 数据驱动编组、能力分派、敌方 AI VM、状态与奖励 | 新编组通过表数据接入；未实现规则显式诊断 |
| 表现和操作 | 通用动画、音频、镜头、菜单、库存和队伍界面 | 多地图共享表现能力；特殊演出单列能力增量 |
| 区域批次 | 地图依赖闭包、入口状态、主线和支线回归路径 | 在已具备的能力集合内成批运行，实际玩过再记为可玩 |

每批优先处理关键路径和影响面较大的缺口，不按指令出现次数机械排序。覆盖最多地图的共同阻塞组合通常比再完成一场特定战斗更重要。纳尔谢保留为回归样本，另用不含专门修补的地图检查泛化。歌剧的专用演出是共用运行时之后的能力扩展，不能成为绕开基础系统的第二套引擎。

## 可执行的工作队列

```sh
.venv/bin/python tools/source_adapter/export_corpus.py --source "/absolute/path/to/Final.Fantasy.VI.Pixel.Remaster"
npm run corpus:plan
```

`build/corpus/` 保存来源绑定的全量容器内容；每项保留资源包摘要、路径、序列化文件和字符串对象 ID。导出前后检查来源文件。空容器引用和未被容器寻址的 TextAsset 另行登记，不能当作不存在。该步骤不解码全部图片、声音或模型。

`build/reports/corpus-plan.json` 保存地图包绑定、逐脚本能力集合、共用能力受影响地图和明确可解析的引用。相邻 Markdown 是工作队列摘要。它直接调用当前字段解码器检测参数形态；没有维护第二份容易漂移的“支持指令名单”。

当前解析包内别名、常驻公共脚本回退、SetEntities 组引用、Call、SetPuppet、Jump、Branch、Encount 后继和 ChangeScript 名称引用；`maps:check` 另解析初始化与切图入口候选。动态分派、完整地图初始化、图片/动画/声音、战斗规则等依赖仍须扩展。脚本全部参数可解码不等于可运行：未知分支和资源依赖不能被扫描数字掩盖。不同剧情阶段的脚本均参与静态清单，不自动判断哪一版世界状态可达。

事件状态和条件控制流已有共用实现。`npm run events:check` 按已实现能力整批选择来源脚本，使用同一个游戏 VM 执行并记录状态变化；本批 87 份脚本、258 组受控输入执行完成，详见 [事件 VM](event-vm.md)。这是执行证据，未替代地图装载或实际游玩。

## 进度口径

分别报告：来源已索引、参数可解码、依赖闭合、实际可运行、已实玩。不能用前四者之一冒充后一项，也不能把静态扫描所得地图数当作迁移完成数。当前有开场战斗和一张陌生地图加载、移动的 Web 实玩证据；没有可信的全游戏完成日期。后续依据共享能力对实际可运行入口与事件的影响建立估算，不能按导出文件数外推工期。

通用地图装载已经接入：515 个来源媒体包导出后，649 条地图记录由同一编译器生成内容包。`world:check` 对依赖就绪的默认入口逐个执行实际 WorldSession 准备和提交，并汇总全部排除原因；没有按地图名编写场景实现。详见 [地图生命周期](map-lifecycle.md)。

静态 0–13 碰撞、默认 MapRange、小地图标记、显式 BGM、环境音、静止 NPC 交互和 TileAnimation 区域已实现为共用能力；见 [碰撞批次](collision.md)、[小地图批次](minimap.md)、[背景音乐批次](bgm.md)、[环境音批次](environment-audio.md)、[NPC 批次](npc.md)、[地图动画批次](tile-animation.md)。当前 187 个尝试入口中有 76 个到达空闲，分布于 39 条地图记录。下一实现重点是角色动画、地图机关、NPC 游走/路线与交互选择和初始化状态/指令，随后扩展区域往返和保存。几何/入口缺口和初始化指令缺口分别排队；不能把具有图像但缺少角色或机关的地图标记为完成。

角色动画已新增未骑乘演员的共用播放、定位与移动关联；2,005 个来源动画条目通过隔离单次播放，2 份原始定位脚本完成，见 [角色动画批次](actor-animation.md)。入口数未增加。后续角色能力仍有骑乘组合、透明度与自定义动画缺口，与地图机关/NPC、事件状态和系统迁移继续按实际依赖排序。
