# 首战可玩开发规则

当前目录格式为 `narshe-playability-v6`。v6 将玩家/敌人中性物理、选定手槽数值、命中和暴击接入共用结算，详见 [物理计算](physical-calculation.md)。v5 将中性魔法/计算型恢复接入共用命中与数值模块，详见 [魔法计算](magic-calculation.md)。v4 的来源技能/命令资格和受限沉默行为保留，见 [状态动作](battle-conditions.md)。原有开场菜单范围不变。未知组合整条阻塞，详见 [能力分派](ability-dispatch.md)。已完成的街道数据固定为回归样本；按照用户最新指令，先搭建共用游戏系统，再扩展区域内容，不继续为单场战斗增加模板。自动检查已走通编组 3 → 1 → 2 → 3 → 42；后续编组的画面尚未逐一实玩。

V2 边界：角色、能力和 Sprite 只保存一份，编组按源表数据选择；狼犬仅支持全队等级小于 7 的默认攻击分支，其他分支明确停止。`IsLevelCheckAct 0x824D00` 的阈值方向有原生研究依据；没有通用 AI VM。夹击采用临时站位和初始行动条。`SetPos` 重新显示已隐藏角色是开发假设；源事件仅隐藏但当前实体组不存在的 154/156 被显式登记，不虚构角色。PlaySE/SyncSE 共六次在静音开发策略中记录并立即完成，不能视为声音或音画同步已经迁移。

2026-10-10，按用户“先让游戏跑起来、凭常识判断能不能玩”的指示，先完成首战交互；暂缓正式一致性采样。`opening-playability-v1` 是显式开发 profile，不能参与原版一致性或全游戏放行。源数据检查包仍独立保留，未知的通用指令仍停止。

## 当前闭环

纳尔谢 `(38,49)` → 前行 11 格 → 守卫对白 → 两名守卫战斗 → 胜利结算 → `sc_e_0002_1` → 返回地图。玩家可切换已就绪角色、选择三种射线/治愈原力和目标；敌人主动攻击。失败可从本次战斗入口重试，不获得奖励、不推进剧情。暂停、窗口失焦和页面隐藏均停止模拟。

`GameSession` 独占地图与战斗交接，内核产生胜负而非 UI 按钮指定。经验来自倒下敌人的记录，分配给存活角色；奖励只能领取一次。HP/MP、等级、经验、Gil 在本页面会话保留，刷新后重置。道具掉落保持 `pending`，没有假造一个已完成的空掉落结果。

首战胜利后执行来源后继脚本：子任务隐藏 164/165/177，0.7 秒黑色淡入，设置 `ScenarioFlag1[1]`。非视觉实体 177 也进入隐藏集合；渲染、实体阻挡、动态碰撞、交互和进入触发共用这份集合，避免图像消失但重复开战。当前旗标不等于已恢复所有地图初始化/重返条件。

## 来源规则与临时规则

| 项目 | 当前依据与实现 | 仍未证明的部分 |
|---|---|---|
| 初始 HP | character_status 1/31/32 的 63/68/70；本地既有 Mac 首战截图 `build/runtime/battle.jpg` 可见这三个最大值 | 其他角色/剧情初始化、原版存档导入 |
| 属性与装备 | 六个 content 槽解析到 weapon/armor；十项共用确认算术保留分阶段上限、手槽/空手、特殊装备和回避输入。开场负重仍为 8；敌方魔力修正为 ability_attack。见 [属性确认](character-parameters.md) | 开场仍显式假定零成长追加/Correction/临时/被动值及双手倍率 1；穿戴效果、状态生成和能力解锁未完成 |
| 魔导菜单 | command 26 / ability group 7，与角色 ability_random_group 取交集；成员为 8/4/4 项 | 运行时 OwnedAbility 的解锁值初始化未恢复；暂以成员视为已解锁。原生过滤器 `0x754770` 实际检查 SkillLevel > 99 |
| ATB | 增量使用已审核的 `0x675950` 模块；初始范围取源表玩家/敌人 NORMAL 50–80 | 自有 xorshift32 PRNG；整数均匀抽样、speed=1、动作播放时冻结行动条，均为临时调度。不是 Unity RNG/原版模式复现 |
| 蓄力与队列 | 玩家暂用 `wait*20/(agility*0.5+20)` 秒；敌人无蓄力；就绪队列顺序固定。执行前重验存活目标；已死目标换到同侧第一个存活目标 | 仅使用 `GetChantingTime 0x6765D0` 的普通分支方向；没有状态修正、反击/插队/特殊等待语义 |
| 守卫 AI | 无初始状态的 Guard 模板，默认分支取 Act 的 65/35 权重及 ability 1/377；目标为随机存活玩家 | 只适用于此首战和当前无状态招式；未实现 SyncAI 通用解释器、条件 12 的运行时切换或 `sc_b_0239`。模板形状变化会拒绝编译 |
| 射线伤害 | 使用共用中性魔法模块；source flag 1 令必中并跳过命中抽样，保留浮动/防御取整与 65535/9999 上限，见 [魔法计算](magic-calculation.md) | 元素中性仍为开发上下文；反射、数值状态、饰品和其他修正尚未接入，不代表完整魔法 |
| 治愈原力 | Recovery(2,2,0) 走同一魔法入口，isRecover 跳过防御；source flag 1 必中，恢复封顶、MP 费用一次性提交 | Unique/None 没有解除状态效果；其他目标、状态、装备与特殊恢复上下文仍未完成 |
| 物理攻击 | 共用前排中性分支；玩家单手/力量、敌方基础抽样、整数倍率、浮动先于命中、严格暴击判定及防御逐步取整，见 [物理计算](physical-calculation.md) | 前后排、双持/双手、元素/种族、数值状态、特殊武器和装备附加效果未接入；玩家普通攻击只有受控队列证据，开场仍为魔导菜单 |
| 经验/Gil | 两个独立敌人实例分别累加源 exp/gill；存活者均分取整，首战 96/3=32。`BattleResultProvider.Genelate 0x3D51A0` 支持均分方向 | 原版经验资格/被动技能未实现；等级按 exp_table，最大 HP/MP 暂按 growth_curve 固定增量，当前 HP/MP 不自动补满 |
| 二维表现 | 背景和人物使用精确源 Sprite；角色 RideL_00、装甲 WalkL_00 | 站位、骑乘裁剪、400 ms 命中点与 900 ms 动作时长、自绘光束均为临时表现；无原版音效/特效 |

八项源魔导中仅三种射线和治愈原力可执行；另外四项保留禁用菜单。没有用空操作吞掉对应效果。将来扩展到其他敌人/剧情前，必须扩大显式能力范围或保持停止，不能暗中把首战假设推广。

## 所有权与检查

- `src/compiler/battle.ts` 保留源表/资源引用和静态检查包。
- `src/compiler/opening-playable.ts` 将范围受限的选择与临时规则标记为独立开发内容 `opening-playable.json`，保留源检查包摘要与中文文本来源集。
- `src/core/battle-content.ts` 是纯数据契约，`battle.ts` 拥有行动条、队列、伤害、胜负和随机状态，`game-session.ts` 拥有交接和奖励消费。
- `apps/game/battle-view.js` 只投影状态和发出命令，不决定战斗结果。

```sh
npm run check
npm run battle:check
npm run game:check
npm run playable:check
npm run dev
```

初次首战交付时通过 29 项 TypeScript 测试和 9 项 Python 测试；当前 184 项 / 18 项及共用物理检查见 [物理计算](physical-calculation.md)。真实源检查覆盖构建确定性、菜单成员、装备负重、胜利/失败、奖励一次性、后继脚本、隐藏触发器和重试。合成用例额外验证非法输入不耗回合、已死目标重选、治疗封顶和不同帧切分的重放。真实源回归还覆盖地图→战斗交接的帧切分：修复前 1000 ms 单帧与 100×10 ms 分帧分别推进战斗 0 / 290 ms；修复后交接统一按 10 ms 步推进。

Codex 内置浏览器实际操作过移动、对白、选射线/目标、治疗指令、暂停恢复、胜利、奖励及回到 `(38,36)`；另已实际等待队伍自然战败，点击重试并确认三人恢复 63/68/70 HP；无控制台错误。截图：`build/runtime/web-battle-victory.png`、`web-battle-defeat.png`。严格验收没有因此变为通过；完整纳尔谢、后续战斗、掉落、存读档、跨图、音频及其他浏览器尚未完成。
