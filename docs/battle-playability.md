# 首战可玩开发规则

当前目录格式为 `narshe-playability-v15`。v15 将玩家复活与已支持状态解除、普通装备变更、字段物品/Gil 事务接入共享状态。换装、升级、战斗和保存使用同一份装备及原始成长输入；见 [装备](equipment.md)、[复活与解除状态道具](item-status.md)、[字段库存](inventory-events.md)。菜单 14 个、战斗 16 个道具计划仍受活动状态与目标资格限制，不能全部计作可实用物品。正式开场保留来源库存，没有额外发放测试药品或装备。此前 v14 的固定恢复子集见 [道具动作](item-actions.md)。

v13 接入按动作结果触发的基础反击、优先队列和反应事务，保留普通行动及行动条，见 [普通反击](battle-reactions.md)。v12 接入连续行动整组提交、逐击结算和末击释放行动条，见 [连续行动](battle-action-groups.md)。v11 接入逐敌变量、阶段编号及 HP/MP 条件，初始化与预检查、行动决策分别提交，见 [行为参数](battle-ai-state.md)。v10 用来源普通行动 VM 取代守卫/狼犬模板，支持条件、跳转、行动表轮换及逐敌状态，见 [来源 AI](battle-ai.md)。v9 接入 HP/死亡状态协调、玩家复活、濒死更新、蓄力取消和跨战斗状态保留，详见 [死亡与复活](battle-life.md)。v8 接入显式元素与抗性、无效/吸收结果及装备相性投影，详见 [元素相性](elemental-affinities.md)。v7 增加共用单体/群体选择和逐目标结果，整次费用、效果和随机流提交见 [目标结算](battle-targets.md)。v6 将玩家/敌人中性物理、选定手槽数值、命中和暴击接入共用结算，详见 [物理计算](physical-calculation.md)。v5 将中性魔法/计算型恢复接入共用命中与数值模块，详见 [魔法计算](magic-calculation.md)。v4 的来源技能/命令资格和受限沉默行为保留，见 [状态动作](battle-conditions.md)。魔导技能范围未扩展。未知组合整条阻塞，详见 [能力分派](ability-dispatch.md)。已完成的街道数据固定为回归样本；按照用户最新指令，先搭建共用游戏系统，再扩展区域内容，不继续为单场战斗增加模板。自动检查已走通编组 3 → 1 → 2 → 3 → 42；后续编组的画面尚未逐一实玩。

角色、能力和 Sprite 只保存一份，编组按源表数据选择。旧 v2 的狼犬等级模板已由 v10 通用 AI 路径检查取代：等级阈值来自源指令，高等级分支因能力 696 的函数 38 未实现而停止。夹击采用临时站位和初始行动条。`SetPos` 重新显示已隐藏角色是开发假设；源事件仅隐藏但当前实体组不存在的 154/156 被显式登记，不虚构角色。PlaySE/SyncSE 共六次在静音开发策略中记录并立即完成，不能视为声音或音画同步已经迁移。

2026-10-10，按用户“先让游戏跑起来、凭常识判断能不能玩”的指示，先完成首战交互；暂缓正式一致性采样。`opening-playability-v1` 是显式开发 profile，不能参与原版一致性或全游戏放行。源数据检查包仍独立保留，未知的通用指令仍停止。

## 当前闭环

纳尔谢 `(38,49)` → 前行 11 格 → 守卫对白 → 两名守卫战斗 → 胜利结算 → `sc_e_0002_1` → 返回地图。玩家可切换已就绪角色、选择三种射线/治愈原力和目标；敌人主动攻击。失败可从本次战斗入口重试，不获得奖励、不推进剧情。暂停、窗口失焦和页面隐藏均停止模拟。

`GameSession` 协调地图与战斗交接，`GameState` 独占角色、库存及奖励记录，内核产生胜负。战斗使用角色和库存入场副本，全部成长计算成功后公布胜利；领奖预检后继脚本与共享状态，再一次性提交角色、物品消耗、Gil 和领奖记录并排入后继。经验仍按开发规则分给存活角色。HP/MP、等级、经验、装备身份、物品数量与 Gil 可随稳定地图检查点保存，刷新后从已保存位置继续；见 [共享游戏状态](shared-game-state.md)、[检查点存档](checkpoint-saves.md)。道具掉落仍为 `pending`。

首战胜利后执行来源后继脚本：子任务隐藏 164/165/177，0.7 秒黑色淡入，设置 `ScenarioFlag1[1]`。非视觉实体 177 也进入隐藏集合；渲染、实体阻挡、动态碰撞、交互和进入触发共用这份集合，避免图像消失但重复开战。当前旗标不等于已恢复所有地图初始化/重返条件。

八项源魔导中仅三种射线和治愈原力可执行；另外四项保留禁用菜单。没有用空操作吞掉对应效果。将来扩展到其他敌人/剧情前，必须扩大显式能力范围或保持停止，不能暗中把首战假设推广。

## 所有权与检查

- `src/compiler/battle.ts` 保留源表/资源引用和静态检查包。
- `src/compiler/opening-playable.ts` 将范围受限的选择与临时规则标记为独立开发内容 `opening-playable.json`，保留源检查包摘要与中文文本来源集。
- `src/core/battle-content.ts` 是纯数据契约，`battle.ts` 拥有行动条、队列、伤害、胜负和随机状态，`game-state.ts` 拥有共享角色与库存，`game-session.ts` 协调交接和奖励消费。
- `apps/game/battle-view.js` 只投影状态和发出命令，不决定战斗结果。

```sh
npm run check
npm run battle:check
npm run game:check
npm run playable:check
npm run dev
```

初次首战交付时通过 29 项 TypeScript 测试和 9 项 Python 测试；v15 当前 323 项 / 18 项及道具、装备和字段库存检查见各系统文档，此前 AI/反击证据见 [普通反击](battle-reactions.md)。真实源检查覆盖构建确定性、菜单成员、装备负重、胜利/失败、奖励一次性、后继脚本、隐藏触发器和重试。合成用例额外验证非法输入不耗回合、已死目标重选、治疗封顶和不同帧切分的重放。真实源回归还覆盖地图→战斗交接的帧切分：修复前 1000 ms 单帧与 100×10 ms 分帧分别推进战斗 0 / 290 ms；修复后交接统一按 10 ms 步推进。
