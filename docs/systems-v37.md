# 游戏框架 v37

本批按用户修正优先搭建连续游戏骨架。流程、内容装载和连续验收三线并行，集成线把它们接入现有 Web 页面。后续工作以共用系统与内容依赖为单位；粒子、着色器和逐位数值研究暂停。

## 已交付

`GameFlow` 管理标题、暂停、输入、时钟和异步操作票据。探索、事件、对白、商店、战斗、胜负、切图和阻塞阶段从当前会话派生。`GameSession` 继续串联字段与战斗，`GameState` 继续唯一拥有角色、库存、装备与奖励，菜单没有另一份持久状态。

`GameContentRepository` 统一开发入口、正式新游戏包、世界目录、地图和存档依赖装载。加载检查摘要、来源与地图引用，共享进行中的请求；缓存使用私有副本，失败后可以重试。新增内容沿用同一包契约和运行时，不增加地图名或战斗 ID 专用分支。

浏览器已采用上述模块，增加返回标题入口。后台、媒体准备、暂停、总览和异步 I/O 统一阻止游戏时钟与操作；暂停菜单在 I/O 期间禁用。战斗和商店沿用同一输入就绪条件。过期读档无法发布会话；发布前失败保留原状态，发布后表现故障明确停止并显示错误。缺少遭遇包会报告阻塞，不再无限停留在遭遇等待。

模块边界和批量内容接入方法见 [游戏系统框架](game-framework.md)。

连续验收明确注入一次取得两份回复剂的开发事件，使用来源物品定义与真实首场战斗；保存使用内存存储端口。通过并不表示浏览器保存实测、原版一致性或完整来源主线通过。失败回滚、重复确认和旧操作取消均在同一轨迹上检查。

最终浏览器构建还检查了版本不兼容的旧存档：标题页明确提示无法读取并保留原存档，仍可开始开发片段。控制台没有警告或错误；本轮未点击保存，连续保存与恢复的证据来自上述受控验收。
