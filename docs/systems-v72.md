# v72 商店经济与魔石成长

本批继续交付跨系统的完整流程。商店的声明交易、装备与战斗续行，以及魔石的取得、装备、学习、成长和保存接入已有 `GameState`、`GameSession`、`GameCommands` 和内容仓库。地图名、商店编号和魔石编号都是内容参数，不增加对应的运行时特例。精细演出和 HD-2D 继续后置。

## 连续经济流程

批次路线新增严格的 `shop` 和 `leave-shop` 输入。交易必须绑定当前字段、实际窗口、来源商店组和原会话所有者；错误阶段、背景状态、过期窗口和进行中的请求不能执行交易。未声明输入仍保留 `shop-input-not-declared`，不会自动买卖或离店。

代表性流程经过 NPC 问候、购买、出售、购买装备、离店对白、换装、第一战和实际道具消耗、保存恢复、切图、第二战及再次恢复。网页与批次都调用已有交易和离店接口。读档创建新会话后重新绑定操作，旧窗口不能把交易重定向过去；输入摘要保留购买、出售和离店的原顺序。

## 魔石持有与角色关联

魔石目录读取完整来源表，并核验已有原生构造器导出的回执和摘要。27 个魔石绑定 92 条学习记录，18 个具有非零升级奖励；18 份已支持角色成长计划接入同一目录。目录建立身份与规则，不授予剧情所有权，也不将召唤能力加入永久已学列表。

全局持有列表属于来源初始化后的 `SourceNativeState`，保留取得顺序和唯一内容 ID。角色装备关联、能力和成长仍属于同一持有名册。菜单只列实际持有魔石；装备、转移和卸下经过完整候选校验、版本检查及一次发布。装备不立即增加属性，也不立即学会魔法。来源排除角色和禁用角色的未闭合转移保持明确拒绝。

必须区分两条消费者：菜单卸下魔石会按实际熟练度处理魔法命令；字段 `GetItem/RemoveItem` 的 Type9 使用 `UserDataManager.IOwnedItemClient`。这个库存消费者忽略 Count；重复取得不重复插入，未持有时移除不操作，持有时只清除实际名册中首个装备关联，保留命令和技能。角色离队的底层关联清除也保留这些命令和技能。直接 `UserDataClient`、菜单和库存管理器不能互相代替。

若移除后仍残留另一个持有人关联，本 Web 生命周期明确拒绝整项候选；这是当前持有状态合同的限制，不声称原版会拒绝或自动清除全部关联。宝箱的魔石容量与奖励上下文尚未恢复，继续明确阻塞；字段库存支持不自动放行宝箱。

旧开发检查点没有来源原生初始化状态，继续保持 `nativeState=null`，不能凭新目录取得魔石。它的菜单不显示这项功能。来源新游戏和从来源初始化建立的受控会话使用真实持有域；检查器不向旧开发入口伪造全局魔石列表。

## 战后学习、成长与保存

结算读取本战实际参战成员、冻结的装备和实际 MagicPoint。部分熟练度按来源学习顺序累计，达到 100 后进入已有字段和战斗资格；普通撤退不获得学习奖励。自然等级学习、魔石 Type2 学习和观察学习保留各自顺序，已有独立计数器不替代熟练度。

升级奖励逐级应用，每级 HP/MP 百分比使用该级基础增量和整数截断；属性奖励加入对应的成长增量。保存有序的装备变化、底层移除与成长记录，恢复时按历史重放。换一块魔石不能反算并改写过去的升级奖励，重复结算和伪造战斗历史不能重复加成。

带魔石合同的内容使用 owned v14；历史记录是必需数据，缺失时拒绝恢复，不从入口或当前装备补猜。无魔石合同的旧内容仍按自己的 owned v12/v13 保存。外层检查点继续为 v5，来源原生状态仍为 v2；内容摘要分别验证，不自动迁移旧摘要。

魔石页面接入现有角色菜单，显示实际持有、装备者、学习进度与升级奖励。按钮保留会话、所有者和渲染代际，恢复或更换会话后旧按钮失效。已学普通魔法可用与召唤是否可执行分别判断；本批未开放召唤生命周期和效果。

## 字段事件的共同发布

交叉审查复现了离队的半发布：owned 名册先提交，真实原生演员随后进行最后一次材料校验并拒绝，演员仍保留旧队伍。编队事件具有相同的顺序缺陷。本批将 live 和地图初始化草稿的两种事件都改为 `commitWith`，在原持有状态仍可读、其他持久写入被锁定时完成演员的最后校验，再一起发布准备好的演员和 owned 数据。

真实原生演员提供器的失败、依赖旧持有状态的读取、重入写入、过期草稿和重复提交有专门回归。失败保留魔石关联、命令、成长历史、名册与演员；成功离队才发布关联清除和历史。原始反例与修复后回执分别保留，不用假的演员提交函数替代此验证。
